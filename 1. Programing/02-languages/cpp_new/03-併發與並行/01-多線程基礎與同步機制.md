## 核心概念

### 1. 基本定義

**多線程 (Multithreading)** 允許程式同時執行多個指令流,充分利用多核 CPU 資源。在 C++ 中,`std::thread` 是最基礎的執行單元。

**同步 (Synchronization)** 是指協調多個執行緒對共享資源的訪問,以避免**數據競爭 (Data Race)** 和**未定義行為 (Undefined Behavior)**。

### 2. 使用場景

- **HFT (高頻交易)**: 市場數據接收、策略計算、訂單發送並行處理。
- **高性能伺服器**: 每個請求由獨立執行緒或執行緒池處理。
- **複雜計算**: 將大任務拆分為小任務並行運算 (如矩陣乘法)。

## 執行緒管理

### 1. std::thread 基礎

C++11 引入了 `std::thread`,是所有並發編程的基礎。

```cpp
#include <thread>
#include <iostream>
#include <vector>

void worker(int id) {
    // std::this_thread 提供當前執行緒的操作
    std::cout << "Thread " << id << " running on " 
              << std::this_thread::get_id() << "\n";
}

void thread_lifecycle() {
    // 1. 創建並啟動執行緒
    std::thread t1(worker, 1);
    
    // 2. Lambda 表達式
    std::thread t2([]{
        std::cout << "Lambda thread running\n";
    });

    // 3. 等待執行緒結束 (Join)
    if (t1.joinable()) t1.join();
    if (t2.joinable()) t2.join();

    // 4. 分離執行緒 (Detach) - 慎用!
    // 執行緒將在背景運行,若主程式結束可能導致資源未釋放或崩潰
    std::thread t3(worker, 3);
    t3.detach(); 
}
```

### 2. std::jthread (C++20)

C++20 引入了 `std::jthread`,它在解構時自動 `request_stop()` 並 `join()`,更安全且支援協作式中斷。

```cpp
#include <thread>
#include <chrono>
#include <iostream>

void interruptible_worker(std::stop_token stoken) {
    while (!stoken.stop_requested()) {
        std::cout << "Working...\n";
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
    std::cout << "Worker stopped.\n";
}

void jthread_example() {
    // 自動 join, 支援 stop_token
    std::jthread t(interruptible_worker);
    
    std::this_thread::sleep_for(std::chrono::milliseconds(300));
    // t 解構時會自動呼叫 request_stop() 並 join()
}
```

## 互斥鎖與 RAII

互斥鎖 (Mutex) 用於保護臨界區 (Critical Section),確保同一時間只有一個執行緒能訪問共享資源。

### 1. Mutex 類型

| 類型 | 描述 | 適用場景 |
|------|------|----------|
| `std::mutex` | 基本互斥鎖,不可遞迴 | 大多數場景 |
| `std::recursive_mutex` | 允許同一執行緒多次上鎖 | 遞迴函數調用 |
| `std::timed_mutex` | 支援超時嘗試上鎖 | 避免長時間阻塞 |
| `std::shared_mutex` (C++17) | 讀寫鎖 (Reader-Writer Lock) | 讀多寫少場景 |

### 2. RAII 鎖管理 (推薦)

永遠不要手動調用 `lock()` 和 `unlock()`,應使用 RAII 包裝器。

```cpp
#include <mutex>
#include <shared_mutex>

std::mutex mtx;
std::shared_mutex smtx;

void raii_locking() {
    // 1. std::lock_guard (C++11)
    // 最輕量, 構造時鎖定, 解構時解鎖
    {
        std::lock_guard<std::mutex> lock(mtx);
        // 臨界區...
    } // 自動解鎖

    // 2. std::unique_lock (C++11)
    // 靈活, 可手動 unlock/lock, 支援條件變數
    {
        std::unique_lock<std::mutex> lock(mtx);
        // ...
        lock.unlock(); // 暫時解鎖
        // ...
        lock.lock();   // 重新鎖定
    }

    // 3. std::scoped_lock (C++17)
    // 防止死鎖 (Deadlock), 可同時鎖定多個 mutex
    {
        std::mutex mtx2;
        std::scoped_lock lock(mtx, mtx2); // 原子性鎖定兩個鎖
    }

    // 4. std::shared_lock (C++14/17)
    // 用於 shared_mutex 的讀取鎖 (共享鎖)
    {
        std::shared_lock<std::shared_mutex> lock(smtx);
        // 多個執行緒可同時進入此區域讀取
    }
}
```

### 3. 死鎖 (Deadlock) 與解決

**死鎖**發生在兩個執行緒互相等待對方釋放鎖時。

**錯誤示範**:
```cpp
// Thread A: lock(m1) -> lock(m2)
// Thread B: lock(m2) -> lock(m1)
// 可能導致死鎖!
```

**解決方案**:
1. **統一上鎖順序**: 所有執行緒都依相同順序獲取鎖。
2. **使用 `std::scoped_lock`**: 讓標準庫處理上鎖順序。

## 條件變數

`std::condition_variable` 用於執行緒間的信號通知,常用於生產者-消費者模式。

### 生產者-消費者實作

```cpp
#include <condition_variable>
#include <queue>
#include <mutex>

template<typename T>
class ThreadSafeQueue {
    std::queue<T> queue_;
    mutable std::mutex mtx_;
    std::condition_variable cv_;

public:
    void push(T value) {
        {
            std::lock_guard<std::mutex> lock(mtx_);
            queue_.push(std::move(value));
        }
        // 通知一個等待中的執行緒
        cv_.notify_one();
    }

    T pop() {
        std::unique_lock<std::mutex> lock(mtx_);
        
        // 使用 Lambda 作為 Predicate, 防止虛假喚醒 (Spurious Wakeup)
        // 等價於: while(queue_.empty()) { cv_.wait(lock); }
        cv_.wait(lock, [this]{ return !queue_.empty(); });

        T value = std::move(queue_.front());
        queue_.pop();
        return value;
    }
};
```

> [!WARNING]
> **虛假喚醒 (Spurious Wakeup)**: `wait()` 可能在沒有 `notify()` 的情況下返回。務必總是配合 `while` 迴圈或 Predicate 使用 `wait()`。

## Future 與 Promise

C++11 提供了更高層次的異步結果獲取機制,避免手動管理 Mutex 和 CV。

### 1. std::async

最簡單的異步執行方式。

```cpp
#include <future>
#include <iostream>

int calculate() {
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    return 42;
}

void async_example() {
    // std::launch::async 強制開啟新執行緒
    std::future<int> result = std::async(std::launch::async, calculate);
    
    // 做其他事情...
    
    // 獲取結果 (如果未完成會阻塞)
    std::cout << "Result: " << result.get() << "\n";
}
```

### 2. std::promise 與 std::future

用於在執行緒間傳遞值或異常。

```cpp
void worker(std::promise<int> prom) {
    try {
        // 模擬計算
        int res = 100;
        prom.set_value(res); // 設置結果
    } catch (...) {
        prom.set_exception(std::current_exception()); // 傳遞異常
    }
}

void promise_example() {
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();
    
    std::thread t(worker, std::move(prom));
    
    try {
        std::cout << "Got: " << fut.get() << "\n";
    } catch (const std::exception& e) {
        std::cout << "Exception: " << e.what() << "\n";
    }
    
    t.join();
}
```

## C++20 同步原語

C++20 引入了更輕量、更高效的同步機制,特別適合協調多個執行緒。

### 1. std::latch (一次性柵欄)

用於等待一組執行緒完成初始化或任務。計數器減至 0 後不可重用。

```cpp
#include <latch>
#include <vector>

void latch_example() {
    const int N = 4;
    std::latch work_done{N}; // 初始化計數為 4
    std::vector<std::thread> threads;

    for(int i=0; i<N; ++i) {
        threads.emplace_back([&] {
            // 做一些工作...
            work_done.count_down(); // 計數減 1
        });
    }

    work_done.wait(); // 阻塞直到計數為 0
    // 所有工作完成
    
    for(auto& t : threads) t.join();
}
```

### 2. std::barrier (可重用柵欄)

適用於分階段執行的任務。所有執行緒到達同步點後,執行完成回調 (Completion Function),然後進入下一階段。

```cpp
#include <barrier>

void barrier_example() {
    const int N = 3;
    auto on_completion = []() noexcept { 
        static int phase = 0;
        std::cout << "Phase " << ++phase << " done\n"; 
    };
    
    std::barrier sync_point(N, on_completion);

    auto worker = [&](int id) {
        for(int i=0; i<3; ++i) {
            // 階段性任務
            sync_point.arrive_and_wait(); // 等待其他人
        }
    };
    
    // 啟動執行緒...
}
```

### 3. std::semaphore (信號量)

用於控制同時訪問特定資源的執行緒數量 (如連線池)。

```cpp
#include <semaphore>

// 限制最多 4 個並發訪問
std::counting_semaphore<4> sem{4};

void access_resource() {
    sem.acquire(); // P 操作: 計數減 1, 若為 0 則阻塞
    
    // 訪問受限資源...
    
    sem.release(); // V 操作: 計數加 1, 喚醒等待者
}
```

## 性能分析

### 同步機制開銷對比

在無競爭 (Uncontended) 情況下的單次操作開銷估算 (x86_64):

| 機制 | 開銷 (ns) | 說明 |
|------|-----------|------|
| `std::atomic` (relaxed) | ~1-2 ns | 最快, 僅 CPU 指令 |
| `std::atomic` (seq_cst) | ~5-10 ns | 需要 Memory Fence |
| `Spinlock` (atomic_flag) | ~15-20 ns | 適合極短臨界區 |
| `std::mutex` | ~25-50 ns | 無競爭時通常是使用者空間操作 |
| `std::condition_variable` | > 1000 ns | 涉及系統調用與上下文切換 |

### HFT 實戰建議

1. **優先使用無鎖 (Lock-free)**: 對於極低延遲路徑,使用 `std::atomic` 或無鎖隊列 (SPSC)。
2. **避免 False Sharing**: 確保頻繁寫入的變數位於不同的 Cache Line (使用 `alignas(64)`).
3. **減少鎖粒度**: 鎖住的範圍越小越好,只保護共享數據操作。
4. **讀多寫少**: 使用 `std::shared_mutex` 提升讀取並發度。

## 最佳實踐

1. **永遠使用 RAII**: 禁止裸用 `lock()`/`unlock()`,使用 `std::scoped_lock` 防止死鎖。
2. **避免在鎖內執行耗時操作**: 如 I/O、複雜計算,會大幅降低並發性能。
3. **優先使用高階原語**: C++20 的 `latch`/`barrier` 比手寫 `condition_variable` 更不易出錯且性能更好。
4. **使用 ThreadSanitizer**: 編譯時加上 `-fsanitize=thread` 檢測 Data Race。

```bash
g++ -fsanitize=thread -g -O2 my_program.cpp -o my_program
```
