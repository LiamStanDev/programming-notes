## 1. C++ 類型轉換概覽

C++ 提供 4 種具名類型轉換 (Named Cast) 取代 C 風格轉換:

| 轉換類型 | 用途 | 安全性 | 執行期開銷 | 常用度 |
|---------|------|-------|-----------|--------|
| `static_cast` | 編譯期類型轉換 | 中等 | 無 | ⭐⭐⭐ |
| `dynamic_cast` | 執行期類型識別 (RTTI) | 高 | 有 | ⭐ |
| `const_cast` | 移除/添加 const/volatile | 低 | 無 | ⭐ |
| `reinterpret_cast` | 位元重新解釋 | 極低 | 無 | ⭐ |

### 為什麼需要具名轉換?

```cpp
// C 風格轉換的問題
double x = 3.14;
int y = (int)x;  // 這是做了什麼?
                 // static_cast? reinterpret_cast? const_cast?
                 // 無法確定,難以搜索和審查

// C++ 具名轉換的優勢
int y = static_cast<int>(x);  // 意圖明確
                              // 可用工具搜索所有 static_cast
                              // 編譯期檢查更嚴格
```

## 2. static_cast - 編譯期類型轉換

**用途**: 相關類型間的轉換,編譯期檢查。

**使用場景**:
- 數值類型轉換
- 指針類型轉換 (繼承關係)
- enum 與整數互轉
- void* 轉型別指針

### 2.1 基本類型轉換

```cpp
// 數值轉換
double price = 100.75;
int price_int = static_cast<int>(price);  // 100 (截斷小數)

// 隱式轉換的明確化
int x = 10;
double y = static_cast<double>(x);  // 明確表達意圖

// 避免整數除法陷阱 ⭐⭐⭐
int total = 100;
int count = 3;

// ❌ 錯誤: 整數除法
double avg1 = total / count;  // 33.0 (先計算 100/3=33,再轉 double)

// ✅ 正確: 至少一個操作數轉為 double
double avg2 = static_cast<double>(total) / count;  // 33.333...
double avg3 = total / static_cast<double>(count);  // 33.333... (也可以)
```

### 2.2 指針類型轉換

```cpp
class Base {};
class Derived : public Base {};

// ✅ 向上轉換 (子類 -> 基類) - 總是安全
Derived* d = new Derived();
Base* b = static_cast<Base*>(d);  // OK
// 或隱式轉換
Base* b2 = d;  // OK, 不需要 cast

// ⚠️ 向下轉換 (基類 -> 子類) - 不檢查!
Base* b3 = new Base();
Derived* d2 = static_cast<Derived*>(b3);  // 編譯通過但危險!
// 若 b3 實際不指向 Derived,行為未定義!

// ✅ 安全的向下轉換: 使用 dynamic_cast (見後文)
```

### 2.3 enum class 轉換

```cpp
enum class Side : uint8_t { 
    Buy = 0, 
    Sell = 1 
};

// enum -> 整數
Side side = Side::Buy;
uint8_t value = static_cast<uint8_t>(side);  // 0

// 整數 -> enum
uint8_t raw_value = 1;
Side side2 = static_cast<Side>(raw_value);  // Side::Sell

// ⚠️ 注意: 不檢查值是否有效!
Side invalid = static_cast<Side>(99);  // 編譯通過,但值無效
```

### 2.4 void* 轉換

```cpp
// void* -> T*
void* ptr = malloc(sizeof(int));
int* p = static_cast<int*>(ptr);  // OK
*p = 42;

// T* -> void* (隱式轉換,不需要 cast)
int x = 42;
void* vp = &x;  // OK
```

## 3. dynamic_cast - 執行期類型識別

**用途**: 安全的向下轉換,帶執行期檢查。

**限制**: 
- 需要多態類型 (至少一個虛函數)
- 有執行期開銷 (RTTI 查詢)

### 3.1 基本用法

```cpp
class Base {
public:
    virtual ~Base() = default;  // ⚠️ 必須有虛函數!
};

class Derived : public Base {
public:
    void specific_method() {
        std::cout << "Derived method\n";
    }
};

// ✅ 安全的向下轉換
Base* b = new Derived();
Derived* d = dynamic_cast<Derived*>(b);

if (d != nullptr) {  // 轉換成功
    d->specific_method();
} else {
    // 轉換失敗
}

// ❌ 轉換失敗返回 nullptr
Base* b2 = new Base();
Derived* d2 = dynamic_cast<Derived*>(b2);  // nullptr
```

### 3.2 引用轉換

```cpp
// 引用轉換失敗拋出 std::bad_cast 異常
Base& base_ref = *b2;

try {
    Derived& derived_ref = dynamic_cast<Derived&>(base_ref);
    derived_ref.specific_method();
} catch (std::bad_cast& e) {
    std::cerr << "Cast failed: " << e.what() << "\n";
}
```

### 3.3 何時使用 dynamic_cast?

**適用場景**:
- ✅ 當你不確定對象的實際類型
- ✅ 需要安全地訪問子類特有成員

**避免過度使用**:
- ❌ 頻繁使用表示設計可能有問題
- ✅ 考慮使用虛函數實現多態

```cpp
// ❌ 不好的設計
void process(Base* b) {
    if (auto d1 = dynamic_cast<Derived1*>(b)) {
        d1->method1();
    } else if (auto d2 = dynamic_cast<Derived2*>(b)) {
        d2->method2();
    }
    // 每增加新子類都要修改此函數!
}

// ✅ 更好的設計: 使用虛函數
class Base {
public:
    virtual void process() = 0;
};

class Derived1 : public Base {
public:
    void process() override { method1(); }
};

void process(Base* b) {
    b->process();  // 多態調用,無需 cast
}
```

### 3.4 替代方案: std::variant (C++17)

```cpp
#include <variant>
#include <iostream>

struct TypeA { 
    int value; 
    void process() { std::cout << "TypeA: " << value << "\n"; }
};

struct TypeB { 
    double value; 
    void process() { std::cout << "TypeB: " << value << "\n"; }
};

using MyType = std::variant<TypeA, TypeB>;

MyType obj = TypeA{42};

// 類型安全的訪問
std::visit([](auto&& arg) {
    arg.process();
}, obj);

// 或使用 if constexpr
std::visit([](auto&& arg) {
    using T = std::decay_t<decltype(arg)>;
    if constexpr (std::is_same_v<T, TypeA>) {
        std::cout << "It's TypeA\n";
    } else if constexpr (std::is_same_v<T, TypeB>) {
        std::cout << "It's TypeB\n";
    }
}, obj);

// ✅ 優點: 無虛函數開銷,編譯期類型安全
```

## 4. const_cast - 移除 const/volatile

**用途**: 移除或添加 `const`/`volatile` 限定符。

⚠️ **危險**: 修改原本為 const 的對象是 UB!

### 4.1 合法用途

```cpp
// ✅ 場景 1: 傳遞給舊 API (不修改內容)
void legacy_api(char* str);  // 舊 API 沒有 const

void modern_code() {
    const char* str = "Hello";
    legacy_api(const_cast<char*>(str));  // OK, 只要 legacy_api 不修改
}

// ✅ 場景 2: 原對象不是 const
int y = 42;
const int* cp = &y;
int* p = const_cast<int*>(cp);
*p = 10;  // OK, y 本來就不是 const
```

### 4.2 未定義行為

```cpp
// ❌ UB: 修改原本為 const 的對象
const int x = 42;
int* p = const_cast<int*>(&x);
*p = 10;  // UB! x 宣告為 const

// 編譯器可能將 x 存在唯讀記憶體區段,修改會崩潰
```

### 4.3 最佳實踐

**原則**: 幾乎不需要使用 `const_cast`!

- 良好的 API 設計應避免它
- 如果需要使用,重新思考設計
- 唯一合理場景: 與舊 C API 互操作

## 5. reinterpret_cast - 位元重新解釋

**用途**: 指針類型間的低級轉換,重新解釋位元模式。

⚠️ **極度危險**: 
- 破壞類型安全
- 可能違反 strict aliasing rule
- 可能導致對齊問題

### 5.1 合法用途

```cpp
// ✅ 用途 1: 指針轉整數
void* ptr = malloc(100);
uintptr_t addr = reinterpret_cast<uintptr_t>(ptr);
std::cout << "Address: 0x" << std::hex << addr << "\n";

// ✅ 用途 2: 整數轉指針 (系統程式設計)
uintptr_t mmio_addr = 0x40000000;  // 記憶體映射 I/O 地址
volatile uint32_t* reg = reinterpret_cast<volatile uint32_t*>(mmio_addr);
*reg = 0xFF;  // 寫入硬體暫存器

// ✅ 用途 3: char* 指向任意對象 (讀取位元組表示)
int x = 42;
unsigned char* bytes = reinterpret_cast<unsigned char*>(&x);
for (size_t i = 0; i < sizeof(int); ++i) {
    printf("%02X ", bytes[i]);
}
```

### 5.2 危險用法

```cpp
// ❌ UB: 違反 strict aliasing
int x = 42;
float* p = reinterpret_cast<float*>(&x);
*p = 3.14f;  // UB! 通過 float* 訪問 int 對象

// ✅ 正確做法: 使用 memcpy
float f;
std::memcpy(&f, &x, sizeof(float));

// ✅ 或使用 std::bit_cast (C++20)
#include <bit>
float f2 = std::bit_cast<float>(x);
```

### 5.3 對齊問題

```cpp
// ❌ 潛在的對齊問題
char buffer[100];
int* p = reinterpret_cast<int*>(buffer);  // 可能未對齊!
*p = 42;  // 某些架構會崩潰

// ✅ 確保對齊
alignas(int) char buffer[100];
int* p = reinterpret_cast<int*>(buffer);  // 安全
```

### 5.4 何時使用?

**極少數場景**:
- 系統程式設計 (MMIO, DMA)
- 網路封包解析 (需確保對齊)
- 序列化/反序列化 (配合 memcpy)

**幾乎任何其他場景都有更好的替代方案**!

## 6. C 風格轉換 - 應避免

### 6.1 為什麼避免?

```cpp
// ❌ C 風格轉換
double x = 3.14;
int y = (int)x;

// 問題:
// 1. 不明確: 執行哪種轉換?
// 2. 難以搜索: grep "cast" 找不到
// 3. 可能執行危險操作
// 4. 可能是多個 cast 的組合
```

### 6.2 C 風格轉換的等價規則

C 風格轉換 `(T)expr` 會依序嘗試:

1. `const_cast<T>(expr)`
2. `static_cast<T>(expr)`
3. `static_cast<T>(const_cast<U>(expr))`
4. `reinterpret_cast<T>(expr)`
5. `reinterpret_cast<T>(const_cast<U>(expr))`

**危險**: 可能執行 `reinterpret_cast` 級別的轉換!

```cpp
// 範例: C 風格轉換可能執行危險操作
const int* cp = nullptr;
int* p = (int*)cp;  // const_cast
int x = (int)3.14;  // static_cast

void* vp = nullptr;
int* ip = (int*)vp;  // reinterpret_cast (如果需要)
```

### 6.3 函數風格轉換

```cpp
// 函數風格 (仍是 C 風格轉換)
int y = int(3.14);  // 等價於 (int)3.14

// ⚠️ 與建構函數語法混淆
std::string s = std::string("hello");  // 建構函數
int x = int(3.14);  // C 風格轉換!
```

### 6.4 替代方案

```cpp
// ✅ 始終使用具名轉換
double x = 3.14;
int y = static_cast<int>(x);

const int* cp = nullptr;
int* p = const_cast<int*>(cp);
```

## 7. 隱式轉換與類型提升

### 7.1 整數提升 (Integral Promotion)

```cpp
// 小整數類型自動提升為 int
char c = 'A';      // 1 byte
short s = 100;     // 2 bytes
int result = c + s;  // char 和 short 都提升為 int (4 bytes)

// ⚠️ 符號擴展 vs 零擴展
int8_t signed_val = -1;   // 0xFF
int i1 = signed_val;      // 0xFFFFFFFF (符號擴展)

uint8_t unsigned_val = 255;  // 0xFF
int i2 = unsigned_val;       // 0x000000FF (零擴展)

// ⚠️ 有符號與無符號混合運算
int a = -1;
unsigned int b = 1;
if (a < b) {  // ❌ 錯誤! a 轉為 unsigned, -1 變成 4294967295
    // 不會執行
}
```

**為什麼要提升?**
- CPU 通常以 word 大小 (32/64-bit) 運算
- 避免小整數運算的溢位問題

### 7.2 浮點轉換

```cpp
float f = 3.14f;
double d = f;  // OK, 擴展為 double (無損)

double d2 = 3.14159265359;
float f2 = d2;  // ⚠️ 精度損失,編譯器可能警告

// 混合運算: 較小型別提升為較大型別
float a = 1.0f;
double b = 2.0;
auto result = a + b;  // a 提升為 double, result 為 double
```

### 7.3 整數與浮點混合運算

```cpp
int x = 10;
double y = 3.14;
auto result = x + y;  // x 轉為 double, result 為 double

// ⚠️ 常見陷阱: 整數除法
int total = 100;
int count = 3;

double avg1 = total / count;  // ❌ 33.0 (整數除法!)
// 步驟: 100/3 = 33 (int), 然後 33 轉為 double

double avg2 = static_cast<double>(total) / count;  // ✅ 33.333...
// 步驟: total 轉 double, 100.0/3 = 33.333...
```

### 7.4 指針與布林轉換

```cpp
// 指針隱式轉為 bool
int* p = nullptr;
if (p) {  // 隱式轉為 bool
    // p 非空
}

// 等價於
if (p != nullptr) {
    // ...
}

// ⚠️ 整數轉指針 (C++11 後嚴格限制)
int* p1 = 0;        // OK, 字面量 0 可轉為 nullptr
int* p2 = nullptr;  // ✅ 推薦
// int* p3 = 1;     // ❌ Error! 其他整數不能隱式轉換

// ⚠️ bool 轉整數
bool b = true;
int x = b;  // 1
int y = false;  // 0
```

## 8. 用戶定義轉換

### 8.1 轉換建構函式

```cpp
class Price {
    double value_;
public:
    // ❌ 允許隱式轉換
    Price(double v) : value_(v) {}
};

void process(Price p) {
    // ...
}

int main() {
    process(100.5);  // ⚠️ 隱式轉換! double -> Price
    // 等價於 process(Price(100.5));
}
```

### 8.2 explicit 關鍵字 ⭐⭐⭐

```cpp
class Price {
    double value_;
public:
    // ✅ 禁止隱式轉換
    explicit Price(double v) : value_(v) {}
};

void process(Price p) {}

int main() {
    // process(100.5);  // ❌ Error! 不能隱式轉換
    process(Price{100.5});  // ✅ OK, 顯式轉換
    process(Price(100.5));  // ✅ OK
}
```

**最佳實踐**: 所有單參數建構函式都應加 `explicit`!

```cpp
class String {
public:
    explicit String(size_t size);  // ✅ 防止 5 -> String
    String(const char* str);       // ⚠️ 可能需要隱式轉換
    explicit String(std::string_view sv);  // ✅
};

// 例外: 複製/移動建構函式不加 explicit
class Widget {
public:
    Widget(const Widget&);  // 複製建構函式
    Widget(Widget&&);       // 移動建構函式
};
```

### 8.3 轉換運算子

```cpp
class Price {
    double value_;
public:
    // ❌ 隱式轉換運算子
    operator double() const { return value_; }
};

Price p{100.5};
double d = p;  // 隱式轉換
double result = p + 50.0;  // 也會隱式轉換

// ✅ 顯式轉換運算子 (C++11)
class Price {
    double value_;
public:
    explicit operator double() const { return value_; }
};

Price p{100.5};
// double d = p;  // ❌ Error!
double d = static_cast<double>(p);  // ✅ OK
```

### 8.4 bool 轉換運算子

```cpp
// ⚠️ bool 轉換運算子通常不用 explicit (慣用法)
class SmartPtr {
    void* ptr_;
public:
    operator bool() const { 
        return ptr_ != nullptr; 
    }
};

SmartPtr p;
if (p) {  // 隱式轉為 bool
    // ...
}

// C++11 explicit bool (更安全)
class SmartPtr {
    void* ptr_;
public:
    explicit operator bool() const { 
        return ptr_ != nullptr; 
    }
};

SmartPtr p;
if (p) {  // OK, 在條件表達式中允許
    // ...
}
// int x = p;  // ❌ Error! 不能轉為 int
```

## 9. 實戰案例

### 案例 1: 金融價格轉換

```cpp
// 問題: 價格以整數 (分) 存儲,需要轉為 double (元)
class Price {
    int64_t cents_;  // 以分為單位
    
public:
    explicit Price(int64_t cents) : cents_(cents) {}
    
    // ✅ 顯式轉換為 double
    explicit operator double() const {
        return cents_ / 100.0;
    }
    
    // ✅ 提供命名函數更清晰
    double to_dollars() const {
        return cents_ / 100.0;
    }
    
    // 運算符重載
    Price operator+(Price other) const {
        return Price(cents_ + other.cents_);
    }
};

// 使用
Price p1{10050};  // 100.50 元
Price p2{2500};   // 25.00 元

Price total = p1 + p2;  // 125.50 元
double dollars = total.to_dollars();  // 顯式轉換

std::cout << "Total: $" << dollars << "\n";
```

### 案例 2: 網路封包解析

```cpp
// 問題: 從網路封包讀取多位元組整數 (需處理字節序)

#pragma pack(push, 1)  // 禁用填充
struct PacketHeader {
    uint32_t magic;
    uint16_t version;
    uint16_t length;
};
#pragma pack(pop)

// ❌ 錯誤做法: 直接 cast
void parse_packet_bad(const char* buffer) {
    const PacketHeader* header = 
        reinterpret_cast<const PacketHeader*>(buffer);
    // ❌ 違反 strict aliasing!
    // ❌ 字節序問題未處理!
}

// ✅ 正確做法: 使用 memcpy
void parse_packet_good(const char* buffer) {
    PacketHeader header;
    std::memcpy(&header, buffer, sizeof(PacketHeader));
    
    // 處理字節序 (網路序 -> 主機序)
    header.magic = ntohl(header.magic);
    header.version = ntohs(header.version);
    header.length = ntohs(header.length);
    
    // 使用 header...
}

// ✅ 更好: 使用 std::byte (C++17)
void parse_packet_best(const std::byte* buffer) {
    PacketHeader header;
    std::memcpy(&header, buffer, sizeof(PacketHeader));
    // ...
}
```

### 案例 3: enum class 與整數互轉

```cpp
// 交易訂單方向
enum class Side : uint8_t {
    Buy = 0,
    Sell = 1
};

// 從網路封包讀取
uint8_t raw_side = buffer[offset];

// ✅ 轉換前驗證
Side parse_side(uint8_t value) {
    if (value > static_cast<uint8_t>(Side::Sell)) {
        throw std::invalid_argument("Invalid side value");
    }
    return static_cast<Side>(value);
}

// 寫入網路封包
void serialize_side(Side side, uint8_t* buffer) {
    buffer[0] = static_cast<uint8_t>(side);
}

// 使用
try {
    Side side = parse_side(raw_side);
    if (side == Side::Buy) {
        // 處理買單
    }
} catch (const std::invalid_argument& e) {
    // 處理錯誤
}
```

### 案例 4: 避免整數除法陷阱

```cpp
// 計算平均成交價
struct Trade {
    int64_t quantity;
    int64_t price;  // 以分為單位
};

// ❌ 錯誤: 整數除法
double calculate_avg_price_bad(const std::vector<Trade>& trades) {
    int64_t total_value = 0;
    int64_t total_qty = 0;
    
    for (const auto& trade : trades) {
        total_value += trade.quantity * trade.price;
        total_qty += trade.quantity;
    }
    
    return total_value / total_qty;  // ❌ 整數除法!
}

// ✅ 正確: 轉換為 double
double calculate_avg_price_good(const std::vector<Trade>& trades) {
    int64_t total_value = 0;
    int64_t total_qty = 0;
    
    for (const auto& trade : trades) {
        total_value += trade.quantity * trade.price;
        total_qty += trade.quantity;
    }
    
    if (total_qty == 0) {
        return 0.0;
    }
    
    return static_cast<double>(total_value) / total_qty;
}

// 使用
std::vector<Trade> trades = {
    {100, 10050},  // 100股 @ 100.50元
    {200, 10100},  // 200股 @ 101.00元
};

double avg = calculate_avg_price_good(trades);
std::cout << "Average price: " << avg / 100.0 << " dollars\n";
```

## 總結

### 類型轉換選擇指南

| 需求 | 使用 | 範例 |
|------|------|------|
| 數值類型轉換 | `static_cast` | `static_cast<int>(3.14)` |
| 繼承體系向上轉換 | 隱式轉換 | `Derived* -> Base*` |
| 繼承體系向下轉換 (安全) | `dynamic_cast` | `dynamic_cast<Derived*>(base)` |
| 繼承體系向下轉換 (確定) | `static_cast` | `static_cast<Derived*>(base)` |
| 移除 const | `const_cast` | `const_cast<int*>(cp)` |
| 指針轉整數 | `reinterpret_cast` | `reinterpret_cast<uintptr_t>(p)` |
| 位元重新解釋 | `std::bit_cast` (C++20) | `std::bit_cast<float>(i)` |
| 任何情況 | **避免 C 風格轉換** | ~~`(int)x`~~ |

### 最佳實踐

1. ✅ **優先使用具名轉換**: 意圖明確,易於搜索
2. ✅ **避免 C 風格轉換**: 危險且難以維護
3. ✅ **單參數建構函式加 explicit**: 防止意外轉換
4. ✅ **轉換運算子加 explicit**: 除了 `bool` 可例外
5. ✅ **注意整數除法**: 至少一個操作數轉為 `double`
6. ✅ **檢查 enum 轉換**: 驗證值的有效性
7. ✅ **避免過度使用 dynamic_cast**: 考慮虛函數
8. ✅ **使用 memcpy 而非 reinterpret_cast**: 避免 strict aliasing 違規

### 編譯器警告配置

```bash
# GCC/Clang: 啟用轉換相關警告
g++ -Wconversion          # 隱式轉換警告
    -Wsign-conversion     # 有符號/無符號轉換警告
    -Wfloat-conversion    # 浮點轉換警告
    -Wold-style-cast      # C 風格轉換警告
    main.cpp
```
