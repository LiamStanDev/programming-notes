## 1. C++11 核心特性

### 1.1 Auto 類型推導

```cpp
// auto 類型推導
auto x = 42;              // int
auto y = 3.14;            // double
auto z = std::make_unique<int>(10);  // std::unique_ptr<int>

// 複雜類型簡化
std::map<std::string, std::vector<int>> map;
auto it = map.begin();  // 取代冗長的迭代器類型

// ⚠️ 注意引用
auto a = vec[0];   // 拷貝
auto& b = vec[0];  // 引用
const auto& c = vec[0];  // const 引用
```

**好處**:
- **可讀性**: 減少冗長的類型聲明,特别是模板類型
- **維護性**: 當類型改變時,代碼自動適配
- **開發效率**: 減少手動輸入複雜類型名稱
- **性能**: 編譯期類型推導,無運行時開銷

**缺點**:
- **可讀性降低**: 有時類型不明確,影響代碼理解
- **意外拷貝**: 忘記使用引用可能導致不必要的拷貝
- **調試困難**: IDE 可能無法顯示推導的具體類型

### 1.2 範圍 For 循環

```cpp
std::vector<int> vec = {1, 2, 3, 4, 5};

// 範圍 for
for (const auto& x : vec) {
    std::cout << x << "\n";
}

// 修改元素
for (auto& x : vec) {
    x *= 2;
}

// 初始化列表
for (int x : {1, 2, 3, 4, 5}) {
    std::cout << x << " ";
}
```

**好處**:
- **可讀性**: 語法簡潔,意圖明確
- **安全性**: 避免陣列越界錯誤
- **維護性**: 容器大小改變時無需修改循環
- **性能**: 編譯器優化與手寫索引循環相當

**缺點**:
- **靈活性**: 無法直接獲取索引,需要額外處理
- **控制流**: 無法輕易跳躍或反向遍歷
- **複雜遍歷**: 對於複雜的遍歷模式可能不適用

### 1.3 nullptr

```cpp
// nullptr 取代 NULL
int* p = nullptr;  // 明確的空指針

// 函數重載
void func(int x);
void func(int* p);

func(0);        // 調用 func(int)
func(NULL);     // 可能有歧義
func(nullptr);  // 明確調用 func(int*)
```

**好處**:
- **類型安全**: 避免整數與指針的混淆
- **重載解析**: 明確指示指針類型,避免歧義
- **可讀性**: 明確表示空指針意圖
- **性能**: 編譯期處理,無運行時開銷

**缺點**:
- **向後相容**: 與舊代碼混用時需要注意一致性
- **微小開銷**: 某些情況下可能增加二進制大小(極少見)

### 1.4 統一初始化

```cpp
// 統一初始化語法
std::vector<int> v1{1, 2, 3};
std::string s{"Hello"};
int arr[]{1, 2, 3};

// 防止窄化轉換
int x{3.14};  // Error! 窄化轉換

// 初始化列表
struct Point {
    int x, y;
};
Point p{10, 20};
```

### 1.5 移動語義

```cpp
// 右值引用
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = std::move(v1);  // 移動,不拷貝

// 移動建構函式
class Widget {
public:
    Widget(Widget&& other) noexcept;
    Widget& operator=(Widget&& other) noexcept;
};
```

**好處**:
- **性能**: 避免昂貴的深拷貝,特別是大型容器
- **記憶體效率**: 減少暫時物件的記憶體分配
- **RAII**: 完美轉發資源擁有權
- **STL 優化**: 容器操作性能顯著提升

**缺點**:
- **複雜性**: 增加類設計複雜度,需要實作移動建構函式
- **語義陷阱**: `std::move` 後原物件處於未定義狀態
- **調試困難**: 移動語義錯誤較難追蹤
- **學習曲線**: 理解右值引用需要時間

### 1.6 Lambda 表達式

```cpp
// Lambda
auto f = [](int x) { return x * 2; };
int result = f(5);  // 10

// 捕獲
int offset = 10;
auto add_offset = [offset](int x) { return x + offset; };

// 與 STL 結合
std::vector<int> vec = {5, 2, 8, 1};
std::sort(vec.begin(), vec.end(),
    [](int a, int b) { return a < b; });
```

**好處**:
- **簡潔性**: 減少小函數的定義,代碼更緊湊
- **局部性**: 邏輯就近定義,增強可讀性
- **STL 整合**: 與演算法完美結合
- **性能**: 通常會被內聯,無函數調用開銷
- **閉包**: 方便捕獲局部變數

**缺點**:
- **調試困難**: 某些調試器對 lambda 支持不佳
- **捕獲陷阱**: 引用捕獲可能導致懸空引用
- **可讀性**: 複雜 lambda 可能降低可讀性
- **編譯時間**: 大量使用可能增加編譯時間

### 1.7 智能指針

```cpp
// unique_ptr
auto p1 = std::unique_ptr<int>(new int(42));  // C++11

// shared_ptr
auto p2 = std::make_shared<int>(42);

// weak_ptr
std::weak_ptr<int> weak = p2;
```

**好處**:
- **記憶體安全**: 自動管理記憶體,防止洩漏
- **異常安全**: RAII 保證異常時也能正確清理
- **所有權語義**: 明確表達資源擁有關係
- **零開銷**: `unique_ptr` 與原始指針性能相同

**缺點**:
- **shared_ptr 開銷**: 引用計數有原子操作成本
- **循環引用**: `shared_ptr` 可能造成記憶體洩漏
- **學習成本**: 需要理解不同智能指針的使用時機
- **調試複雜**: 智能指針層次可能增加調試難度

### 1.8 其他重要特性

```cpp
// constexpr
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}

// static_assert
static_assert(sizeof(int) == 4, "int must be 4 bytes");

// decltype
int x = 10;
decltype(x) y = 20;  // y 的類型與 x 相同

// 變參模板
template<typename... Args>
void print(Args... args);

// 右值引用
void process(std::string&& s);

// 強類型枚舉
enum class Color { RED, GREEN, BLUE };
```

## 2. C++14 特性

### 2.1 make_unique

```cpp
// C++14 添加 make_unique
auto p = std::make_unique<int>(42);
auto arr = std::make_unique<int[]>(10);
```

**好處**:
- **異常安全**: 避免 `new` 與智能指針分離造成的記憶體洩漏
- **簡潔性**: 語法更簡潔,類型推導自動化
- **一致性**: 與 `make_shared` 保持一致的命名風格
- **性能**: 無額外開銷,編譯器通常會優化

**缺點**:
- **自定義刪除器**: 無法直接指定自定義刪除器
- **初始化語法**: 某些初始化語法可能不如直接建構清晰

### 2.2 泛型 Lambda

```cpp
// auto 參數
auto print = [](const auto& x) {
    std::cout << x << "\n";
};

print(42);
print(3.14);
print("Hello");
```

**好處**:
- **重用性**: 一個 lambda 處理多種類型
- **簡潔性**: 避免寫多個類似的 lambda
- **性能**: 編譯期展開,無運行時多型開銷
- **靈活性**: 結合模板元編程技術

**缺點**:
- **錯誤訊息**: 類型推導錯誤時,錯誤訊息可能複雜
- **調試困難**: 泛型實例化增加調試複雜度
- **編譯時間**: 可能增加編譯時間

### 2.3 返回類型推導

```cpp
// 自動推導返回類型
auto add(int a, int b) {
    return a + b;  // 推導為 int
}

// 複雜返回類型
auto get_data() {
    return std::vector<int>{1, 2, 3};
}
```

**好處**:
- **簡化聲明**: 複雜返回類型無需手動指定
- **維護性**: 實作改變時返回類型自動更新
- **一致性**: 與變數的 `auto` 推導保持一致
- **性能**: 編譯期推導,無運行時開銷

**缺點**:
- **可讀性**: 函數簽名不夠明確,需要查看實作
- **接口變化**: 實作改變可能意外改變公共接口
- **模板錯誤**: 在模板中使用可能產生複雜錯誤訊息

### 2.4 數字分隔符

```cpp
// 數字分隔符提高可讀性
int million = 1'000'000;
double pi = 3.141'592'653;
int binary = 0b1111'0000;
int hex = 0xDEAD'BEEF;
```

**好處**:
- **可讀性**: 大數字更易讀,減少錯誤
- **維護性**: 數字結構清晰,便於檢查和修改
- **無開銷**: 純編譯期特性,不影響運行時
- **靈活性**: 可在任意位置添加分隔符

**缺點**:
- **編譯器支持**: 較舊編譯器不支持
- **代碼風格**: 團隊需要統一分隔符使用規範

### 2.5 二進位字面量

```cpp
// 二進位字面量
int mask = 0b1111'0000;
int flags = 0b0001'0010'0100;
```

### 2.6 變量模板

```cpp
// 變量模板
template<typename T>
constexpr T pi = T(3.1415926535897932385);

float f = pi<float>;
double d = pi<double>;
```

## 3. C++17 特性

### 3.1 結構化綁定

```cpp
// 結構化綁定
std::pair<int, std::string> p = {1, "one"};
auto [id, name] = p;

std::map<int, std::string> m = {{1, "one"}, {2, "two"}};
for (const auto& [key, value] : m) {
    std::cout << key << ": " << value << "\n";
}

// 陣列
int arr[] = {1, 2, 3};
auto [a, b, c] = arr;
```

**好處**:
- **可讀性**: 直接命名結構成員,意圖清晰
- **簡潔性**: 避免 `.first`, `.second` 等存取
- **多返回值**: 優雅處理函數多返回值
- **性能**: 編譯期展開,無額外開銷

**缺點**:
- **編譯器支持**: 需要 C++17 支持
- **調試**: 某些調試器對結構化綁定支持有限
- **靈活性**: 必須綁定所有成員,無法選擇性忽略

### 3.2 if/switch 初始化

```cpp
// if 初始化
if (auto it = map.find(key); it != map.end()) {
    // 使用 it
    std::cout << it->second << "\n";
}

// switch 初始化
switch (auto value = get_value(); value) {
    case 1: break;
    case 2: break;
}
```

### 3.3 std::optional

```cpp
#include <optional>

// 可能失敗的操作
std::optional<int> parse_int(const std::string& str) {
    try {
        return std::stoi(str);
    } catch (...) {
        return std::nullopt;
    }
}

// 使用
if (auto result = parse_int("123"); result) {
    std::cout << "Value: " << *result << "\n";
} else {
    std::cout << "Parse failed\n";
}

// value_or
int value = parse_int("abc").value_or(0);
```

**好處**:
- **語義清晰**: 明確表示值可能不存在
- **類型安全**: 避免 `nullptr` 或哨兵值的誤用
- **異常替代**: 提供不拋異常的錯誤處理方式
- **函數式風格**: 支持 `map`, `and_then` 等操作

**缺點**:
- **記憶體開銷**: 額外的布爾標誌位
- **性能影響**: 頻繁檢查狀態可能有微小開銷
- **學習成本**: 需要理解 `optional` 的正確使用方式
- **兼容性**: C++17 以前版本不可用

### 3.4 std::variant

```cpp
#include <variant>

// 類型安全的 union
std::variant<int, double, std::string> v = 42;
v = 3.14;
v = "hello";

// 訪問
std::visit([](auto&& arg) {
    std::cout << arg << "\n";
}, v);

// 類型檢查
if (std::holds_alternative<int>(v)) {
    int x = std::get<int>(v);
}
```

**好處**:
- **類型安全**: 取代不安全的 C-style union
- **記憶體效率**: 只占用最大類型的空間
- **模式匹配**: `std::visit` 提供函數式處理方式
- **異常安全**: 訪問錯誤類型會拋出異常

**缺點**:
- **性能開銷**: 類型標誌和虛擬調用成本
- **複雜性**: `std::visit` 語法對初學者不友好  
- **編譯時間**: 複雜的模板實例化
- **調試困難**: 類型標籤信息在調試時不夠直觀

### 3.5 std::string_view

```cpp
#include <string_view>

// 零拷貝字符串視圖
void process(std::string_view sv) {
    std::cout << sv << "\n";
}

process("hello");  // 字面量
std::string s = "world";
process(s);  // std::string
process(s.substr(0, 3));  // 子串
```

**好處**:
- **零拷貝**: 避免不必要的字符串拷貝
- **統一接口**: 同時支持 `const char*`, `std::string` 等
- **性能**: 只傳遞指針和長度,成本極低
- **子串操作**: 高效的子串視圖操作

**缺點**:
- **生命週期**: 必須確保原字符串在視圖使用期間有效
- **懸空指針**: 原字符串銷毀後視圖變為懸空
- **C 接口**: 不以 null 結尾,與 C API 交互需要轉換
- **修改限制**: 只讀視圖,無法修改原內容

### 3.6 inline 變數

```cpp
// header.h
inline constexpr int MAX_SIZE = 100;
```

### 3.7 constexpr if

```cpp
template<typename T>
auto process(T value) {
    if constexpr (std::is_integral_v<T>) {
        return value * 2;
    } else if constexpr (std::is_floating_point_v<T>) {
        return value * 1.5;
    } else {
        return value;
    }
}
```

### 3.8 Fold Expression


## 4. C++20 特性

### 4.1 Concepts

```cpp
#include <concepts>

// 定義概念
template<typename T>
concept Numeric = std::is_arithmetic_v<T>;

// 使用概念約束
template<Numeric T>
T add(T a, T b) {
    return a + b;
}

add(1, 2);      // OK
add(1.5, 2.5);  // OK
// add("a", "b");  // Error!
```

**好處**:
- **錯誤訊息**: 模板錯誤訊息更清晰易懂
- **接口文檔**: 概念作為活文檔,明確模板要求
- **編譯加速**: 早期類型檢查,減少深層實例化
- **重載解析**: 更精確的函數重載選擇

**缺點**:
- **學習曲線**: 需要學習概念的定義和使用
- **編譯器支持**: 需要較新的編譯器版本
- **複雜性**: 複雜概念的定義可能很困難
- **編譯時間**: 概念檢查可能增加編譯時間

### 4.2 Ranges

```cpp
#include <ranges>
namespace views = std::views;

std::vector<int> vec = {1, 2, 3, 4, 5};

// 過濾 + 轉換
auto result = vec
    | views::filter([](int n) { return n % 2 == 0; })
    | views::transform([](int n) { return n * n; });

for (int x : result) {
    std::cout << x << " ";  // 4 16
}
```

**好處**:
- **函數式風格**: 鏈式操作,代碼更優雅
- **惰性求值**: 按需計算,節省記憶體和計算
- **組合性**: 視圖可以自由組合
- **STL 整合**: 與現有 STL 容器完美配合

**缺點**:
- **學習曲線**: 函數式編程思維需要適應
- **調試困難**: 惰性求值使調試變困難
- **編譯器支持**: 需要 C++20 完整支持
- **性能考量**: 某些場景可能不如手寫循環高效

### 4.3 std::span

```cpp
#include <span>

// 非擁有的連續序列視圖
void process(std::span<int> data) {
    for (int x : data) {
        std::cout << x << " ";
    }
}

int arr[] = {1, 2, 3};
std::vector<int> vec = {4, 5, 6};

process(arr);  // OK
process(vec);  // OK
```

**好處**:
- **統一接口**: 同時支持陣列、向量、指針等
- **邊界檢查**: 提供安全的下標存取
- **零開銷**: 只包含指針和大小,成本極低
- **切片操作**: 方便的子區間操作

**缺點**:
- **生命週期**: 必須確保原序列在 span 使用期間有效
- **動態大小**: 運行時大小可能影響某些優化
- **C++20 限制**: 需要較新編譯器支持
- **類型限制**: 只能用於連續記憶體序列

### 4.4 Designated Initializers

```cpp
// 指定初始化器
struct Point {
    int x;
    int y;
    int z;

Point p = {.x = 10, .y = 20, .z = 30};
Point p2 = {.x = 5, .z = 15};  // y 默認初始化為 0
```

### 4.5 三向比較 (Spaceship Operator)

```cpp
#include <compare>

struct Point {
    int x, y;

    // 自動生成所有比較運算符
    auto operator<=>(const Point&) const = default;
};

Point p1{1, 2};
Point p2{3, 4};

bool b1 = p1 < p2;   // OK
bool b2 = p1 == p2;  // OK
bool b3 = p1 >= p2;  // OK
```

### 4.6 Coroutines

```cpp
#include <coroutine>

// 協程 (簡化示例)
generator<int> fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;
        auto temp = a;
        a = b;
        b = temp + b;
    }
}

// 使用
for (int x : fibonacci()) {
    if (x > 100) break;
    std::cout << x << " ";
}
```

**好處**:
- **異步編程**: 簡化異步代碼編寫
- **記憶體效率**: 避免回調地獄和堆疊爆炸
- **狀態保持**: 自然保持函數執行狀態
- **可組合性**: 協程可以良好組合

**缺點**:
- **複雜性**: 概念複雜,學習成本高
- **調試困難**: 協程狀態機難以調試
- **性能開銷**: 狀態保存和恢復有開銷
- **編譯器支持**: 需要完整的 C++20 支持
- **生態系統**: 標準庫支持仍不完善

### 4.7 其他特性

```cpp
// consteval: 強制編譯期執行
consteval int square(int x) {
    return x * x;
}

// constinit: 編譯期初始化
constinit int global = 42;

// [[likely]] / [[unlikely]]
if (condition) [[likely]] {
    // 大多數情況
} else [[unlikely]] {
    // 極少發生
}

// 模板 Lambda
auto f = []<typename T>(T x) {
    return x * 2;
};
```

## 5. 特性選擇指南

### 5.1 優先使用的特性

**C++11**:

- ✅ `auto` - 簡化類型聲明
- ✅ 範圍 for - 簡化循環
- ✅ `nullptr` - 取代 NULL
- ✅ 智能指針 - 自動記憶體管理
- ✅ Lambda - 函數式編程
- ✅ 移動語義 - 性能優化

**C++14**:

- ✅ `make_unique` - 異常安全
- ✅ 泛型 Lambda - 更靈活
- ✅ 數字分隔符 - 提高可讀性

**C++17**:

- ✅ 結構化綁定 - 簡化代碼
- ✅ `std::optional` - 取代錯誤碼
- ✅ `std::string_view` - 零拷貝
- ✅ `if constexpr` - 編譯期分支

**C++20**:

- ✅ Concepts - 更好的模板約束
- ✅ Ranges - 函數式編程
- ✅ `std::span` - 安全的陣列視圖

### 5.2 高頻交易與性能敏感場景推薦

**零開銷抽象 (Zero Overhead)**:
```cpp
// ✅ 強烈推薦 - 零運行時成本
auto price = calculate_price();      // auto 類型推導
for (const auto& order : orders) {}  // 範圍 for
constexpr int MAX_SIZE = 1000;      // constexpr 常數
std::unique_ptr<Order> order;       // unique_ptr
std::string_view symbol;            // string_view (無拷貝)
if constexpr (condition) {}         // 編譯期分支
```

**微小開銷但值得使用**:
```cpp
// ✅ 推薦使用 - 開銷極小
std::optional<Price> price;         // 1 byte 標誌位
std::span<int> data;               // 只有指針+大小
Lambda 表達式;                      // 通常被內聯
結構化綁定 auto [a, b] = pair;      // 編譯期展開
```

**需要測量的特性**:
```cpp
// ⚠️ 謹慎使用 - 需要性能測試
std::shared_ptr<Data> data;        // 原子引用計數
std::variant<A, B> obj;            // 類型標誌+間接訪問
std::visit(visitor, variant);      // 虛擬調用或跳轉表
Ranges 管道操作;                    // 可能產生額外間接層
std::function<void()> callback;    // 類型擦除+堆分配風險
```

**高成本特性**:
```cpp
// ❌ 熱路徑避免使用
try { } catch { }                  // 異常處理開銷
dynamic_cast<T*>(ptr);             // RTTI 查找
協程 (Coroutines);                  // 狀態機+記憶體分配
std::regex operations;             // 正則表達式編譯
```

### 5.3 性能特性分析

**編譯期特性 (零運行時開銷)**:
- `auto` 類型推導 - 純編譯期,零開銷
- `constexpr` / `consteval` - 編譯期計算
- `constexpr if` - 編譯期分支選擇
- 範圍 for 循環 - 優化為普通循環
- Lambda 表達式 - 通常完全內聯
- `static_assert` - 編譯期檢查

**記憶體效率特性**:
- `std::string_view` - 只有指針+長度 (16 bytes)
- `std::span` - 只有指針+大小 (16 bytes)  
- `std::unique_ptr` - 只有指針大小 (8 bytes)
- 移動語義 - 避免深拷貝,只轉移資源
- 結構化綁定 - 編譯期展開,無額外儲存

**有開銷但合理的特性**:
- `std::optional<T>` - sizeof(T) + 1 byte 標誌
- `std::shared_ptr<T>` - 8 bytes + 控制塊 (原子計數)
- `std::variant<T...>` - max(sizeof(T...)) + 類型標誌
- Concepts - 編譯期檢查,可能增加編譯時間

**高開銷特性**:
- `std::function` - 類型擦除,可能堆分配
- `std::visit` - 虛擬調用或跳轉表
- 異常處理 - 堆疊展開和清理成本
- RTTI (`dynamic_cast`) - 類型信息查找

### 5.5 實際使用建議

**按應用場景選擇**:

**系統編程/高性能計算**:
```cpp
✅ auto, constexpr, 範圍for, 移動語義, unique_ptr
✅ string_view, span, optional (小型物件)
⚠️ shared_ptr (僅在必要時), variant (測試性能)
❌ exception, function, 複雜ranges鏈
```

**業務邏輯/應用開發**:
```cpp  
✅ 所有現代特性都可以使用
✅ 特別推薦: optional, variant, ranges, concepts
✅ 智能指針全系列, 結構化綁定
```

**函式庫開發**:
```cpp
✅ concepts (清晰API約束), constexpr (編譯期優化)
✅ 完美轉發, 變參模板, SFINAE/concepts
⚠️ 謹慎使用 ranges (ABI穩定性)
```

**遷移策略**:
1. **C++11 特性** - 立即採用,收益最大
2. **C++14 特性** - 逐步引入,風險極低
3. **C++17 特性** - 評估編譯器支持,選擇性採用
4. **C++20 特性** - 新專案優先,舊專案謹慎
