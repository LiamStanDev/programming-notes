## 1. const 的多重含義

### 1.1 const 與指針

這是 C++ 中最容易混淆的概念之一。

```cpp
// 1. 指向 const 的指針 (pointer to const)
const int* p1;   // p1 可變,*p1 不可變
int const* p2;   // 同上,const 在 * 左側

int x = 42, y = 100;
p1 = &x;   // ✅ OK, 改變指針指向
// *p1 = 10;  // ❌ Error! 不能修改指向的值

// 2. const 指針 (const pointer)
int* const p3 = &x;  // p3 不可變,*p3 可變
*p3 = 10;  // ✅ OK, 修改指向的值
// p3 = &y;   // ❌ Error! 不能改變指針指向

// 3. 指向 const 的 const 指針
const int* const p4 = &x;
// p4 = &y;   // ❌ Error! 指針不可變
// *p4 = 10;  // ❌ Error! 指向的值不可變
```

#### 記憶技巧: 從右向左讀

```cpp
const int* const p;
//           ^---- p is const (指針是常數)
//      ^--------- pointer to const int (指向常數 int)

int const* const p;
// ^-------------- const int (常數整數)
//           ^---- const pointer (常數指針)
```

#### 函數參數中的應用

```cpp
// 不會修改指向的值
void read_only(const int* p) {
    // *p = 10;  // Error
    int value = *p;  // OK
}

// 不會改變指針指向 (但可修改值)
void modify_value(int* const p) {
    *p = 10;  // OK
    // p = nullptr;  // Error
}

// 都不改變
void fully_const(const int* const p) {
    // p = nullptr;  // Error
    // *p = 10;  // Error
    int value = *p;  // OK
}
```

### 1.2 const 成員函數

const 成員函數保證不修改物件狀態。

```cpp
class Vector {
    double x_, y_;
    
public:
    // const 成員函數: 不修改物件狀態
    double length() const {
        // x_ = 10;  // ❌ Error! 不能修改成員
        return std::sqrt(x_ * x_ + y_ * y_);
    }
    
    // 非 const 成員函數
    void set_x(double x) {
        x_ = x;  // OK
    }
    
    // const 重載: 提供唯讀和讀寫兩個版本
    double& operator[](size_t i) {
        return data_[i];  // 可修改
    }
    
    const double& operator[](size_t i) const {
        return data_[i];  // 唯讀
    }
    
private:
    double data_[10];
};

// const 物件只能調用 const 成員函數
const Vector v{1, 2};
double len = v.length();   // ✅ OK
// v.set_x(10);  // ❌ Error! 不能調用非 const 成員函數

// 非 const 物件可以調用兩種
Vector v2{3, 4};
v2.length();    // 調用 const 版本 (也可以)
v2.set_x(10);   // 調用非 const 版本
```

### 1.3 mutable - 打破 const

`mutable` 允許在 const 成員函數中修改成員變數。

```cpp
class Cache {
    mutable std::mutex mtx_;               // mutable 成員
    mutable std::map<int, int> cache_;     // mutable 成員
    
public:
    int get(int key) const {  // const 成員函數
        std::lock_guard<std::mutex> lock(mtx_);  // ✅ OK
        
        auto it = cache_.find(key);
        if (it != cache_.end()) {
            return it->second;
        }
        
        // 計算並緩存
        int value = expensive_calculation(key);
        cache_[key] = value;  // ✅ OK, 修改 mutable 成員
        return value;
    }
    
private:
    int expensive_calculation(int key) const;
};
```

#### 何時使用 mutable?

| 使用場景 | 範例 | 原因 |
|---------|------|------|
| 緩存 (lazy evaluation) | `mutable std::map cache_` | 緩存不影響邏輯狀態 |
| 執行緒同步原語 | `mutable std::mutex mtx_` | 鎖不影響邏輯狀態 |
| 統計資訊 | `mutable int access_count_` | 計數器不影響邏輯狀態 |

⚠️ **注意**: 不要濫用 `mutable`,它打破了 const 的語義。

## 2. static 的多重含義

`static` 在不同上下文有完全不同的含義。

### 2.1 靜態局部變數

```cpp
void counter() {
    static int count = 0;  // 只初始化一次
    ++count;
    std::cout << count << "\n";
}

counter();  // 輸出: 1
counter();  // 輸出: 2
counter();  // 輸出: 3
```

#### C++11 執行緒安全初始化

```cpp
// ✅ C++11 保證執行緒安全的初始化
void thread_safe_singleton() {
    static ExpensiveObject obj;  // 只會初始化一次,即使多執行緒同時調用
    return &obj;
}

// 實現等價於:
void thread_safe_singleton_manual() {
    static std::once_flag flag;
    static ExpensiveObject* obj = nullptr;
    std::call_once(flag, []() {
        obj = new ExpensiveObject();
    });
    return obj;
}
```

#### 執行緒安全陷阱

```cpp
// ⚠️ 初始化是執行緒安全的,但操作不是!
void counter_unsafe() {
    static int count = 0;  // 初始化執行緒安全
    ++count;  // ❌ 數據競爭! 操作不是執行緒安全的
}

// ✅ 執行緒安全版本
void counter_safe() {
    static std::atomic<int> count{0};
    count.fetch_add(1, std::memory_order_relaxed);
}
```

### 2.2 靜態成員變數

```cpp
class Config {
public:
    // 類內初始化 (C++11: 僅整數 const static)
    static const int MAX_SIZE = 100;  // ✅ OK
    
    // 類內聲明,類外定義
    static double pi;  // 聲明
    
    // C++17 前需類外定義
    static std::string name;
    
    // C++17: inline 靜態成員變數 (推薦)
    inline static std::string name_cpp17 = "default";
    inline static std::atomic<int> counter{0};
};

// 類外定義 (在 .cpp 文件)
double Config::pi = 3.14159;
std::string Config::name = "config";
```

#### 靜態成員函數

```cpp
class Math {
public:
    static int add(int a, int b) {
        // 不能訪問非靜態成員!
        // value_ = 10;  // Error!
        return a + b;
    }
    
    static double get_pi() {
        return pi_;  // OK, 訪問靜態成員
    }
    
private:
    static constexpr double pi_ = 3.14159;
    int value_;  // 非靜態成員
};

// 調用無需物件
int result = Math::add(1, 2);
```

### 2.3 內部連結 (檔案作用域)

```cpp
// file1.cpp
static int internal_var = 42;  // 只在此 .cpp 可見

static void internal_func() {  // 只在此 .cpp 可見
    // ...
}

// ✅ C++11 推薦: 使用匿名命名空間 (更好的替代)
namespace {
    int internal_var = 42;
    void internal_func() {}
}

// 為什麼更好?
// 1. 可用於類型定義 (static class 非法)
// 2. 更符合 C++ 風格
// 3. 名稱修飾更好
```

## 3. inline 的真正含義

⚠️ **常見誤解**: `inline` **不是**建議編譯器內聯函數!

### 3.1 inline 的真正含義

1. **允許多重定義** (One Definition Rule 的例外)
2. **C++17: 允許在標頭檔定義變數**

```cpp
// header.h
inline int add(int a, int b) {
    return a + b;  // 可在多個 .cpp 包含,連接器會合併
}

// ⚠️ 編譯器自行決定是否內聯,與 inline 關鍵字幾乎無關!
// 編譯器會內聯: 小函數、頻繁調用
// 編譯器不會內聯: 大函數、遞歸函數、虛函數
```

### 3.2 inline 變數 (C++17)

```cpp
// header.h
inline constexpr double PI = 3.14159;  // ✅ C++17
inline std::atomic<int> counter{0};    // ✅ C++17

// C++17 前需要這樣做:
// header.h
extern const double PI;  // 聲明

// source.cpp
const double PI = 3.14159;  // 定義

// ✅ C++17 簡化為:
inline constexpr double PI = 3.14159;
```

### 3.3 強制內聯

```cpp
// GCC/Clang
__attribute__((always_inline)) inline 
int critical_function(int x) {
    return x * 2;
}

// MSVC
__forceinline int critical_function(int x) {
    return x * 2;
}

// ⚠️ 編譯器仍可能拒絕內聯:
// - 遞歸函數
// - 含有複雜控制流
// - 函數過大
```

### 3.4 類內定義的函數自動為 inline

```cpp
class Widget {
public:
    // 類內定義 = 隱式 inline
    int get_value() const {
        return value_;
    }
    
    // 等價於在類外:
    // inline int Widget::get_value() const {
    //     return value_;
    // }
    
private:
    int value_;
};
```

## 4. constexpr - 編譯期計算

### 4.1 constexpr vs const

```cpp
// const: 執行期或編譯期常數
const int runtime = get_value();   // 執行期初始化
const int compile = 42;            // 編譯期 (可能被優化)

// constexpr: 保證編譯期常數
constexpr int value = 42;          // ✅ 編譯期
// constexpr int bad = get_value();  // ❌ Error! 必須編譯期可計算

// 使用場景
int array1[compile];   // 可能通過編譯 (取決於編譯器)
int array2[value];     // ✅ 一定通過 (constexpr 保證)
```

### 4.2 constexpr 函數

```cpp
// C++11: 單一 return 語句
constexpr int square(int x) {
    return x * x;
}

// C++14: 允許多個語句、迴圈
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

// 編譯期執行
constexpr int fact5 = factorial(5);  // 120 (編譯期計算)
int arr[factorial(4)];               // 陣列大小: 24

// 也可執行期執行
int n;
std::cin >> n;
int result = factorial(n);  // 執行期計算
```

### 4.3 constexpr 建構函數

```cpp
class Point {
    int x_, y_;
    
public:
    constexpr Point(int x, int y) : x_(x), y_(y) {}
    
    constexpr int x() const { return x_; }
    constexpr int y() const { return y_; }
    
    constexpr int distance_squared() const {
        return x_ * x_ + y_ * y_;
    }
};

// 編譯期計算
constexpr Point p{3, 4};
constexpr int dist = p.distance_squared();  // 25 (編譯期)
int arr[dist];  // OK, 大小為 25
```

### 4.4 constexpr if (C++17)

```cpp
template<typename T>
void process(T value) {
    if constexpr (std::is_integral_v<T>) {
        // 整數分支
        std::cout << "Integer: " << value << "\n";
    } else if constexpr (std::is_floating_point_v<T>) {
        // 浮點分支
        std::cout << "Float: " << value << "\n";
    } else {
        // 其他類型
        std::cout << "Other\n";
    }
    // ✅ 未使用的分支不會編譯! (真正的編譯期分支)
}

process(42);      // 只編譯整數分支
process(3.14);    // 只編譯浮點分支
```

### 4.5 consteval (C++20) - 立即函數

```cpp
// consteval: 必須在編譯期執行
consteval int square(int x) {
    return x * x;
}

constexpr int fact = square(5);  // ✅ OK, 編譯期

int n = 5;
// int bad = square(n);  // ❌ Error! 不能執行期調用
```

## 5. volatile 與多執行緒

⚠️ **常見誤解**: `volatile` **不是**用於多執行緒同步!

### 5.1 volatile 的真正用途

```cpp
// ✅ 正確用途: 記憶體映射 I/O
volatile uint32_t* const hardware_register = 
    reinterpret_cast<volatile uint32_t*>(0x40000000);

*hardware_register = 0xFF;  // 保證寫入
uint32_t value = *hardware_register;  // 保證讀取
```

**volatile 的語義**:
- 禁止編譯器優化讀寫操作
- 每次訪問都從記憶體讀取/寫入
- 不保證原子性
- 不保證記憶體順序

### 5.2 volatile 不能用於多執行緒

```cpp
// ❌ 錯誤: volatile 不能保證執行緒安全
volatile int counter = 0;

void thread_func() {
    counter++;  // ❌ 仍然是數據競爭!
}

// ✅ 正確: 使用 atomic
std::atomic<int> counter{0};

void thread_func() {
    counter.fetch_add(1, std::memory_order_relaxed);
}
```

### 5.3 volatile 的合法使用場景

1. **硬體暫存器訪問**
2. **信號處理程式** (部分場景)
3. **setjmp/longjmp**

```cpp
// 信號處理程式範例
volatile sig_atomic_t signal_received = 0;

void signal_handler(int sig) {
    signal_received = 1;  // OK
}

int main() {
    signal(SIGINT, signal_handler);
    
    while (!signal_received) {
        // 保證每次讀取 signal_received
    }
}
```

## 6. 關鍵字組合總結

### 6.1 常見組合

| 組合 | 含義 | 使用場景 |
|-----|------|---------|
| `const int` | 執行期常數 | 一般不可變值 |
| `constexpr int` | 編譯期常數 | 陣列大小、模板參數 |
| `static const` | 類內常數 | 類級別配置 |
| `static constexpr` | 類內編譯期常數 | 類級別編譯期值 |
| `inline constexpr` | 標頭檔編譯期常數 (C++17) | 跨翻譯單元常數 |
| `inline static` | 類內定義靜態成員 (C++17) | 簡化靜態成員定義 |
| `mutable` | const 成員函數可修改 | 緩存、mutex、計數器 |
| `static thread_local` | 執行緒局部靜態變數 | 執行緒緩存 |
| `volatile` | 禁止優化 | MMIO、信號處理 |

### 6.2 組合範例

```cpp
class Config {
public:
    // C++17 推薦寫法
    inline static constexpr int MAX_SIZE = 100;
    inline static std::string default_name = "config";
    
    // C++11 寫法 (需類外定義)
    static const int BUFFER_SIZE = 1024;
    static double pi;  // 需類外定義
    
private:
    mutable std::mutex mtx_;  // const 成員函數可修改
    static thread_local int thread_id_;  // 每個執行緒獨立
};

// C++11 類外定義
double Config::pi = 3.14159;
thread_local int Config::thread_id_ = 0;
```

## 7. 實戰案例

### 案例 1: 單例模式 (Meyers' Singleton)

```cpp
class Singleton {
public:
    static Singleton& instance() {
        // C++11 保證執行緒安全初始化
        static Singleton inst;
        return inst;
    }
    
    // 禁止複製和移動
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
    
private:
    Singleton() = default;
};

// 使用
Singleton::instance().do_something();
```

### 案例 2: 編譯期配置

```cpp
// 配置類
class ServerConfig {
public:
    inline static constexpr int MAX_CONNECTIONS = 1000;
    inline static constexpr int BUFFER_SIZE = 4096;
    inline static constexpr int TIMEOUT_MS = 5000;
    
    // 編譯期計算
    inline static constexpr size_t total_buffer_size() {
        return MAX_CONNECTIONS * BUFFER_SIZE;
    }
};

// 編譯期計算
constexpr size_t buffer_size = ServerConfig::total_buffer_size();
char buffer[buffer_size];  // 陣列大小在編譯期確定
```

### 案例 3: 執行緒安全計數器

```cpp
class Counter {
    mutable std::atomic<uint64_t> count_{0};
    mutable std::mutex mtx_;
    mutable std::map<int, int> stats_;  // 統計資訊
    
public:
    uint64_t increment() const {  // const 成員函數
        return count_.fetch_add(1, std::memory_order_relaxed);
    }
    
    void add_stat(int key, int value) const {
        std::lock_guard<std::mutex> lock(mtx_);
        stats_[key] += value;  // 修改 mutable 成員
    }
    
    uint64_t get_count() const {
        return count_.load(std::memory_order_relaxed);
    }
};
```

### 案例 4: 記憶體映射 I/O

```cpp
// 硬體暫存器定義
struct HardwareRegisters {
    volatile uint32_t control;
    volatile uint32_t status;
    volatile uint32_t data;
    uint32_t reserved;  // 不用 volatile (未使用)
};

class Device {
    HardwareRegisters* regs_;
    
public:
    explicit Device(uintptr_t base_addr) {
        regs_ = reinterpret_cast<HardwareRegisters*>(base_addr);
    }
    
    void start() {
        regs_->control = 0x01;  // volatile 保證寫入
    }
    
    bool is_ready() const {
        return (regs_->status & 0x01) != 0;  // volatile 保證讀取
    }
    
    uint32_t read_data() const {
        return regs_->data;
    }
};
```

### 案例 5: constexpr 編譯期字符串哈希

```cpp
// 編譯期計算字符串哈希
constexpr uint32_t fnv1a_hash(const char* str, size_t len) {
    uint32_t hash = 2166136261u;
    for (size_t i = 0; i < len; ++i) {
        hash ^= static_cast<uint32_t>(str[i]);
        hash *= 16777619u;
    }
    return hash;
}

constexpr uint32_t operator"" _hash(const char* str, size_t len) {
    return fnv1a_hash(str, len);
}

// 編譯期計算
constexpr uint32_t msg_type_login = "LOGIN"_hash;
constexpr uint32_t msg_type_logout = "LOGOUT"_hash;

// switch 可使用
void handle_message(uint32_t type) {
    switch (type) {
    case msg_type_login:   // 編譯期常數
        handle_login();
        break;
    case msg_type_logout:
        handle_logout();
        break;
    }
}
```

## 總結

### 關鍵要點

1. **const 與指針**: 從右向左讀,分清指針本身的 const 與指向內容的 const
2. **const 成員函數**: 不修改物件狀態,const 物件只能調用 const 成員函數
3. **mutable**: 允許 const 成員函數修改,用於緩存、鎖、統計
4. **static 局部變數**: C++11 保證執行緒安全初始化,但操作不保證
5. **inline**: 允許多重定義,C++17 可用於變數,不是內聯提示
6. **constexpr**: 保證編譯期計算,可用於函數、變數、建構函數
7. **volatile**: 禁止優化,用於 MMIO,不用於多執行緒同步

### 最佳實踐

- ✅ 盡可能使用 `constexpr` 而非 `const`
- ✅ C++17 使用 `inline static` 定義類內靜態成員
- ✅ 使用匿名命名空間而非 `static` (檔案作用域)
- ✅ 單例模式使用 `static` 局部變數 (Meyers' Singleton)
- ✅ 多執行緒用 `std::atomic`,不用 `volatile`
- ✅ 成員函數盡可能標記為 `const`
- ✅ 單參數建構函式加 `explicit`
