## 1. 異常基礎

### 1.1 異常機制

```cpp
// 拋出異常
void divide(int a, int b) {
    if (b == 0) {
        throw std::invalid_argument("Division by zero");
    }
    return a / b;
}

// 捕獲異常
try {
    int result = divide(10, 0);
} catch (const std::invalid_argument& e) {
    std::cerr << "Error: " << e.what() << "\n";
} catch (const std::exception& e) {
    std::cerr << "Unexpected error: " << e.what() << "\n";
} catch (...) {
    std::cerr << "Unknown error\n";
}
```

### 1.2 標準異常層次

```cpp
// std::exception 層次結構
// std::exception          
//   ├── std::logic_error      (內部邏輯檢查)
//   │   ├── std::invalid_argument
//   │   ├── std::domain_error      
//   │   ├── std::length_error      
//   │   └── std::out_of_range
//   └── std::runtime_error    (外部環境/計算問題)
//       ├── std::range_error
//       ├── std::overflow_error
//       └── std::underflow_error

// 使用
void process(int value) {
    if (value < 0) {
        throw std::invalid_argument("Value must be non-negative");
    }
    if (value > MAX_VALUE) {
        throw std::out_of_range("Value exceeds maximum");
    }
}
```

### 1.3 自定義異常

```cpp
class OrderException : public std::runtime_error {
    int order_id_;

public:
    explicit OrderException(int id, const std::string& msg)
        : std::runtime_error(msg), order_id_(id) {}

    int order_id() const { return order_id_; }
};

// 使用
void process_order(const Order& order) {
    if (!order.is_valid()) {
        throw OrderException(order.id, "Invalid order");
    }
}

try {
    process_order(order);
} catch (const OrderException& e) {
    std::cerr << "Order " << e.order_id() << " failed: "
              << e.what() << "\n";
}
```

## 2. 異常安全保證

### 2.1 三種安全保證

**1. 基本保證 (Basic Guarantee)**:

- 不洩漏資源
- 對象處於有效狀態 (但未指定)

**2. 強保證 (Strong Guarantee)**:

- 操作成功或完全回滾
- 對象狀態不變

**3. 不拋出保證 (No-throw Guarantee)**:

- 操作保證不拋出異常
- 通常標記為 `noexcept`

```cpp
// 基本保證
void basic_guarantee(std::vector<int>& vec, int value) {
    vec.push_back(value);  // 可能拋出,但 vec 仍有效
}

// 強保證 (Copy-and-swap idiom)
class Widget {
    std::vector<int> data_;

public:
    Widget& operator=(const Widget& other) {
        Widget temp(other);  // 可能拋出
        swap(temp);          // 不拋出
        return *this;
    }

    void swap(Widget& other) noexcept {
        data_.swap(other.data_);
    }
};

// 不拋出保證
void no_throw() noexcept {
    // 保證不拋出異常
}
```

### 2.2 Copy-and-Swap Idiom

```cpp
class Buffer {
    char* data_;
    size_t size_;

public:
    // 強異常安全的賦值
    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            Buffer temp(other);  // 可能拋出
            swap(temp);          // 不拋出
        }
        return *this;
    }

    void swap(Buffer& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }
};
```

### 2.3 noexcept 的重要性

```cpp
class Widget {
public:
    // ✅ 移動操作應標記為 noexcept
    Widget(Widget&&) noexcept;
    Widget& operator=(Widget&&) noexcept;

    // ✅ swap 應標記為 noexcept
    void swap(Widget&) noexcept;

    // ✅ 解構函式隱式 noexcept
    ~Widget();
};

// 為什麼重要?
std::vector<Widget> vec;
vec.push_back(Widget{});

// 如果移動建構函式不是 noexcept:
// - vector 重新分配時會拷貝而非移動
// - 性能大幅下降!
```

## 3. RAII 與異常安全

### 3.1 RAII 自動清理

```cpp
// ❌ 手動清理 (不安全)
void bad_example() {
    int* p = new int(42);
    process(p);  // 可能拋出異常
    delete p;    // 不會執行!
}

// ✅ RAII 自動清理
void good_example() {
    auto p = std::make_unique<int>(42);
    process(p.get());  // 即使拋出異常,p 也會自動釋放
}
```

### 3.2 RAII 守衛

```cpp
// 文件守衛
class FileGuard {
    FILE* fp_;

public:
    explicit FileGuard(const char* filename)
        : fp_(std::fopen(filename, "r")) {
        if (!fp_) {
            throw std::runtime_error("Failed to open file");
        }
    }

    ~FileGuard() {
        if (fp_) std::fclose(fp_);
    }

    FileGuard(const FileGuard&) = delete;
    FileGuard& operator=(const FileGuard&) = delete;

    FILE* get() const { return fp_; }
};

// 使用
void process_file(const char* filename) {
    FileGuard file(filename);  // 自動管理
    // ... 處理文件
    // 即使拋出異常,文件也會自動關閉
}
```

### 3.3 鎖守衛

```cpp
std::mutex mtx;
int shared_data = 0;

// ❌ 手動加鎖 (不安全)
void bad_example() {
    mtx.lock();
    process(shared_data);  // 可能拋出異常
    mtx.unlock();          // 不會執行!
}

// ✅ RAII 鎖守衛
void good_example() {
    std::lock_guard<std::mutex> lock(mtx);
    process(shared_data);  // 即使拋出異常,鎖也會自動釋放
}

// ✅ 或使用 unique_lock (更靈活)
void flexible_example() {
    std::unique_lock<std::mutex> lock(mtx);
    process(shared_data);
    lock.unlock();  // 可以手動解鎖
    // ...
    lock.lock();    // 可以重新加鎖
}
```

## 4. 異常的替代方案

### 4.1 錯誤碼

```cpp
enum class ErrorCode {
    SUCCESS,
    INVALID_INPUT,
    FILE_NOT_FOUND,
    NETWORK_ERROR
};

// 返回錯誤碼
ErrorCode read_file(const std::string& filename, std::string& content) {
    std::ifstream file(filename);
    if (!file) {
        return ErrorCode::FILE_NOT_FOUND;
    }

    content.assign(std::istreambuf_iterator<char>(file),
                   std::istreambuf_iterator<char>());
    return ErrorCode::SUCCESS;
}

// 使用
std::string content;
ErrorCode err = read_file("data.txt", content);
if (err != ErrorCode::SUCCESS) {
    // 處理錯誤
}
```

### 4.2 std::optional (C++17)

```cpp
#include <optional>

// 可能失敗的操作
std::optional<int> parse_int(const std::string& str) {
    try {
        return std::stoi(str);
    } catch (...) {
        return std::nullopt;
    }
}

// 使用
auto result = parse_int("123");
if (result) {
    std::cout << "Value: " << *result << "\n";
} else {
    std::cout << "Parse failed\n";
}

// 或使用 value_or
int value = parse_int("abc").value_or(0);
```

### 4.3 std::expected (C++23)

```cpp
// C++23 std::expected (類似 Rust 的 Result)
template<typename T, typename E>
class expected {
    // 包含值或錯誤
};

// 使用
std::expected<int, std::string> divide(int a, int b) {
    if (b == 0) {
        return std::unexpected("Division by zero");
    }
    return a / b;
}

auto result = divide(10, 2);
if (result) {
    std::cout << "Result: " << *result << "\n";
} else {
    std::cout << "Error: " << result.error() << "\n";
}
```

### 4.4 std::variant

```cpp
#include <variant>

// 成功或錯誤
using Result = std::variant<int, std::string>;

Result divide(int a, int b) {
    if (b == 0) {
        return std::string("Division by zero");
    }
    return a / b;
}

// 使用
auto result = divide(10, 2);
std::visit([](auto&& arg) {
    using T = std::decay_t<decltype(arg)>;
    if constexpr (std::is_same_v<T, int>) {
        std::cout << "Result: " << arg << "\n";
    } else {
        std::cout << "Error: " << arg << "\n";
    }
}, result);
```

## 5. 錯誤處理最佳實踐

### 5.1 何時使用異常?

**✅ 適合使用異常**:

- 構造函數失敗
- 資源分配失敗
- 不可恢復的錯誤
- 跨多層調用的錯誤傳播

**❌ 不適合使用異常**:

- 正常的控制流
- 高頻操作 (性能關鍵路徑)
- 可預期的錯誤 (如文件不存在)
- 嵌入式系統 (禁用異常)

```cpp
// ✅ 適合: 構造函數失敗
class Connection {
public:
    Connection(const std::string& host) {
        if (!connect(host)) {
            throw std::runtime_error("Connection failed");
        }
    }
};

// ❌ 不適合: 正常控制流
void bad_example() {
    try {
        for (int i = 0; ; ++i) {
            process(i);
        }
    } catch (const EndOfData&) {
        // 不要用異常控制循環!
    }
}
```

### 5.2 高頻交易場景

```cpp
// ❌ 避免: 熱路徑使用異常
Order process_order(const OrderRequest& req) {
    if (!req.is_valid()) {
        throw std::invalid_argument("Invalid request");  // 太慢!
    }
    // ...
}

// ✅ 使用錯誤碼或 optional
std::optional<Order> process_order(const OrderRequest& req) {
    if (!req.is_valid()) {
        return std::nullopt;  // 快速返回
    }
    // ...
    return order;
}

// ✅ 或使用 expected
std::expected<Order, ErrorCode> process_order(const OrderRequest& req) {
    if (!req.is_valid()) {
        return std::unexpected(ErrorCode::INVALID_REQUEST);
    }
    // ...
    return order;
}
```

### 5.3 異常安全的容器操作

```cpp
class OrderBook {
    std::vector<Order> orders_;

public:
    // ✅ 強異常安全
    void add_order(const Order& order) {
        orders_.push_back(order);  // 可能拋出
        // 如果拋出,orders_ 保持不變
    }

    // ✅ 預分配避免異常
    void add_orders(const std::vector<Order>& new_orders) {
        orders_.reserve(orders_.size() + new_orders.size());
        for (const auto& order : new_orders) {
            orders_.push_back(order);  // 不會拋出 (已預分配)
        }
    }
};
```

### 5.4 日誌與錯誤處理

```cpp
// ✅ 記錄異常但不吞噬
void process() {
    try {
        risky_operation();
    } catch (const std::exception& e) {
        log_error("Operation failed: " + std::string(e.what()));
        throw;  // 重新拋出
    }
}

// ✅ 轉換異常類型
void high_level_operation() {
    try {
        low_level_operation();
    } catch (const LowLevelException& e) {
        throw HighLevelException("High level operation failed", e);
    }
}
```
