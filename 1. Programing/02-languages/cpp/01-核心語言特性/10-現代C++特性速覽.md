## 1. C++11 核心特性

### 1.1 Auto 類型推導

```cpp
// auto 類型推導
auto x = 42;              // int
auto y = 3.14;            // double
auto z = std::make_unique<int>(10);  // std::unique_ptr<int>

// 複雜類型簡化
std::map<std::string, std::vector<int>> map;
auto it = map.begin();  // 取代冗長的迭代器類型

// ⚠️ 注意引用
auto a = vec[0];   // 拷貝
auto& b = vec[0];  // 引用
const auto& c = vec[0];  // const 引用
```

**好處**:
- **可讀性**: 減少冗長的類型聲明,特别是模板類型
- **維護性**: 當類型改變時,代碼自動適配
- **開發效率**: 減少手動輸入複雜類型名稱
- **性能**: 編譯期類型推導,無運行時開銷

**缺點**:
- **可讀性降低**: 有時類型不明確,影響代碼理解
- **意外拷貝**: 忘記使用引用可能導致不必要的拷貝
- **調試困難**: IDE 可能無法顯示推導的具體類型

### 1.2 範圍 For 循環

```cpp
std::vector<int> vec = {1, 2, 3, 4, 5};

// 範圍 for
for (const auto& x : vec) {
    std::cout << x << "\n";
}

// 修改元素
for (auto& x : vec) {
    x *= 2;
}

// 初始化列表
for (int x : {1, 2, 3, 4, 5}) {
    std::cout << x << " ";
}
```

**好處**:
- **可讀性**: 語法簡潔,意圖明確
- **安全性**: 避免陣列越界錯誤
- **維護性**: 容器大小改變時無需修改循環
- **性能**: 編譯器優化與手寫索引循環相當

**缺點**:
- **靈活性**: 無法直接獲取索引,需要額外處理
- **控制流**: 無法輕易跳躍或反向遍歷
- **複雜遍歷**: 對於複雜的遍歷模式可能不適用

### 1.3 nullptr

```cpp
// nullptr 取代 NULL
int* p = nullptr;  // 明確的空指針

// 函數重載
void func(int x);
void func(int* p);

func(0);        // 調用 func(int)
func(NULL);     // 可能有歧義
func(nullptr);  // 明確調用 func(int*)
```

**好處**:
- **類型安全**: 避免整數與指針的混淆
- **重載解析**: 明確指示指針類型,避免歧義
- **可讀性**: 明確表示空指針意圖
- **性能**: 編譯期處理,無運行時開銷

**缺點**:
- **向後相容**: 與舊代碼混用時需要注意一致性
- **微小開銷**: 某些情況下可能增加二進制大小(極少見)

### 1.5 移動語義

移動語義是 C++11 最重要的性能優化特性，通過轉移資源所有權而非拷貝來提升效率。

#### 1.5.1 基本概念與語法

```cpp
#include <vector>
#include <string>
#include <utility>

void basic_move_semantics() {
    // 右值引用基礎
    std::vector<int> v1 = {1, 2, 3, 4, 5};
    std::vector<int> v2 = std::move(v1);  // 移動，不拷貝
    
    // v1 現在是空的（移動後狀態）
    std::cout << "v1 size after move: " << v1.size() << "\n";  // 0
    std::cout << "v2 size after move: " << v2.size() << "\n";  // 5
    
    // 字串移動
    std::string s1 = "Hello, World!";
    std::string s2 = std::move(s1);  // 移動字串內容
    
    std::cout << "s1 after move: '" << s1 << "'\n";  // 空字串
    std::cout << "s2 after move: '" << s2 << "'\n";  // "Hello, World!"
}
```

#### 1.5.2 實現移動建構函式和移動賦值

```cpp
class Resource {
private:
    int* data;
    size_t size;
    
public:
    // 一般建構函式
    Resource(size_t sz) : size(sz), data(new int[sz]) {
        std::cout << "Constructor: allocated " << size << " ints\n";
    }
    
    // 拷貝建構函式
    Resource(const Resource& other) : size(other.size), data(new int[size]) {
        std::copy(other.data, other.data + size, data);
        std::cout << "Copy constructor: allocated " << size << " ints\n";
    }
    
    // 移動建構函式
    Resource(Resource&& other) noexcept : size(other.size), data(other.data) {
        other.data = nullptr;  // 重要：清空源物件
        other.size = 0;
        std::cout << "Move constructor: transferred ownership\n";
    }
    
    // 拷貝賦值運算符
    Resource& operator=(const Resource& other) {
        if (this != &other) {
            delete[] data;
            size = other.size;
            data = new int[size];
            std::copy(other.data, other.data + size, data);
            std::cout << "Copy assignment: allocated " << size << " ints\n";
        }
        return *this;
    }
    
    // 移動賦值運算符
    Resource& operator=(Resource&& other) noexcept {
        if (this != &other) {
            delete[] data;  // 釋放當前資源
            
            // 轉移資源
            data = other.data;
            size = other.size;
            
            // 清空源物件
            other.data = nullptr;
            other.size = 0;
            
            std::cout << "Move assignment: transferred ownership\n";
        }
        return *this;
    }
    
    // 解構函式
    ~Resource() {
        if (data) {
            std::cout << "Destructor: deallocated " << size << " ints\n";
            delete[] data;
        } else {
            std::cout << "Destructor: nothing to deallocate\n";
        }
    }
    
    size_t get_size() const { return size; }
};
```

#### 1.5.3 常見陷阱與最佳實踐

```cpp
void move_pitfalls() {
    // ❌ 陷阱 1：對 const 物件使用 std::move
    const std::string const_str = "hello";
    // std::string moved = std::move(const_str);  // 實際上會拷貝，不會移動！
    
    // ❌ 陷阱 2：移動後繼續使用
    std::vector<int> v1 = {1, 2, 3};
    std::vector<int> v2 = std::move(v1);
    // std::cout << v1.size();  // 危險！v1 處於未指定狀態
    
    // ✅ 正確：移動後只能重新賦值或銷毀
    v1 = {4, 5, 6};  // OK：重新賦值
    std::cout << "v1 size after reassignment: " << v1.size() << "\n";
    
    // ❌ 陷阱 3：不必要的 std::move
    auto create_string_bad = []() {
        std::string local = "hello";
        return std::move(local);  // 不必要！RVO 或 NRVO 更好
    };
    
    // ✅ 正確：讓編譯器優化
    auto create_string_good = []() {
        std::string local = "hello";
        return local;  // 編譯器會自動使用移動或 RVO
    };
}

// ✅ 最佳實踐：移動建構函式應該是 noexcept
class GoodClass {
public:
    GoodClass(GoodClass&& other) noexcept {
        // 移動操作不應該拋出異常
    }
    
    GoodClass& operator=(GoodClass&& other) noexcept {
        return *this;
    }
};
```

**好處**:
- **性能**: 避免昂貴的深拷貝，特別是大型容器和字串，性能提升可達數百倍
- **記憶體效率**: 減少暫時物件的記憶體分配，降低記憶體使用峰值
- **RAII**: 完美轉發資源擁有權，實現零開銷的資源管理
- **STL 優化**: 容器操作性能顯著提升，特別是 `push_back`, `insert` 等操作
- **函數返回**: 大物件的函數返回變得高效，無需擔心拷貝開銷

**缺點**:
- **複雜性**: 增加類設計複雜度，需要實作移動建構函式和移動賦值運算符
- **語義陷阱**: `std::move` 後原物件處於未指定狀態，容易產生 bug
- **調試困難**: 移動語義錯誤較難追蹤，特別是資源管理錯誤
- **學習曲線**: 理解右值引用、完美轉發等概念需要時間
- **維護負擔**: Rule of Five 增加了需要維護的特殊成員函數數量

### 1.6 Lambda 表達式

```cpp
// Lambda
auto f = [](int x) { return x * 2; };
int result = f(5);  // 10

// 捕獲
int offset = 10;
auto add_offset = [offset](int x) { return x + offset; };

// 與 STL 結合
std::vector<int> vec = {5, 2, 8, 1};
std::sort(vec.begin(), vec.end(),
    [](int a, int b) { return a < b; });
```

**好處**:
- **簡潔性**: 減少小函數的定義,代碼更緊湊
- **局部性**: 邏輯就近定義,增強可讀性
- **STL 整合**: 與演算法完美結合
- **性能**: 通常會被內聯,無函數調用開銷
- **閉包**: 方便捕獲局部變數

**缺點**:
- **調試困難**: 某些調試器對 lambda 支持不佳
- **捕獲陷阱**: 引用捕獲可能導致懸空引用
- **可讀性**: 複雜 lambda 可能降低可讀性
- **編譯時間**: 大量使用可能增加編譯時間

### 1.7 智能指針

```cpp
// unique_ptr
auto p1 = std::unique_ptr<int>(new int(42));  // C++11

// shared_ptr
auto p2 = std::make_shared<int>(42);

// weak_ptr
std::weak_ptr<int> weak = p2;
```

**好處**:
- **記憶體安全**: 自動管理記憶體,防止洩漏
- **異常安全**: RAII 保證異常時也能正確清理
- **所有權語義**: 明確表達資源擁有關係
- **零開銷**: `unique_ptr` 與原始指針性能相同

**缺點**:
- **shared_ptr 開銷**: 引用計數有原子操作成本
- **循環引用**: `shared_ptr` 可能造成記憶體洩漏
- **學習成本**: 需要理解不同智能指針的使用時機
- **調試複雜**: 智能指針層次可能增加調試難度

## 2. C++14 特性

### 2.1 make_unique

```cpp
// C++14 添加 make_unique
auto p = std::make_unique<int>(42);
auto arr = std::make_unique<int[]>(10);
```

**好處**:
- **異常安全**: 避免 `new` 與智能指針分離造成的記憶體洩漏
- **簡潔性**: 語法更簡潔,類型推導自動化
- **一致性**: 與 `make_shared` 保持一致的命名風格
- **性能**: 無額外開銷,編譯器通常會優化

**缺點**:
- **自定義刪除器**: 無法直接指定自定義刪除器
- **初始化語法**: 某些初始化語法可能不如直接建構清晰

### 2.2 泛型 Lambda

```cpp
// auto 參數
auto print = [](const auto& x) {
    std::cout << x << "\n";
};

print(42);
print(3.14);
print("Hello");
```

**好處**:
- **重用性**: 一個 lambda 處理多種類型
- **簡潔性**: 避免寫多個類似的 lambda
- **性能**: 編譯期展開,無運行時多型開銷
- **靈活性**: 結合模板元編程技術

**缺點**:
- **錯誤訊息**: 類型推導錯誤時,錯誤訊息可能複雜
- **調試困難**: 泛型實例化增加調試複雜度
- **編譯時間**: 可能增加編譯時間

### 2.3 返回類型推導

```cpp
// 自動推導返回類型
auto add(int a, int b) {
    return a + b;  // 推導為 int

// 複雜返回類型

```

**好處**:
- **簡化聲明**: 複雜返回類型無需手動指定
- **維護性**: 實作改變時返回類型自動更新
- **一致性**: 與變數的 `auto` 推導保持一致
- **性能**: 編譯期推導,無運行時開銷

**缺點**:
- **可讀性**: 函數簽名不夠明確,需要查看實作
- **接口變化**: 實作改變可能意外改變公共接口
- **模板錯誤**: 在模板中使用可能產生複雜錯誤訊息

### 2.4 數字分隔符

## 3. C++17 特性

### 3.1 結構化綁定

```cpp
// 結構化綁定
std::pair<int, std::string> p = {1, "one"};
```

**好處**:

- **簡潔性**: 避免 `.first`, `.second` 等存取
- **多返回值**: 優雅處理函數多返回值
- **性能**: 編譯期展開,無額外開銷

**缺點**:
- **編譯器支持**: 需要 C++17 支持
- **調試**: 某些調試器對結構化綁定支持有限
- **靈活性**: 必須綁定所有成員,無法選擇性忽略

### 3.2 if/switch 初始化

### 3.3 std::optional

```cpp
#include <optional>

// 可能失敗的操作
std::optional<int> parse_int(const std::string& str) {
    try {
        return std::stoi(str);
    } catch (...) {
        return std::nullopt;
    }
}

// 使用
if (auto result = parse_int("123"); result) {
    std::cout << "Value: " << *result << "\n";
```

**好處**:

- **函數式風格**: 支持 `map`, `and_then` 等操作

**缺點**:
- **記憶體開銷**: 額外的布爾標誌位
- **性能影響**: 頻繁檢查狀態可能有微小開銷
- **學習成本**: 需要理解 `optional` 的正確使用方式
- **兼容性**: C++17 以前版本不可用

### 3.4 std::variant

```cpp
#include <variant>

// 類型安全的 union
std::variant<int, double, std::string> v = 42;
v = 3.14;
v = "hello";

// 訪問
std::visit([](auto&& arg) {
    std::cout << arg << "\n";
}, v);

// 類型檢查
if (std::holds_alternative<int>(v)) {
    int x = std::get<int>(v);
}
```

**好處**:
- **類型安全**: 取代不安全的 C-style union
- **記憶體效率**: 只占用最大類型的空間
- **模式匹配**: `std::visit` 提供函數式處理方式
- **異常安全**: 訪問錯誤類型會拋出異常

**缺點**:
- **空間開銷**: 類型標誌空間占用

### 3.5 std::string_view

- **性能**: 只傳遞指針和長度,成本極低
- **子串操作**: 高效的子串視圖操作

**缺點**:
- **生命週期**: 必須確保原字符串在視圖使用期間有效
- **懸空指針**: 原字符串銷毀後視圖變為懸空
- **C 接口**: 不以 null 結尾,與 C API 交互需要轉換

## 4. C++20 特性

### 4.1 Concepts

Concepts 是 C++20 中最重要的特性之一，它為模板提供了約束和要求，讓模板程式設計更安全、更易讀。

#### 4.1.1 基本概念定義

```cpp
#include <concepts>
#include <type_traits>

// 基本概念定義
template<typename T>
concept Numeric = std::is_arithmetic_v<T>;

template<typename T>
concept Integral = std::is_integral_v<T>;

template<typename T>
concept FloatingPoint = std::is_floating_point_v<T>;

// 使用概念約束函數
template<Numeric T>
T add(T a, T b) {
    return a + b;
}

// 測試
add(1, 2);        // ✅ OK - int 滿足 Numeric
```

#### 4.1.9 性能考量與最佳實踐

```cpp
// ✅ 好的實踐：使用標準概念

// ⚠️ 避免：過於複雜的概念

concept BadComplexConcept = requires(T t) {
    // 避免太多複雜要求在一個概念中
    t.method1();
    t.method2();
    t.method3();
    typename T::nested_type1;
    typename T::nested_type2;
    // ... 太多要求
};

// ✅ 較好：分解為多個簡單概念

    t.method1();
    t.method2();
};

template<typename T>
concept HasNestedTypes = requires {
    typename T::nested_type1;
    typename T::nested_type2;
};
```

**好處**:
- **錯誤訊息**: 模板錯誤訊息更清晰易懂，直接指出不滿足的約束
- **接口文檔**: 概念作為活文檔，明確表達模板的要求和意圖
- **編譯加速**: 早期類型檢查，避免深層模板實例化，減少編譯時間
- **重載解析**: 更精確的函數重載選擇，避免歧義
- **代碼可讀性**: 模板約束直接在簽名中表達，無需深入實現
- **類型安全**: 編譯期保證類型滿足所有要求

**缺點**:
- **學習曲線**: 需要學習概念的定義語法和標準庫概念
- **編譯器支持**: 需要完整的 C++20 支持，舊編譯器不可用
- **複雜性**: 複雜概念的定義和組合可能很困難
- **編譯時間**: 概念檢查可能在某些情況下增加編譯時間
- **調試困難**: 概念約束失敗時的調試可能比較困難
- **標準化**: 某些領域特定的概念還沒有標準化

```cpp
    // ✅ 好的實踐：利用惰性求值
    auto efficient = large_dataset
        | views::filter([](int n) { return n % 2 == 0; })
        | views::take(10);  // 只需要 10 個，會盡早停止
    
    // ⚠️ 注意：某些操作可能不如手寫循環高效
    auto potentially_slow = large_dataset
        | views::reverse  // 可能需要隨機存取
        | views::filter([](int n) { return n % 1000 == 0; });
    
    // ✅ 更好：如果需要全部處理，考慮使用傳統演算法
    std::vector<int> result;
    for (auto it = large_dataset.rbegin(); it != large_dataset.rend(); ++it) {
        if (*it % 1000 == 0) {
            result.push_back(*it);
        }
    }
}

// 避免常見陷阱
void common_pitfalls() {
    std::vector<int> vec = {1, 2, 3, 4, 5};
    
    // ❌ 錯誤：懸空引用
    auto dangling_view = [&]() {
        std::vector<int> local_vec = {1, 2, 3};
        return local_vec | views::transform([](int x) { return x * 2; });
        // local_vec 銷毀，但視圖仍引用它！
    }();
    
    // ✅ 正確：確保底層數據的生命週期
    auto safe_view = vec | views::transform([](int x) { return x * 2; });
    
    // ❌ 錯誤：不必要的物化
    std::vector<int> materialized(safe_view.begin(), safe_view.end());
    for (int x : materialized) { /* ... */ }
    
    // ✅ 更好：直接使用視圖
    for (int x : safe_view) { /* ... */ }
}
```

**好處**:
- **函數式風格**: 鏈式操作讓數據處理管道清晰易讀
- **惰性求值**: 按需計算，節省記憶體和不必要的計算
- **組合性**: 視圖可以自由組合，創建複雜的處理管道
- **STL 整合**: 與現有 STL 容器和演算法完美配合
- **零開銷抽象**: 編譯器通常能優化為等價的手寫循環
- **記憶體效率**: 避免創建中間容器，流式處理數據

**缺點**:
- **學習曲線**: 函數式編程思維需要時間適應
- **調試困難**: 惰性求值使得調試和性能分析變困難
- **編譯器支持**: 需要 C++20 完整支持，某些編譯器可能有 bug
- **生命週期陷阱**: 視圖可能引用已銷毀的數據，需要仔細管理
- **性能變化**: 某些場景可能不如手寫循環高效，需要測試
- **編譯時間**: 複雜的範圍表達式可能增加編譯時間

### 4.5 三向比較 (Spaceship Operator)

三向比較運算符 `<=>` 是 C++20 引入的革命性特性，它可以用一個運算符實現所有六種比較操作（`<`, `<=`, `>`, `>=`, `==`, `!=`）。

#### 4.5.1 基本用法

```cpp
#include <compare>

struct Point {
    int x, y;

    // 自動生成所有比較運算符
    auto operator<=>(const Point&) const = default;
    
    // 注意：== 運算符需要單獨聲明或自動生成
    bool operator==(const Point&) const = default;
};

Point p1{1, 2};
Point p2{3, 4};
Point p3{1, 2};

// 自動支援所有比較操作
bool b1 = p1 < p2;   // true (按字典序比較)
bool b2 = p1 == p3;  // true
bool b3 = p1 != p2;  // true  
bool b4 = p1 <= p3;  // true
bool b5 = p2 > p1;   // true
bool b6 = p2 >= p1;  // true
```

#### 4.5.2 比較類別 (Comparison Categories)

`<=>` 運算符返回以下三種比較類別之一：

```cpp
#include <compare>

// 1. std::strong_ordering - 強排序（如整數）
struct StrongPoint {
    int x, y;
    
    std::strong_ordering operator<=>(const StrongPoint& other) const {
        if (auto cmp = x <=> other.x; cmp != 0) return cmp;
        return y <=> other.y;
    }
    
    bool operator==(const StrongPoint&) const = default;
};

// 2. std::weak_ordering - 弱排序（如大小寫不敏感字串）
struct WeakString {
    std::string value;
    
    std::weak_ordering operator<=>(const WeakString& other) const {
        // 大小寫不敏感比較
        std::string a = to_lower(value);
        std::string b = to_lower(other.value);
        return a <=> b;
    }
    
private:
    std::string to_lower(const std::string& s) const {
        std::string result = s;
        std::transform(result.begin(), result.end(), result.begin(), ::tolower);
        return result;
    }
};

// 3. std::partial_ordering - 偏序（如浮點數，有 NaN）
struct PartialFloat {
    double value;
    
    std::partial_ordering operator<=>(const PartialFloat& other) const {
        return value <=> other.value;
    }
    
    bool operator==(const PartialFloat&) const = default;
};
```

#### 4.5.3 手動實現三向比較

對於複雜類型，你可能需要手動實現比較邏輯：

```cpp
struct Person {
    std::string name;
    int age;
    double salary;

    // 手動實現：先按姓名，再按年齡，最後按薪資
    std::strong_ordering operator<=>(const Person& other) const {
        if (auto cmp = name <=> other.name; cmp != 0)
            return cmp;
        if (auto cmp = age <=> other.age; cmp != 0)
            return cmp;
        return salary <=> other.salary;
    }
    
    // 等號比較通常也需要手動實現
    bool operator==(const Person& other) const {
        return name == other.name && age == other.age && salary == other.salary;
    }
};

// 使用示例
Person p1{"Alice", 30, 50000.0};
Person p2{"Bob", 25, 45000.0};
Person p3{"Alice", 35, 60000.0};

std::vector<Person> people = {p3, p1, p2};
std::sort(people.begin(), people.end());  // 自動按定義的順序排序

// 結果：p2 (Bob), p1 (Alice, 30), p3 (Alice, 35)
```

#### 4.5.4 與容器的整合

#### 4.5.5 條件比較

```cpp
struct OptionalInt {
    std::optional<int> value;
    
    std::strong_ordering operator<=>(const OptionalInt& other) const {
        // 處理 optional 的比較
        if (!value && !other.value) return std::strong_ordering::equal;
        if (!value) return std::strong_ordering::less;    // null < any value
        if (!other.value) return std::strong_ordering::greater;
        return *value <=> *other.value;
    }
    
    bool operator==(const OptionalInt& other) const {
        if (!value && !other.value) return true;
        if (!value || !other.value) return false;
        return *value == *other.value;
    }
};
```

#### 4.5.6 性能考量與最佳實踐

```cpp
// ✅ 推薦：對於簡單類型使用 default
struct SimplePoint {
    int x, y;
    auto operator<=>(const SimplePoint&) const = default;
    bool operator==(const SimplePoint&) const = default;
};

// ✅ 推薦：手動實現時使用短路邏輯
struct OptimizedPerson {
    std::string name;
    int age;
    
    std::strong_ordering operator<=>(const OptimizedPerson& other) const {
        // 先比較便宜的操作（int）
        if (auto cmp = age <=> other.age; cmp != 0)
            return cmp;
        // 再比較昂貴的操作（string）
        return name <=> other.name;
    }
    
    bool operator==(const OptimizedPerson&) const = default;
};

// ⚠️ 注意：避免在熱路徑上進行昂貴的比較
struct ExpensiveComparison {
    std::vector<int> data;
    
    // 這種比較可能很昂貴
    std::strong_ordering operator<=>(const ExpensiveComparison& other) const {
        return data <=> other.data;  // 逐元素比較
    }
};
```

#### 4.5.7 常見陷阱與錯誤

```cpp
// ❌ 錯誤：忘記實現 == 運算符
struct BadExample1 {
    int value;
    auto operator<=>(const BadExample1&) const = default;
    // 缺少 operator== 會導致編譯錯誤
};

// ❌ 錯誤：不一致的比較邏輯
struct BadExample2 {
    int a, b;
    
    std::strong_ordering operator<=>(const BadExample2& other) const {
        return a <=> other.a;  // 只比較 a
    }
    
    bool operator==(const BadExample2& other) const {
        return a == other.a && b == other.b;  // 但 == 比較兩個欄位
    }
    // 這會導致 (x == y) 與 (x <=> y == 0) 不一致！
};

// ✅ 正確：保持一致性
struct GoodExample {
    int a, b;
    
    std::strong_ordering operator<=>(const GoodExample& other) const {
        if (auto cmp = a <=> other.a; cmp != 0) return cmp;
        return b <=> other.b;
    }
    
    bool operator==(const GoodExample& other) const {
        return a == other.a && b == other.b;
    }
};
```

#### 4.5.8 與舊代碼的相容性

```cpp
// C++20 之前的代碼
struct LegacyClass {
    int value;
    
    bool operator<(const LegacyClass& other) const {
        return value < other.value;
    }
    
    bool operator==(const LegacyClass& other) const {
        return value == other.value;
    }
    // ... 需要定義所有六個運算符
};

// C++20 簡化版本
struct ModernClass {
    int value;
    
    auto operator<=>(const ModernClass&) const = default;
    bool operator==(const ModernClass&) const = default;
    // 自動獲得所有六個運算符
};

// 混合使用時的注意事項
void compatibility_example() {
    LegacyClass legacy{10};
    ModernClass modern{10};
    
    // ❌ 這會編譯錯誤，因為沒有跨類型比較
    // bool result = legacy < modern;
    
    // ✅ 需要顯式轉換或提供跨類型比較運算符
    bool result = legacy.value < modern.value;
}
```

**好處**:
- **代碼簡化**: 一個運算符生成六個比較操作，減少 80% 的樣板代碼
- **一致性保證**: 自動確保所有比較運算符的邏輯一致性
- **性能優化**: 編譯器可以針對三向比較進行優化
- **標準庫整合**: 與 `std::sort`, `std::set`, `std::map` 等無縫配合
- **類型安全**: 比較類別提供更精確的語義表達

**缺點**:
- **學習曲線**: 需要理解三種比較類別的區別和使用時機
- **調試困難**: 自動生成的運算符在調試時較難跟蹤
- **編譯錯誤**: 複雜類型的自動生成可能失敗，需要手動實現
- **向後相容**: 與舊代碼混用時需要額外注意
- **編譯器支持**: 需要完整的 C++20 支持，某些編譯器實現可能有 bug

### 4.6 Coroutines

```cpp
#include <coroutine>

// 協程 (簡化示例)
generator<int> fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;
        auto temp = a;
        a = b;
        b = temp + b;
    }
```

- **複雜性**: 概念複雜,學習成本高
- **調試困難**: 協程狀態機難以調試
- **性能開銷**: 狀態保存和恢復有開銷

**C++14**:

- ✅ `make_unique` - 異常安全
- ✅ 泛型 Lambda - 更靈活
- ✅ 數字分隔符 - 提高可讀性

**C++17**:

- ✅ 結構化綁定 - 簡化代碼
- ✅ `std::optional` - 取代錯誤碼
- ✅ `std::string_view` - 零拷貝

**C++20**:

- ✅ Concepts - 更好的模板約束

### 5.2 高頻交易與性能敏感場景推薦

**零開銷抽象 (Zero Overhead)**:
```cpp
// ✅ 強烈推薦 - 零運行時成本
auto price = calculate_price();      // auto 類型推導
for (const auto& order : orders) {}  // 範圍 for
constexpr int MAX_SIZE = 1000;      // constexpr 常數
std::unique_ptr<Order> order;       // unique_ptr
std::string_view symbol;            // string_view (無拷貝)
if constexpr (condition) {}         // 編譯期分支
```

**微小開銷但值得使用**:
```cpp
// ✅ 推薦使用 - 開銷極小
std::optional<Price> price;         // 1 byte 標誌位
std::span<int> data;               // 只有指針+大小
Lambda 表達式;                      // 通常被內聯
結構化綁定 auto [a, b] = pair;      // 編譯期展開
```

**需要測量的特性**:
```cpp
// ⚠️ 謹慎使用 - 需要性能測試
std::shared_ptr<Data> data;        // 原子引用計數
std::variant<A, B> obj;            // 類型標誌+間接訪問
std::visit(visitor, variant);      // 跳轉表
Ranges 管道操作;                    // 可能產生額外間接層
std::function<void()> callback;    // 類型擦除+堆分配風險
```

**高成本特性**:
```cpp
// ❌ 熱路徑避免使用
try { } catch { }                  // 異常處理開銷
dynamic_cast<T*>(ptr);             // RTTI 查找
協程 (Coroutines);                  // 狀態機+記憶體分配
std::regex operations;             // 正則表達式編譯
```

### 5.3 性能特性分析

**編譯期特性 (零運行時開銷)**:
- `auto` 類型推導 - 純編譯期,零開銷
- `constexpr` / `consteval` - 編譯期計算
- `constexpr if` - 編譯期分支選擇
- 範圍 for 循環 - 優化為普通循環
- Lambda 表達式 - 通常完全內聯
- `static_assert` - 編譯期檢查

**記憶體效率特性**:
- `std::string_view` - 只有指針+長度 (16 bytes)
- `std::span` - 只有指針+大小 (16 bytes)  
- `std::unique_ptr` - 只有指針大小 (8 bytes)
- 移動語義 - 避免深拷貝,只轉移資源
- 結構化綁定 - 編譯期展開,無額外儲存

**有開銷但合理的特性**:
- `std::optional<T>` - sizeof(T) + 1 byte 標誌
- `std::shared_ptr<T>` - 8 bytes + 控制塊 (原子計數)
- `std::variant<T...>` - max(sizeof(T...)) + 類型標誌
- Concepts - 編譯期檢查,可能增加編譯時間

**高開銷特性**:
- `std::function` - 類型擦除,可能堆分配
- `std::visit` - 虛擬調用或跳轉表
- 異常處理 - 堆疊展開和清理成本
- RTTI (`dynamic_cast`) - 類型信息查找
