## 核心概念

### 網路延遲的組成

```
端到端延遲 (End-to-End Latency):
┌─────────────────────────────────────────────────────────┐
│ 應用層延遲                                              │
│  ├─ 系統調用開銷: ~300-500 ns                           │
│  ├─ 上下文切換: ~500-1000 ns                            │
│  └─ 記憶體拷貝: ~100-500 ns                             │
├─────────────────────────────────────────────────────────┤
│ 內核網路棧延遲                                          │
│  ├─ 中斷處理: ~1-2 μs                                   │
│  ├─ TCP/IP 處理: ~1-3 μs                                │
│  └─ 佇列延遲: ~0.5-5 μs                                 │
├─────────────────────────────────────────────────────────┤
│ 硬體延遲                                                │
│  ├─ NIC 處理: ~0.5-1 μs                                 │
│  ├─ DMA 傳輸: ~100-300 ns                               │
│  └─ 網路傳輸: ~10-100 μs (取決於距離)                   │
└─────────────────────────────────────────────────────────┘

HFT 目標: 將應用層+內核延遲降至 < 5 μs
```

### 調校原則

1. **測量優先**: 先測量,再優化
2. **系統化**: 從硬體→內核→應用逐層優化
3. **權衡**: 延遲 vs 吞吐量 vs CPU 使用率
4. **驗證**: 每次調整後重新測量

## 系統層級調校

### 1. 中斷親和性 (IRQ Affinity)

**問題**: 網卡中斷在多個 CPU 間遷移,導致 Cache Miss 與延遲抖動。

**解決方案**: 將網卡中斷綁定到特定 CPU。

```bash
# 檢視網卡中斷號
cat /proc/interrupts | grep eth0
# 125:   1234567      0 IR-PCI-MSI 524288-edge      eth0-TxRx-0
# 126:   9876543      0 IR-PCI-MSI 524289-edge      eth0-TxRx-1

# 方法 1: 使用 smp_affinity (bitmask)
# 綁定 IRQ 125 到 CPU 0 (bitmask: 0x1)
echo 1 > /proc/irq/125/smp_affinity

# 綁定 IRQ 126 到 CPU 1 (bitmask: 0x2)
echo 2 > /proc/irq/126/smp_affinity

# 方法 2: 使用 irqbalance 停用自動平衡
systemctl stop irqbalance
systemctl disable irqbalance

# 方法 3: 使用 Intel set_irq_affinity 腳本
wget https://raw.githubusercontent.com/intel/networking-recipe/master/scripts/set_irq_affinity.sh
chmod +x set_irq_affinity.sh
./set_irq_affinity.sh 0-3 eth0  # 綁定到 CPU 0-3
```

**程式碼範例**: 應用程式綁定到相同 CPU

```cpp
#include <sched.h>
#include <pthread.h>

// 將當前程序綁定到特定 CPU
void pin_to_cpu(int cpu_id) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(cpu_id, &cpuset);
    
    if (sched_setaffinity(0, sizeof(cpuset), &cpuset) < 0) {
        throw std::runtime_error("sched_setaffinity() failed");
    }
}

// 將執行緒綁定到特定 CPU
void pin_thread_to_cpu(pthread_t thread, int cpu_id) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(cpu_id, &cpuset);
    
    if (pthread_setaffinity_np(thread, sizeof(cpuset), &cpuset) < 0) {
        throw std::runtime_error("pthread_setaffinity_np() failed");
    }
}

// HFT 應用: 網路處理執行緒綁定到 CPU 0
void network_thread() {
    pin_to_cpu(0);  // 與網卡中斷相同 CPU
    
    // 網路處理邏輯...
}
```

### 2. CPU 頻率與省電模式

**問題**: CPU 動態調頻與省電狀態 (C-States) 導致延遲抖動。

```bash
# 檢視當前 CPU 頻率調節器
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
# powersave (省電模式,頻率動態調整)

# 設定為 performance (固定最高頻率)
echo performance | tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor

# 驗證
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
# 3600000 (3.6 GHz)

# 停用 Intel Turbo Boost (可選,降低頻率抖動)
echo 1 > /sys/devices/system/cpu/intel_pstate/no_turbo

# 停用 C-States (省電狀態)
cpupower idle-set -D 0  # 停用深度睡眠

# 或在 GRUB 中永久停用
# /etc/default/grub:
# GRUB_CMDLINE_LINUX="intel_idle.max_cstate=0 processor.max_cstate=1"
```

**效能影響**:
- 延遲降低: ~20-50%
- 抖動降低: ~70-90%
- 功耗增加: ~30-50%

### 3. NUMA 配置

**問題**: 跨 NUMA 節點記憶體存取延遲高 (~100-200 ns extra)。

```bash
# 檢視 NUMA 拓樸
numactl --hardware
# available: 2 nodes (0-1)
# node 0 cpus: 0 1 2 3
# node 1 cpus: 4 5 6 7
# node 0 size: 32768 MB
# node 1 size: 32768 MB

# 將程序綁定到特定 NUMA 節點
numactl --cpunodebind=0 --membind=0 ./my_hft_app

# 檢視 NUMA 統計 (檢測跨節點存取)
numastat -p $(pidof my_hft_app)
# node0    node1
# numa_hit        1234567  100
# numa_miss       50       9876543  ← 跨節點存取 (應最小化)
```

**程式碼範例**: NUMA-aware 記憶體分配

```cpp
#include <numa.h>
#include <sched.h>

// 分配 NUMA 本地記憶體
void* allocate_numa_local_memory(size_t size) {
    if (numa_available() < 0) {
        throw std::runtime_error("NUMA not available");
    }
    
    // 取得當前執行的 CPU 和 NUMA 節點
    int cpu = sched_getcpu();
    int node = numa_node_of_cpu(cpu);
    
    // 分配本地記憶體
    return numa_alloc_onnode(size, node);
}

// 使用範例
class NUMAAwareBuffer {
    void* buffer_;
    size_t size_;
    
public:
    explicit NUMAAwareBuffer(size_t size) : size_(size) {
        buffer_ = allocate_numa_local_memory(size);
    }
    
    ~NUMAAwareBuffer() {
        numa_free(buffer_, size_);
    }
    
    void* data() { return buffer_; }
};

// HFT 應用
void numa_aware_network_handler() {
    pin_to_cpu(0);  // 綁定到 NUMA node 0 的 CPU
    
    NUMAAwareBuffer rx_buffer(1024 * 1024);  // 1 MB 接收緩衝區
    
    // 網路處理 (所有記憶體存取都在本地 NUMA 節點)
}
```

## 網路協定棧調校

### 1. TCP 參數優化

```bash
# /etc/sysctl.conf 或 sysctl -w

# ===== TCP 緩衝區大小 =====
net.core.rmem_max = 134217728           # 接收緩衝區最大值: 128 MB
net.core.wmem_max = 134217728           # 發送緩衝區最大值: 128 MB
net.ipv4.tcp_rmem = 4096 87380 67108864  # TCP 接收緩衝區: min default max
net.ipv4.tcp_wmem = 4096 65536 67108864  # TCP 發送緩衝區: min default max

# ===== TCP 擁塞控制 =====
net.ipv4.tcp_congestion_control = bbr    # BBR 演算法 (低延遲)
# 或 cubic (傳統)

# ===== TCP Fast Open (TFO) =====
net.ipv4.tcp_fastopen = 3                # Client (1) + Server (2) = 3
# 減少 1 RTT 建立連線時間

# ===== TCP Timestamps =====
net.ipv4.tcp_timestamps = 0              # 停用 (降低 12 bytes overhead)
# HFT 場景可停用,但會影響 RTT 估計

# ===== TCP SACK (選擇性確認) =====
net.ipv4.tcp_sack = 1                    # 啟用 (提升重傳效率)

# ===== 連線追蹤表大小 =====
net.netfilter.nf_conntrack_max = 1000000 # 高並發必須增大

# ===== SYN Backlog =====
net.ipv4.tcp_max_syn_backlog = 8192      # 增大 SYN 佇列

# ===== 本地埠範圍 =====
net.ipv4.ip_local_port_range = 10000 65535  # 擴大可用埠

# ===== TIME_WAIT Socket 重用 =====
net.ipv4.tcp_tw_reuse = 1                # 允許 TIME_WAIT 重用 (Client)
# 注意: tcp_tw_recycle 已廢棄,不要使用!

# ===== FIN Timeout =====
net.ipv4.tcp_fin_timeout = 15            # 降低 FIN_WAIT_2 超時 (預設 60s)

# 應用設定
sysctl -p
```

**HFT 專用配置**:

```bash
# 極低延遲配置
net.ipv4.tcp_low_latency = 1             # 優先低延遲而非吞吐量
net.ipv4.tcp_no_metrics_save = 1         # 不保存連線指標 (減少處理)
```

### 3. Socket 緩衝區動態調整

```cpp
#include <sys/socket.h>
#include <iostream>

void optimize_socket_buffer(int sockfd) {
    // 讀取當前緩衝區大小
    int current_size;
    socklen_t len = sizeof(current_size);
    getsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &current_size, &len);
    
    std::cout << "Current RX buffer: " << current_size << " bytes\n";
    
    // 設定更大的緩衝區
    int new_size = 16 * 1024 * 1024;  // 16 MB
    if (setsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &new_size, sizeof(new_size)) < 0) {
        perror("setsockopt(SO_RCVBUF)");
    }
    
    // 驗證實際大小 (內核可能調整為 2 倍)
    getsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &current_size, &len);
    std::cout << "New RX buffer: " << current_size << " bytes\n";
    // 輸出: New RX buffer: 33554432 bytes (32 MB)
}

// HFT 應用: TCP 連線優化
void optimize_tcp_for_hft(int sockfd) {
    int optval;
    
    // 1. TCP_NODELAY: 禁用 Nagle 演算法
    optval = 1;
    setsockopt(sockfd, IPPROTO_TCP, TCP_NODELAY, &optval, sizeof(optval));
    
    // 2. TCP_QUICKACK: 快速 ACK (降低延遲)
    optval = 1;
    setsockopt(sockfd, IPPROTO_TCP, TCP_QUICKACK, &optval, sizeof(optval));
    
    // 3. 增大緩衝區
    optval = 2 * 1024 * 1024;  // 2 MB
    setsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &optval, sizeof(optval));
    setsockopt(sockfd, SOL_SOCKET, SO_SNDBUF, &optval, sizeof(optval));
}
```

## NIC 硬體調校

### 1. Ring Buffer 大小

**問題**: Ring Buffer 太小導致封包丟失。

```bash
# 檢視當前 ring buffer 大小
ethtool -g eth0
# Ring parameters for eth0:
# Pre-set maximums:
# RX:         4096
# TX:         4096
# Current hardware settings:
# RX:         512   ← 太小
# TX:         512

# 設定最大 ring buffer
ethtool -G eth0 rx 4096 tx 4096

# 驗證
ethtool -g eth0
```

**注意**: 增大 Ring Buffer 會增加延遲 (~1-2 μs),需權衡丟包率與延遲。

### 2. 中斷合併 (Interrupt Coalescing)

**問題**: 過度中斷合併增加延遲;不合併則 CPU 中斷過多。

```bash
# 檢視當前中斷合併設定
ethtool -c eth0
# Coalesce parameters for eth0:
# rx-usecs: 30        ← 接收 30 μs 後才中斷
# tx-usecs: 30

# HFT 場景: 降低延遲,減少中斷合併
ethtool -C eth0 rx-usecs 0 tx-usecs 0

# 或完全停用自適應中斷合併
ethtool -C eth0 adaptive-rx off adaptive-tx off rx-usecs 0 tx-usecs 0
```

**權衡**:
- `rx-usecs = 0`: 最低延遲,但 CPU 中斷頻繁
- `rx-usecs = 30`: 降低 CPU 使用率,但延遲增加 ~30 μs

### 3. RSS (Receive Side Scaling)

**問題**: 單 CPU 處理所有接收封包,成為瓶頸。

```bash
# 啟用 RSS (多佇列網卡)
ethtool -L eth0 combined 4  # 4 個 RX/TX 佇列

# 檢視 RSS 配置
ethtool -x eth0
# RSS hash function:
#     toeplitz: on
# RSS indirection table: ...

# 配置 RSS Hash Key (可選)
ethtool -X eth0 hfunc toeplitz hkey <hash_key>
```

**效能提升**:
- 單佇列: ~2 Mpps
- 4 佇列: ~8 Mpps (接近線性擴展)

### 4. TSO/GSO/GRO 調整

**問題**: Offload 功能增加延遲 (~5-10 μs)。

```bash
# 檢視 offload 功能
ethtool -k eth0 | grep offload
# tcp-segmentation-offload: on
# generic-segmentation-offload: on
# generic-receive-offload: on

# HFT 場景: 停用 offload (降低延遲)
ethtool -K eth0 tso off gso off gro off

# 或僅停用 GRO (最大影響延遲)
ethtool -K eth0 gro off
```

**延遲影響**:
- TSO/GSO/GRO on: 延遲 +5-10 μs
- 全部 off: 延遲 -5-10 μs,但 CPU 使用率 +20-30%

### 5. Flow Director (Flow Steering)

**問題**: 需要將特定流量導向特定 CPU。

```bash
# 將特定 TCP 流導向 Queue 0 (CPU 0)
ethtool -N eth0 flow-type tcp4 src-ip 192.168.1.100 dst-port 8080 action 0

# 檢視 Flow Director 規則
ethtool -n eth0
# Total 1 rules
# Filter: 0
#     Rule Type: TCP over IPv4
#     Src IP addr: 192.168.1.100 mask: 0.0.0.0
#     Dest IP addr: 0.0.0.0 mask: 255.255.255.255
#     TOS: 0x0 mask: 0xff
#     Src port: 0 mask: 0xffff
#     Dest port: 8080 mask: 0x0
#     Action: Direct to queue 0
```

## 低延遲監控

### 1. 硬體時間戳

```cpp
#include <linux/net_tstamp.h>
#include <linux/sockios.h>
#include <sys/socket.h>

// 啟用硬體時間戳
void enable_hardware_timestamp(int sockfd) {
    int flags = SOF_TIMESTAMPING_RX_HARDWARE | 
                SOF_TIMESTAMPING_TX_HARDWARE |
                SOF_TIMESTAMPING_RAW_HARDWARE;
    
    if (setsockopt(sockfd, SOL_SOCKET, SO_TIMESTAMPING, &flags, sizeof(flags)) < 0) {
        throw std::runtime_error("setsockopt(SO_TIMESTAMPING) failed");
    }
}

// 接收並讀取硬體時間戳
void recv_with_hardware_timestamp(int sockfd) {
    char buffer[2048];
    char control[1024];
    
    iovec iov{};
    iov.iov_base = buffer;
    iov.iov_len = sizeof(buffer);
    
    msghdr msg{};
    msg.msg_iov = &iov;
    msg.msg_iovlen = 1;
    msg.msg_control = control;
    msg.msg_controllen = sizeof(control);
    
    ssize_t n = recvmsg(sockfd, &msg, 0);
    
    if (n > 0) {
        // 解析控制訊息中的時間戳
        for (cmsghdr* cmsg = CMSG_FIRSTHDR(&msg); cmsg; cmsg = CMSG_NXTHDR(&msg, cmsg)) {
            if (cmsg->cmsg_level == SOL_SOCKET && 
                cmsg->cmsg_type == SO_TIMESTAMPING) {
                
                timespec* ts = (timespec*)CMSG_DATA(cmsg);
                
                // ts[0]: 軟體時間戳
                // ts[1]: (未使用)
                // ts[2]: 硬體時間戳 (網卡記錄)
                printf("Hardware RX timestamp: %ld.%09ld\n", 
                       ts[2].tv_sec, ts[2].tv_nsec);
            }
        }
    }
}
```

### 2. 延遲統計追蹤

```cpp
#include <chrono>
#include <vector>
#include <algorithm>
#include <cstdint>

class LatencyTracker {
    std::vector<uint64_t> latencies_;
    
public:
    void record(uint64_t latency_ns) {
        latencies_.push_back(latency_ns);
    }
    
    void print_statistics() {
        if (latencies_.empty()) return;
        
        std::sort(latencies_.begin(), latencies_.end());
        
        size_t count = latencies_.size();
        uint64_t min = latencies_.front();
        uint64_t max = latencies_.back();
        uint64_t median = latencies_[count / 2];
        uint64_t p99 = latencies_[count * 99 / 100];
        uint64_t p999 = latencies_[count * 999 / 1000];
        
        uint64_t sum = 0;
        for (auto lat : latencies_) {
            sum += lat;
        }
        uint64_t avg = sum / count;
        
        printf("Latency Statistics (ns):\n");
        printf("  Count:  %zu\n", count);
        printf("  Min:    %lu\n", min);
        printf("  Avg:    %lu\n", avg);
        printf("  Median: %lu\n", median);
        printf("  P99:    %lu\n", p99);
        printf("  P99.9:  %lu\n", p999);
        printf("  Max:    %lu\n", max);
    }
    
    void reset() {
        latencies_.clear();
    }
};

// 測量 RTT (Round-Trip Time)
void measure_rtt_example(int sockfd) {
    LatencyTracker tracker;
    char buffer[64] = "PING";
    
    for (int i = 0; i < 10000; ++i) {
        auto start = std::chrono::high_resolution_clock::now();
        
        send(sockfd, buffer, sizeof(buffer), 0);
        recv(sockfd, buffer, sizeof(buffer), 0);
        
        auto end = std::chrono::high_resolution_clock::now();
        auto latency = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start).count();
        
        tracker.record(latency);
    }
    
    tracker.print_statistics();
    // 輸出範例:
    // Latency Statistics (ns):
    //   Count:  10000
    //   Min:    2340
    //   Avg:    3567
    //   Median: 3421
    //   P99:    5678
    //   P99.9:  8901
    //   Max:    12345
}
```

## 效能瓶頸診斷

### 1. 高 CPU 使用率

```bash
# 1. 檢視 CPU 使用 (按執行緒)
top -H -p $(pidof my_app)

# 2. 檢視系統調用統計
strace -c -p $(pidof my_app)
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- ----------------
#  45.23    0.123456          12     10000           epoll_wait
#  30.12    0.082345           8     10000           recvfrom
#  ...

# 3. CPU Profiling
perf record -g -p $(pidof my_app) -- sleep 10
perf report
```

**常見原因與解決方案**:
- **過多系統調用**: 使用批次 I/O (io_uring, DPDK)
- **Lock Contention**: 使用 Lock-free 資料結構
- **Context Switch**: CPU 綁定 (taskset, isolcpus)

### 2. UDP 丟包

```bash
# 1. 檢視 UDP 丟包統計
netstat -su | grep -E "packet receive errors|receive buffer errors"
#     123 packet receive errors        ← 應用層丟包
#     456 receive buffer errors        ← 內核緩衝區滿

# 2. 檢視網卡 Ring Buffer 丟包
ethtool -S eth0 | grep rx_dropped
#      rx_dropped: 789                 ← 硬體丟包

# 3. 檢視 Socket Buffer Overflow
ss -u -m
# State    Recv-Q Send-Q Local Address:Port
# UNCONN   0      0      *:9000
#          skmem:(r0,rb212992,t0,tb212992,f0,w0,o0,bl0)
#                 ^^^^^^^^^^  ← 接收緩衝區大小
```

**解決方案**:
```bash
# 增大 UDP 接收緩衝區
sysctl -w net.core.rmem_max=33554432

# 增大 Ring Buffer
ethtool -G eth0 rx 4096

# 應用層:
int optval = 16 * 1024 * 1024;
setsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &optval, sizeof(optval));
```

### 3. TCP 重傳

```bash
# 檢視 TCP 重傳統計
netstat -s | grep retransmit
#     1234 segments retransmitted      ← 重傳封包數

# 實時監控重傳
watch -n 1 'netstat -s | grep retransmit'

# 使用 ss 檢視特定連線的重傳
ss -ti dst 192.168.1.100
#         cubic wscale:7,7 rto:204 rtt:0.5/0.25 ato:40 mss:1448 rcvmss:536
#         send 123Mbps lastsnd:12 lastrcv:12 lastack:12 pacing_rate 246Mbps
#         retrans:0/10 ← 當前重傳/總重傳
```

**常見原因**:
- 網路擁塞: 調整 TCP 擁塞控制 (BBR)
- 封包亂序: 檢查網路設備
- 緩衝區不足: 增大 TCP buffer

## HFT 最佳實踐

### 完整調校清單

#### 硬體層級
- [ ] 網卡中斷綁定到特定 CPU
- [ ] CPU 設定為 performance 模式
- [ ] 停用 C-States (避免延遲抖動)
- [ ] 應用程式綁定到特定 CPU
- [ ] NUMA-aware 記憶體分配
- [ ] 使用高效能網卡 (10GbE/25GbE/100GbE)
- [ ] 配置 SR-IOV (虛擬化環境)

#### 網卡層級
- [ ] 增大 Ring Buffer 大小 (4096)
- [ ] 降低或停用中斷合併 (rx-usecs=0)
- [ ] 啟用 RSS (多佇列)
- [ ] 配置 Flow Director (流量導向)
- [ ] 停用 TSO/GSO/GRO (極低延遲場景)
- [ ] 啟用硬體時間戳

#### 協定棧層級
- [ ] 增大 TCP/UDP 緩衝區
- [ ] TCP 禁用 Nagle 演算法 (`TCP_NODELAY`)
- [ ] TCP 啟用 Quick ACK
- [ ] 調整 TCP 擁塞控制 (BBR/CUBIC)
- [ ] UDP 增大接收緩衝區 (32 MB)
- [ ] 調整本地埠範圍 (10000-65535)

#### 應用層級
- [ ] 使用 epoll/io_uring (避免 select/poll)

- [ ] 批次處理 I/O (減少系統調用)
- [ ] 使用 Lock-Free 資料結構
- [ ] 零拷貝技術 (sendfile, MSG_ZEROCOPY)
- [ ] 考慮內核旁路 (DPDK, AF_XDP)

#### 監控層級
- [ ] 記錄延遲統計 (P50/P99/P999)
- [ ] 監控 UDP 丟包率 (< 0.1%)
- [ ] 監控 TCP 重傳率 (< 0.5%)
- [ ] 監控 CPU 使用率
- [ ] 監控 Context Switch 次數
- [ ] 使用硬體時間戳測量延遲

### HFT 系統架構範例

```cpp
// HFT 網路處理執行緒 (完整調校)
class HFTNetworkHandler {
public:
    HFTNetworkHandler() {
        // 1. CPU 綁定
        pin_to_cpu(0);
        
        // 2. 建立 Socket
        sockfd_ = socket(AF_INET, SOCK_DGRAM, 0);
        
        // 3. 優化 Socket
        optimize_udp_socket(sockfd_);
        
        // 4. 啟用硬體時間戳
        enable_hardware_timestamp(sockfd_);
        
        // 5. 分配 NUMA 本地記憶體
        buffer_ = allocate_numa_local_memory(16 * 1024 * 1024);
    }
    
private:
    void optimize_udp_socket(int sockfd) {
        // 增大接收緩衝區
        int optval = 16 * 1024 * 1024;
        setsockopt(sockfd, SOL_SOCKET, SO_RCVBUF, &optval, sizeof(optval));
        
        // 設定 TOS (Type of Service) - 最低延遲
        optval = IPTOS_LOWDELAY;
        setsockopt(sockfd, IPPROTO_IP, IP_TOS, &optval, sizeof(optval));
        
        // 非阻塞模式
        int flags = fcntl(sockfd, F_GETFL, 0);
        fcntl(sockfd, F_SETFL, flags | O_NONBLOCK);
    }
    
    int sockfd_;
    void* buffer_;
};
```
