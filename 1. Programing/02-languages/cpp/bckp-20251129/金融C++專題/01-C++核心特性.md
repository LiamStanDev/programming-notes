## 1. 未定義行為 (UB) 防範手冊

### 1.1 什麼是未定義行為?

**未定義行為 (Undefined Behavior, UB)** 是 C++ 規範中故意不定義的行為,編譯器可以做任何事情,包括:
- 程式崩潰
- 產生錯誤結果
- **看似正常工作,但在優化後失效**

⚠️ **核心危險**: 編譯器假設你的代碼沒有 UB,並基於此進行激進優化。

### 1.2 常見 UB 列表與防範

#### 1.2.1 有符號整數溢位

```cpp
// ❌ UB: 有符號整數溢位
int x = INT_MAX;
int y = x + 1;  // UB!

// ❌ 溢位檢查可能被優化掉
if (x + 1 > x) {  // 編譯器可能認為這永遠為真!
    // ...
}

// ✅ 正確: 檢查前先判斷
if (x > INT_MAX - 1) {
    // 處理溢位
}

// ✅ 或使用無符號型別 (環繞行為是定義的)
uint32_t u = UINT32_MAX;
u + 1;  // 定義為 0 (環繞)

// ✅ 使用固定寬度整數 (推薦)
#include <cstdint>
int64_t value = INT64_MAX;
```

#### 1.2.2 數組越界

```cpp
// ❌ UB: 數組越界
int arr[10];
arr[10] = 42;  // UB! 有效範圍是 0-9

// ❌ UB: 指針運算越界
int* p = arr + 11;  // UB!

// ✅ 正確: 使用 std::array (帶邊界檢查)
std::array<int, 10> arr;
arr.at(10);  // 拋出 std::out_of_range

// ✅ 斷言檢查 (Debug 模式)
assert(index < arr.size());
arr[index] = value;
```

#### 1.2.3 懸空指針/引用

```cpp
// ❌ UB: 返回局部變數引用
const int& dangerous() {
    int x = 42;
    return x;  // UB! x 在函數結束後銷毀
}

// ❌ UB: 使用已釋放的記憶體
int* p = new int(42);
delete p;
*p = 10;  // UB! Use-after-free

// ❌ UB: 迭代器失效
std::vector<int> vec = {1, 2, 3};
auto it = vec.begin();
vec.push_back(4);  // 可能重新分配
*it = 10;          // UB! it 已失效

// ✅ 正確: 使用智能指針
auto p = std::make_unique<int>(42);
// 自動管理,無需手動 delete

// ✅ 正確: 預分配避免重新分配
vec.reserve(100);
```

#### 1.2.4 未初始化變數

```cpp
// ❌ UB: 讀取未初始化變數
int x;
int y = x + 1;  // UB! x 值未定義

// ❌ UB: 部分初始化結構體
struct Point {
    int x;
    int y;
};
Point p;  // x, y 都未初始化!

// ✅ 正確: 始終初始化
int x = 0;
Point p{10, 20};  // 統一初始化 (C++11)

// ✅ 成員預設初始化 (推薦)
struct Point {
    int x = 0;
    int y = 0;
};
```

#### 1.2.5 數據競爭

```cpp
// ❌ UB: 多執行緒同時修改
int counter = 0;

// 執行緒 1
counter++;  // UB! 非原子

// 執行緒 2  
counter++;  // UB! 數據競爭

// ✅ 正確: 原子操作
std::atomic<int> counter{0};
counter.fetch_add(1, std::memory_order_relaxed);

// ✅ 或使用 mutex
std::mutex mtx;
int counter = 0;
{
    std::lock_guard<std::mutex> lock(mtx);
    counter++;
}
```

#### 1.2.6 空指針解引用

```cpp
// ❌ UB: 解引用空指針
int* p = nullptr;
*p = 42;  // UB!

// ⚠️ delete nullptr 是安全的,但解引用不是
delete p;  // OK
*p;        // UB!

// ✅ 正確: 檢查後使用
if (p != nullptr) {
    *p = 42;
}

// ✅ 更好: 使用智能指針避免 nullptr
auto p = std::make_unique<int>(42);
*p = 10;  // 安全
```

#### 1.2.7 Strict Aliasing Violation

```cpp
// ❌ UB: 通過不兼容指針訪問記憶體
int x = 42;
float* p = reinterpret_cast<float*>(&x);
*p = 3.14f;  // UB! Strict aliasing violation

// ✅ 正確: 使用 memcpy (編譯器會優化)
float f;
std::memcpy(&f, &x, sizeof(float));

// ✅ 或使用 union (C++20 保證安全)
union {
    int i;
    float f;
} u;
u.i = 42;
float f = u.f;  // OK
```

### 1.3 UB 檢測工具

#### 編譯期檢測

```bash
# 啟用所有警告
g++ -Wall -Wextra -Wpedantic -Werror

# 未初始化變數
g++ -Wuninitialized

# 數組越界 (有限)
g++ -Warray-bounds
```

#### 執行期檢測 (Sanitizers)

```bash
# AddressSanitizer (記憶體錯誤)
g++ -fsanitize=address -g -O1 main.cpp

# UndefinedBehaviorSanitizer (UB)
g++ -fsanitize=undefined -g main.cpp

# ThreadSanitizer (數據競爭)
g++ -fsanitize=thread -g main.cpp

# 組合使用
g++ -fsanitize=address,undefined -g -O1 main.cpp
```

**執行範例:**

```cpp
// test.cpp
int main() {
    int arr[10];
    arr[10] = 42;  // 越界
}
```

```bash
$ g++ -fsanitize=address test.cpp
$ ./a.out
# AddressSanitizer 會報告越界錯誤
```

## 2. 類型轉換系統完全指南

### 2.1 C++ 類型轉換概覽

C++ 提供 4 種具名類型轉換取代 C 風格轉換:

| 轉換類型 | 用途 | 安全性 | 常用度 |
|---------|------|-------|--------|
| `static_cast` | 編譯期類型轉換 | 中等 | ⭐⭐⭐ |
| `dynamic_cast` | 執行期類型識別 (RTTI) | 高 | ⭐ |
| `const_cast` | 移除 const/volatile | 低 | ⭐ |
| `reinterpret_cast` | 位元重新解釋 | 極低 | ⭐ |

### 2.2 static_cast - 編譯期類型轉換

**用途**: 相關類型間轉換,編譯期檢查。

#### 基本類型轉換

```cpp
// 數值轉換
double price = 100.75;
int price_int = static_cast<int>(price);  // 100 (截斷)

// 隱式轉換的明確化
int x = 10;
double y = static_cast<double>(x);

// 避免整數除法陷阱
int total = 100;
int count = 3;
double avg = static_cast<double>(total) / count;  // 33.333...
// 若不加 static_cast: 100/3 = 33 (整數除法)
```

#### 指針類型轉換

```cpp
class Base {};
class Derived : public Base {};

// ✅ 向上轉換 (子類 -> 基類) - 安全
Derived* d = new Derived();
Base* b = static_cast<Base*>(d);  // OK

// ⚠️ 向下轉換 (基類 -> 子類) - 不檢查!
Base* b2 = new Base();
Derived* d2 = static_cast<Derived*>(b2);  // 編譯通過但危險!
// 若 b2 不指向 Derived,行為未定義
```

#### enum class 轉換

```cpp
enum class Side : uint8_t { Buy = 0, Sell = 1 };

Side side = Side::Buy;
uint8_t value = static_cast<uint8_t>(side);  // 0

// 反向轉換
Side side2 = static_cast<Side>(1);  // Side::Sell
```

### 2.3 dynamic_cast - 執行期類型識別

**用途**: 安全的向下轉換,帶執行期檢查。

⚠️ **限制**: 需要虛函數表 (至少一個虛函數),有性能開銷。

```cpp
class Base {
public:
    virtual ~Base() = default;  // 必須有虛函數!
};

class Derived : public Base {
public:
    void specific_method() {}
};

// ✅ 安全的向下轉換
Base* b = new Derived();
Derived* d = dynamic_cast<Derived*>(b);
if (d != nullptr) {  // 轉換成功
    d->specific_method();
}

// ❌ 轉換失敗返回 nullptr
Base* b2 = new Base();
Derived* d2 = dynamic_cast<Derived*>(b2);  // nullptr

// ⚠️ 引用轉換失敗拋出異常
try {
    Derived& d3 = dynamic_cast<Derived&>(*b2);
} catch (std::bad_cast& e) {
    // 轉換失敗
}
```

**何時使用 dynamic_cast?**
- ✅ 當你不確定對象的實際類型
- ❌ 避免過度使用,考慮多態設計

**替代方案**: `std::variant` (C++17)

```cpp
#include <variant>

struct TypeA { int value; };
struct TypeB { double value; };

using MyType = std::variant<TypeA, TypeB>;

MyType obj = TypeA{42};

// 類型安全的訪問
std::visit([](auto&& arg) {
    using T = std::decay_t<decltype(arg)>;
    if constexpr (std::is_same_v<T, TypeA>) {
        // 處理 TypeA
    } else if constexpr (std::is_same_v<T, TypeB>) {
        // 處理 TypeB
    }
}, obj);
```

### 2.4 const_cast - 移除 const/volatile

**用途**: 移除或添加 const/volatile 限定符。

⚠️ **危險**: 修改原本為 const 的對象是 UB!

```cpp
// ✅ 合法用途: 傳遞給舊 API
void legacy_api(char* str);  // 舊 API 沒有 const

void modern_code() {
    const char* str = "Hello";
    legacy_api(const_cast<char*>(str));  // OK,只要不修改
}

// ❌ UB: 修改原本為 const 的對象
const int x = 42;
int* p = const_cast<int*>(&x);
*p = 10;  // UB! x 本來就是 const

// ✅ 合法: 原對象不是 const
int y = 42;
const int* cp = &y;
int* p2 = const_cast<int*>(cp);
*p2 = 10;  // OK, y 本來不是 const
```

**最佳實踐**: 幾乎不需要使用 const_cast,良好的 API 設計應避免它。

### 2.5 reinterpret_cast - 位元重新解釋

**用途**: 指針類型間的低級轉換,重新解釋位元模式。

⚠️ **極度危險**: 破壞類型安全,可能違反 strict aliasing。

```cpp
// ✅ 合法用途: 指針轉整數
void* ptr = malloc(100);
uintptr_t addr = reinterpret_cast<uintptr_t>(ptr);
std::cout << std::hex << addr << "\n";

// ✅ 合法用途: 整數轉指針
uintptr_t addr2 = 0x7fff00000000;
void* ptr2 = reinterpret_cast<void*>(addr2);

// ⚠️ 指針類型轉換 (需小心對齊)
int x = 42;
char* p = reinterpret_cast<char*>(&x);  // OK, char* 可指向任何對象

// ❌ UB: 違反 strict aliasing
int x = 42;
float* p = reinterpret_cast<float*>(&x);
*p = 3.14f;  // UB!

// ✅ 正確做法: 使用 memcpy
float f;
std::memcpy(&f, &x, sizeof(float));
```

**何時使用 reinterpret_cast?**
- 系統程式設計 (記憶體映射 I/O)
- 網路封包解析 (需確保對齊)
- 幾乎任何其他場景都有更好的替代方案

### 2.6 C 風格轉換 - 應避免

```cpp
// ❌ 避免: C 風格轉換
double x = 3.14;
int y = (int)x;  // 這是哪種轉換?無法確定!

// ✅ 使用具名轉換
int y = static_cast<int>(x);  // 意圖明確
```

**為什麼避免 C 風格轉換?**

1. **不明確**: 無法知道執行哪種轉換
2. **難以搜索**: 無法用工具查找所有轉換
3. **可能執行多個轉換**: `(type)expr` 可能是多個 cast 的組合
4. **破壞類型安全**: 可能執行 `reinterpret_cast` 級別的危險操作

## 3. 隱式轉換與類型提升

### 3.1 整數提升 (Integral Promotion)

```cpp
// 小整數類型自動提升為 int
char c = 'A';      // 1 byte
short s = 100;     // 2 bytes
int result = c + s;  // char 和 short 都提升為 int (4 bytes)

// ⚠️ 注意符號擴展
int8_t x = -1;   // 0xFF
int y = x;       // 0xFFFFFFFF (符號擴展)

uint8_t u = 255; // 0xFF
int z = u;       // 0x000000FF (零擴展)
```

**為什麼要提升?**
- CPU 通常以 word 大小 (32/64-bit) 運算
- 避免小整數運算的溢位問題

### 3.2 浮點轉換

```cpp
float f = 3.14f;
double d = f;  // OK, 擴展為 double (無損)

double d2 = 3.14159265359;
float f2 = d2;  // ⚠️ 精度損失,可能有編譯器警告

// 混合運算: 較小型別提升為較大型別
float a = 1.0f;
double b = 2.0;
auto result = a + b;  // a 提升為 double, result 為 double
```

### 3.3 整數與浮點混合運算

```cpp
int x = 10;
double y = 3.14;
auto result = x + y;  // x 轉為 double, result 為 double

// ⚠️ 常見陷阱: 整數除法
int total = 100;
int count = 3;

double avg1 = total / count;  // 33.0 (錯誤!)
// 步驟: 100/3 = 33 (整數除法), 然後 33 轉為 double

double avg2 = static_cast<double>(total) / count;  // 33.333... (正確)
// 步驟: total 轉 double, 100.0/3 = 33.333...

// 或者
double avg3 = total / static_cast<double>(count);  // 也正確
```

### 3.4 指針與布林轉換

```cpp
// 指針隱式轉為 bool
int* p = nullptr;
if (p) {  // 隱式轉為 bool
    // ...
}

// 等價於
if (p != nullptr) {
    // ...
}

// ⚠️ 整數轉指針 (C++11 後限制)
int* p1 = 0;        // OK, 字面量 0 可轉為 nullptr
int* p2 = nullptr;  // OK (推薦)
// int* p3 = 1;     // Error! 其他整數不能隱式轉換
```

### 3.5 用戶定義轉換

#### 3.5.1 轉換建構函式

```cpp
class Price {
    double value_;
public:
    // ❌ 隱式轉換建構函式
    Price(double v) : value_(v) {}
};

void process(Price p) {}

int main() {
    process(100.5);  // ⚠️ 隱式轉換! double -> Price
    // 等價於 process(Price(100.5));
}
```

#### 3.5.2 explicit 關鍵字 ⭐⭐⭐

```cpp
class Price {
    double value_;
public:
    // ✅ 禁止隱式轉換
    explicit Price(double v) : value_(v) {}
};

void process(Price p) {}

int main() {
    // process(100.5);  // Error! 必須顯式轉換
    process(Price{100.5});  // OK
    process(Price(100.5));  // OK
}
```

**最佳實踐**: 所有單參數建構函式都應加 `explicit`!

```cpp
class String {
public:
    explicit String(size_t size);  // ✅
    String(const char* str);       // ⚠️ 可能需要隱式轉換
    explicit String(std::string_view sv);  // ✅
};
```

#### 3.5.3 轉換運算子

```cpp
class Price {
    double value_;
public:
    // ❌ 隱式轉換運算子
    operator double() const { return value_; }
};

Price p{100.5};
double d = p;  // 隱式轉換
double result = p + 50.0;  // 也會隱式轉換

// ✅ 顯式轉換運算子 (C++11)
class Price {
    double value_;
public:
    explicit operator double() const { return value_; }
};

Price p{100.5};
// double d = p;  // Error!
double d = static_cast<double>(p);  // OK

// ⚠️ bool 轉換運算子可以不用 explicit
class SmartPtr {
    void* ptr_;
public:
    operator bool() const { return ptr_ != nullptr; }  // 慣用法
};
```

## 4. 關鍵字組合詳解

### 4.1 const 的多重含義

#### 4.1.1 const 與指針

```cpp
// 1. 指向 const 的指針 (pointer to const)
const int* p1;   // p1 可變,*p1 不可變
int const* p2;   // 同上,const 在 * 左側

int x = 42, y = 100;
p1 = &x;   // OK, 改變指針
// *p1 = 10;  // Error! 不能修改指向的值

// 2. const 指針 (const pointer)
int* const p3 = &x;  // p3 不可變,*p3 可變
*p3 = 10;  // OK, 修改指向的值
// p3 = &y;   // Error! 不能改變指針

// 3. 指向 const 的 const 指針
const int* const p4 = &x;
// p4 = &y;   // Error! 指針不可變
// *p4 = 10;  // Error! 指向的值不可變

// 📌 記憶技巧: 從右向左讀
// const int* const p
//           ^---- p is const (指針是常數)
//      ^--------- pointer to const int (指向常數 int)
```

**實用範例:**

```cpp
// 函數參數:
void read_only(const int* p);     // 不會修改 *p
void modify_value(int* const p);  // 不會改變 p 指向
void fully_const(const int* const p);  // 都不改變
```

#### 4.1.2 const 成員函數

```cpp
class Vector {
    double x_, y_;
    
public:
    // const 成員函數: 不修改物件狀態
    double length() const {
        // x_ = 10;  // Error! 不能修改成員
        return std::sqrt(x_ * x_ + y_ * y_);
    }
    
    // 非 const 成員函數
    void set_x(double x) {
        x_ = x;
    }
    
    // const 重載
    int& operator[](size_t i) {
        return data_[i];  // 可修改
    }
    
    const int& operator[](size_t i) const {
        return data_[i];  // 唯讀
    }
};

// const 物件只能調用 const 成員函數
const Vector v{1, 2};
v.length();   // OK
// v.set_x(10);  // Error!
```

#### 4.1.3 mutable - 打破 const

```cpp
class Cache {
    mutable std::mutex mtx_;               // mutable!
    mutable std::map<int, int> cache_;     // mutable!
    
public:
    int get(int key) const {  // const 成員函數
        std::lock_guard<std::mutex> lock(mtx_);  // OK
        return cache_[key];  // OK, 可以修改 mutable 成員
    }
};
```

**何時使用 mutable?**
- 緩存 (lazy evaluation)
- 執行緒同步原語 (mutex, atomic)
- 統計資訊 (計數器)

### 4.2 static 的多重含義

#### 4.2.1 靜態局部變數

```cpp
void counter() {
    static int count = 0;  // 只初始化一次
    ++count;
    std::cout << count << "\n";
}

counter();  // 1
counter();  // 2
counter();  // 3

// ✅ C++11 保證執行緒安全的初始化
void thread_safe_init() {
    static ExpensiveObject obj;  // 只會初始化一次,即使多執行緒
}

// ⚠️ 但 ++ 操作不是執行緒安全的!
void counter_unsafe() {
    static int count = 0;
    ++count;  // 數據競爭!
}

// ✅ 執行緒安全版本
void counter_safe() {
    static std::atomic<int> count{0};
    count.fetch_add(1, std::memory_order_relaxed);
}
```

### 4.3 inline 的真正含義

⚠️ **常見誤解**: `inline` 不是建議編譯器內聯!

**真正含義**:
1. 允許多重定義 (One Definition Rule 的例外)
2. C++17: 允許在標頭檔定義變數

#### 4.3.1 inline 函數

```cpp
// header.h
inline int add(int a, int b) {
    return a + b;  // 可在多個 .cpp 包含,只有一份定義
}

// 編譯器自行決定是否內聯,與 inline 關鍵字無關!
```

#### 4.3.2 inline 變數 (C++17)

```cpp
// header.h
inline constexpr double PI = 3.14159;  // ✅ C++17
inline std::atomic<int> counter{0};    // ✅ C++17

// C++17 前需在 .cpp 定義:
// extern const double PI;  // header.h
// const double PI = 3.14159;  // .cpp
```

#### 4.3.3 強制內聯

```cpp
// GCC/Clang
__attribute__((always_inline)) inline 
int critical_function(int x) {
    return x * 2;
}

// MSVC
__forceinline int critical_function(int x) {
    return x * 2;
}

// ⚠️ 編譯器仍可能拒絕內聯 (如遞歸函數)
```

### 4.4 constexpr - 編譯期計算

#### 4.4.1 constexpr vs const

```cpp
// const: 執行期或編譯期常數
const int runtime = get_value();   // 執行期
const int compile = 42;            // 編譯期 (可能)

// constexpr: 保證編譯期常數
constexpr int value = 42;          // 編譯期
// constexpr int bad = get_value();  // Error! 必須編譯期可計算
```

#### 4.4.2 constexpr 函數

```cpp
// C++11: 單一 return 語句
constexpr int square(int x) {
    return x * x;
}

// C++14: 允許多個語句
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

// 編譯期執行
constexpr int fact5 = factorial(5);  // 120 (編譯期計算)
int arr[factorial(4)];  // 陣列大小必須是編譯期常數

// 也可執行期執行
int n;
std::cin >> n;
int result = factorial(n);  // 執行期計算
```

#### 4.4.3 constexpr if (C++17)

```cpp
template<typename T>
void process(T value) {
    if constexpr (std::is_integral_v<T>) {
        // 整數分支
        std::cout << "Integer: " << value << "\n";
    } else if constexpr (std::is_floating_point_v<T>) {
        // 浮點分支
        std::cout << "Float: " << value << "\n";
    } else {
        // 其他類型
        std::cout << "Other\n";
    }
    // 未使用的分支不會編譯! (真正的編譯期分支)
}

process(42);      // 只編譯整數分支
process(3.14);    // 只編譯浮點分支
```

### 4.5 關鍵字組合總結

| 組合 | 含義 | 使用場景 |
|-----|------|---------|
| `const int` | 執行期常數 | 一般不可變值 |
| `constexpr int` | 編譯期常數 | 陣列大小、模板參數 |
| `static const` | 類內常數 | 類級別配置 |
| `static constexpr` | 類內編譯期常數 | 類級別編譯期值 |
| `inline constexpr` | 標頭檔編譯期常數 (C++17) | 跨翻譯單元常數 |
| `mutable` | const 成員函數可修改 | 緩存、mutex |
| `static thread_local` | 執行緒局部靜態變數 | 執行緒緩存 |

## 5. 記憶體管理與智能指針

### 5.1 RAII 原則

**RAII (Resource Acquisition Is Initialization)**: 資源獲取即初始化。

```cpp
// ❌ 手動管理 (容易洩漏)
void bad_example() {
    int* p = new int(42);
    process(p);
    delete p;  // 如果 process 拋出異常,不會執行!
}

// ✅ RAII (自動管理)
void good_example() {
    auto p = std::make_unique<int>(42);
    process(p.get());
    // 離開作用域自動釋放,即使異常
}
```

### 5.2 unique_ptr - 獨占所有權

```cpp
#include <memory>

// 創建
auto p1 = std::make_unique<int>(42);  // C++14 (推薦)
std::unique_ptr<int> p2(new int(42)); // C++11

// 訪問
*p1 = 10;
int value = *p1;

// 移動 (轉移所有權)
auto p3 = std::move(p1);  // p1 變為 nullptr
// *p1;  // Error! p1 已無效

// 釋放並獲取裸指針
int* raw = p3.release();  // p3 變為 nullptr,不會 delete
delete raw;  // 需手動刪除

// 重置
p3.reset(new int(100));  // 刪除舊值,持有新值
p3.reset();  // 刪除並變為 nullptr

// 自定義刪除器
auto deleter = [](int* p) {
    std::cout << "Custom delete\n";
    delete p;
};
std::unique_ptr<int, decltype(deleter)> p4(new int(42), deleter);
```

**數組版本:**

```cpp
auto arr = std::make_unique<int[]>(10);  // C++14
arr[0] = 42;
// 自動調用 delete[]
```

### 5.3 shared_ptr - 共享所有權

```cpp
// 創建
auto p1 = std::make_shared<int>(42);  // 推薦 (單次分配)
std::shared_ptr<int> p2(new int(42)); // 兩次分配

// 引用計數
std::cout << p1.use_count() << "\n";  // 1

// 共享
auto p3 = p1;  // 引用計數 +1
std::cout << p1.use_count() << "\n";  // 2

{
    auto p4 = p1;  // 引用計數 +1
    std::cout << p1.use_count() << "\n";  // 3
}  // p4 銷毀,計數 -1

std::cout << p1.use_count() << "\n";  // 2

// 重置
p3.reset();  // 計數 -1
std::cout << p1.use_count() << "\n";  // 1
```

**性能考量:**
- 引用計數是原子操作 (執行緒安全但有開銷)
- 額外記憶體 (控制塊 16-32 bytes)
- 優先使用 `unique_ptr`,只在必要時用 `shared_ptr`

### 5.4 weak_ptr - 弱引用

**用途**: 打破循環引用。

```cpp
class Node {
public:
    std::shared_ptr<Node> next;  // 強引用
    std::weak_ptr<Node> prev;    // 弱引用,打破循環
};

auto n1 = std::make_shared<Node>();
auto n2 = std::make_shared<Node>();

n1->next = n2;  // n1 -> n2
n2->prev = n1;  // n2 觀察 n1 (不增加計數)

// 使用 weak_ptr
std::weak_ptr<Node> weak = n1;

// 檢查是否存活
if (auto shared = weak.lock()) {  // 嘗試提升為 shared_ptr
    // n1 仍存活
    shared->next;
} else {
    // n1 已銷毀
}

// 或檢查 expired
if (weak.expired()) {
    // 已銷毀
}
```

### 5.5 智能指針最佳實踐

```cpp
// ✅ 工廠函數返回 unique_ptr
std::unique_ptr<Base> create_object(int type) {
    if (type == 1) return std::make_unique<Derived1>();
    return std::make_unique<Derived2>();
}

// ✅ 函數接受裸指針或引用 (不轉移所有權)
void process(const Widget& w);  // 推薦
void process(Widget* w);        // 可空時使用

// ❌ 不要接受智能指針 (除非要轉移/共享所有權)
void bad(std::unique_ptr<Widget> w);  // 強制轉移
void bad(std::shared_ptr<Widget> w);  // 強制共享

// ✅ 只在需要時轉移所有權
void take_ownership(std::unique_ptr<Widget> w);
```

## 6. 移動語義與完美轉發

### 6.1 左值與右值

```cpp
int x = 10;  // x 是左值 (有名字,可取地址)
int y = 20;  // y 是左值

int z = x + y;  // x+y 是右值 (臨時值,無名字)

// 左值引用
int& lref = x;  // OK
// int& bad = 10;  // Error! 不能綁定右值

// const 左值引用可綁定右值
const int& cref = 10;  // OK

// 右值引用 (C++11)

int&& rref2 = x + y;  // OK
// int&& bad = x;  // Error! 不能綁定左值
```

### 6.2 std::move - 轉為右值

```cpp
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = std::move(v1);  // 移動,不拷貝

// v1 現在處於"有效但未指定"狀態
// 可以: v1.clear(), v1 = other_vec
// 不要: 訪問 v1 的元素!

```

**std::move 不做任何事**,只是轉型:

```cpp
template<typename T>
typename std::remove_reference<T>::type&& move(T&& t) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(t);
}
```

### 6.3 移動建構函式與移動賦值

```cpp
class String {
    char* data_;
    size_t size_;
    
public:
    // 建構函式
    String(const char* str) {
        size_ = strlen(str);
        data_ = new char[size_ + 1];
        strcpy(data_, str);
    }
    
    // 拷貝建構函式
    String(const String& other) {
        size_ = other.size_;
        data_ = new char[size_ + 1];
        strcpy(data_, other.data_);
    }
    
    // 移動建構函式
    String(String&& other) noexcept {
        data_ = other.data_;
        size_ = other.size_;
        other.data_ = nullptr;  // 重置
        other.size_ = 0;
    }
    
    // 拷貝賦值
    String& operator=(const String& other) {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = new char[size_ + 1];
            strcpy(data_, other.data_);
        }
        return *this;
    }
    
    // 移動賦值
    String& operator=(String&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }
    
    ~String() {
        delete[] data_;
    }
};
```

**Rule of Five**: 如果需要自定義其中一個,通常需要全部:
1. 解構函式
2. 拷貝建構函式
3. 拷貝賦值運算子
4. 移動建構函式
5. 移動賦值運算子

### 6.4 完美轉發

```cpp
// 問題: 如何保持參數的值類別?
template<typename T>
void wrapper(T arg) {
    process(arg);  // 總是拷貝!
}

// ✅ 解決: 完美轉發
template<typename T>
void wrapper(T&& arg) {  // 萬能引用
    process(std::forward<T>(arg));  // 保持值類別
}

void process(int& x) { std::cout << "Lvalue\n"; }
void process(int&& x) { std::cout << "Rvalue\n"; }

int x = 10;
wrapper(x);   // 調用 process(int&)
wrapper(20);  // 調用 process(int&&)
```

**std::forward 的作用**:
- 左值轉發為左值
- 右值轉發為右值

```cpp
try {
    // ...
} catch (...) {
    // ...
}

// ⚠️ 避免: RTTI/虛函數 (間接調用)
dynamic_cast<Derived*>(base_ptr);

// ⚠️ 避免: shared_ptr (原子操作開銷)
std::shared_ptr<int> p;

// ✅ 使用錯誤碼
std::optional<Result> try_operation();

// ✅ 使用 std::variant
std::variant<Success, Error> result;
```
