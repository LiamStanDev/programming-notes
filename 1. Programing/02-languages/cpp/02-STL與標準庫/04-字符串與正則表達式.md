## std::string 深度解析

`std::string` 是 C++ 中管理文本的標準方式，本質上是 `std::basic_string<char>`。

### 1. 記憶體管理與 SSO

`std::string` 的性能關鍵在於記憶體分配。現代標準庫實現了 **SSO (Small String Optimization)**：

- **短字符串**: 直接存儲在對象內部的棧緩衝區 (通常 15-22 字節)，無堆分配。
- **長字符串**: 在堆上分配記憶體，對象內部只存指針、大小和容量。

```cpp
std::string s1 = "short"; // SSO: 無堆分配
std::string s2 = "this is a very long string that requires heap allocation"; // 堆分配
```

### 2. 常用操作複雜度

| 操作         | 複雜度    | 說明                                    |
| :----------- | :-------- | :-------------------------------------- |
| `operator[]` | O(1)      | 隨機訪問                                |
| `push_back`  | O(1) 均攤 | 尾部追加                                |
| `insert`     | O(N)      | 中間插入 (需移動數據)                   |
| `substr`     | O(N)      | **注意**: 會產生新的 string 對象 (拷貝) |
| `find`       | O(N\*M)   | 子串查找                                |

## std::string_view (C++17)

在 HFT 和高性能系統中，`std::string_view` 是最重要的特性之一。它是一個輕量級的字符串「視圖」，只包含指針和長度，**不擁有記憶體，不進行拷貝**。

### 1. 為什麼需要 string_view

```cpp
// ❌ 傳統方式: 產生臨時 string 對象，觸發 malloc/free
void process(const std::string& s);
process("hello world"); // 隱式轉換: const char* -> string

// ✅ string_view: 無拷貝，無分配
void process(std::string_view s);
process("hello world"); // 直接構造 view
```

### 2. 使用陷阱

由於 `string_view` 不擁有記憶體，必須確保它指向的生命週期大於 view 本身。

```cpp
std::string_view get_view() {
    std::string s = "hello";
    return s; // ❌ 危險: s 銷毀後 view 懸空 (Dangling Pointer)
}
```

## 字符串算法

C++ 標準庫提供了豐富的字符串處理算法。

### 1. 查找與替換

```cpp
std::string s = "hello world";

// 查找
size_t pos = s.find("world"); // 6
if (pos != std::string::npos) { ... }

// 替換 (原地)
s.replace(pos, 5, "C++"); // "hello C++"
```

### 2. 數值轉換

```cpp
// string -> number
int i = std::stoi("42");
double d = std::stod("3.14");

// number -> string
std::string s = std::to_string(123);

// 高性能轉換 (C++17 from_chars / to_chars)
#include <charconv>
char buffer[10];
std::to_chars(buffer, buffer + 10, 123); // 無 locale 開銷，極快
```

## 正則表達式

C++11 引入了 `<regex>`，但在高性能場景下應**謹慎使用**。

### 1. 基本用法

```cpp
#include <regex>

std::string text = "Order: 12345, Price: 99.5";
std::regex re(R"(Order: (\d+), Price: ([\d.]+)");
std::smatch matches;

if (std::regex_search(text, matches, re)) {
    std::cout << "ID: " << matches[1] << ", Price: " << matches[2] << "\n";
}
```

### 2. 性能陷阱

標準庫的 `std::regex` 性能通常不如其他語言 (如 Python, Perl) 或專用庫 (如 RE2, Boost.Regex)。

- **編譯開銷**: `std::regex` 構造很慢，務必使用 `static` 或全局變量重用。
- **匹配開銷**: 複雜的正則可能導致回溯 (Backtracking)，嚴重影響延遲。

## 性能優化技巧

### 1. 避免 substr

`substr` 會創建新字符串。使用 `string_view` 的 `substr` (O(1)) 代替。

```cpp
std::string s = "data: 123";
// ❌ 拷貝
std::string val = s.substr(6);

// ✅ 零拷貝
std::string_view sv = s;
std::string_view val_view = sv.substr(6);
```

### 2. 預分配 (Reserve)

拼接字符串時，先預估大小。

```cpp
std::string res;
res.reserve(1024); // 避免多次擴容
res += s1;
res += s2;
```

### 3. 使用 charconv (C++17)

`std::stoi` 和 `std::to_string` 依賴 C locale，速度慢且阻止編譯器優化。`std::from_chars` 和 `std::to_chars` 是底層、無 locale 的高性能替代品。

```cpp
#include <iostream>
#include <string>
#include <charconv> // C++17 核心
#include <array>
#include <system_error> // 包含 std::errc

// --- 1. 使用 std::to_chars 將數值轉換為字串 (數值 -> 字串) ---
void value_to_string_example() {
    std::cout << "--- 1. 數值轉字串 (std::to_chars) ---\n";
    
    int value = 42007;
    // 緩衝區必須足夠大。int 的最大值大約是 10 位數，加上符號和終止符。
    // std::array 通常比 char[] 更好
    std::array<char, 20> buffer{}; 
    
    // 執行轉換：
    // buffer.data(): 輸出緩衝區的起始位址
    // buffer.data() + buffer.size(): 輸出緩衝區的結束位址
    auto [ptr, ec] = std::to_chars(buffer.data(), buffer.data() + buffer.size(), value);

    if (ec == std::errc()) { // 空的 errc() 表示成功
        // 轉換成功。*ptr* 指向轉換結束後的位置
        std::string result(buffer.data(), ptr);
        std::cout << "轉換成功 (整數): " << result << "\n";
    } else if (ec == std::errc::value_too_large) {
        std::cout << "錯誤: 緩衝區太小\n";
    } else {
        std::cout << "錯誤: 其他轉換錯誤\n";
    }

    // --- 浮點數轉換範例 (C++17 不支援，但 C++20 已添加) ---
    // double d_value = 123.456;
    // std::array<char, 30> d_buffer{};
    // auto [d_ptr, d_ec] = std::to_chars(d_buffer.data(), d_buffer.data() + d_buffer.size(), d_value);
    // if (d_ec == std::errc()) {
    //     std::string d_result(d_buffer.data(), d_ptr);
    //     std::cout << "轉換成功 (浮點數): " << d_result << "\n";
    // }
}

// --- 2. 使用 std::from_chars 將字串轉換為數值 (字串 -> 數值) ---
void string_to_value_example() {
    std::cout << "\n--- 2. 字串轉數值 (std::from_chars) ---\n";
    
    // 成功案例
    std::string s1 = "123456";
    long long value1 = 0;
    
    // 執行轉換：
    // s1.data(): 輸入字串的起始位址
    // s1.data() + s1.size(): 輸入字串的結束位址
    auto [ptr1, ec1] = std::from_chars(s1.data(), s1.data() + s1.size(), value1);

    if (ec1 == std::errc()) {
        // 檢查 ptr1 是否指向字串的末尾，確保整個字串都被解析
        if (ptr1 == s1.data() + s1.size()) {
            std::cout << "成功解析: " << value1 << "\n";
        } else {
            // 如果字串包含額外的字符，例如 "123abc"
            std::cout << "部分解析，剩餘字元: " << value1 << " (剩餘: " << ptr1 << ")\n";
        }
    } else if (ec1 == std::errc::invalid_argument) {
        std::cout << "錯誤: 無法解析為數值\n";
    } else if (ec1 == std::errc::result_out_of_range) {
        std::cout << "錯誤: 數值溢位\n";
    }

    // 失敗案例 (非數值)
    std::string s2 = "12X45";
    int value2 = 0;
    auto [ptr2, ec2] = std::from_chars(s2.data(), s2.data() + s2.size(), value2);

    if (ec2 == std::errc::invalid_argument) {
        std::cout << "失敗解析: '" << s2 << "' 不是有效數值 (錯誤碼: invalid_argument)\n";
    }
}
```

## 實戰案例

### 案例 1: FIX 協議解析 (Zero-copy)

**場景**: 解析 FIX 消息 `8=FIX.4.4|9=123|35=D|...`，提取 Tag 35 (MsgType)。

**實現**:
使用 `string_view` 進行切分，完全避免記憶體分配。

```cpp
std::string_view get_tag_value(std::string_view msg, std::string_view tag) {
    // 構造 "tag="
    // 實際優化: 預先計算好 "35=" 的位置或使用更高效的 parser
    size_t start = msg.find(tag);
    if (start == std::string_view::npos) return {};

    start += tag.size() + 1; // 跳過 "tag="
    size_t end = msg.find('|', start); // 假設 | 是分隔符
    if (end == std::string_view::npos) return msg.substr(start);

    return msg.substr(start, end - start);
}

// 使用
std::string_view msg = "8=FIX.4.4|9=123|35=D|...";
auto msg_type = get_tag_value(msg, "35"); // 返回 "D", 無拷貝
```

### 案例 2: Symbol 標準化

**場景**: 將 "tcelec" 轉換為 "TCELEC" 並去除空白。

**實現**:
原地修改，避免創建新串。

```cpp
void normalize(std::string& s) {
    // 1. 去除首尾空白 (Trim)
    auto start = s.find_first_not_of(" \t");
    if (start == std::string::npos) { s.clear(); return; }
    auto end = s.find_last_not_of(" \t");
    s = s.substr(start, end - start + 1); // 這裡可能需要一次移動

    // 2. 轉大寫
    std::transform(s.begin(), s.end(), s.begin(),
                   [](unsigned char c){ return std::toupper(c); });
}
```

### 案例 3: 日誌格式化 (Log Formatting)

**場景**: 高頻寫入日誌，避免 `sprintf` 或 `stringstream` 的開銷。

**實現**:
使用 `fmt` 庫 (C++20 `std::format` 的前身) 或手寫 buffer 填充。

```cpp
#include <fmt/core.h> // 或 #include <format> in C++20

void log_trade(const char* symbol, double price, int qty) {
    // fmt 庫在編譯期解析格式串，運行時直接寫入 buffer
    // 比 sprintf 快，且類型安全
    std::string s = fmt::format("Trade: {} @ {} x {}", symbol, price, qty);
    // ... 寫入文件 ...
}
```

## 性能分析

### String vs String View

| 操作                 | std::string    | std::string_view | 提升    |
| :------------------- | :------------- | :--------------- | :------ |
| **傳參 (100 bytes)** | 30 ns (malloc) | 1 ns             | **30x** |
| **Substr**           | 30 ns (malloc) | 1 ns             | **30x** |
| **Find**             | 50 ns          | 50 ns            | 持平    |

### Regex vs Manual Parsing

解析簡單格式 (如 "Key=Value")：

- **std::regex**: ~1000 ns (回溯、狀態機開銷)
- **Manual (find/substr)**: ~10 ns
- **結論**: 在熱點路徑 (Hot Path) 嚴禁使用 `std::regex`。

---

## 最佳實踐

1. **參數傳遞**: 函數參數優先使用 `std::string_view` (按值傳遞) 代替 `const std::string&`。
2. **避免 Regex**: 在延遲敏感代碼中，手寫解析邏輯或使用編譯期解析庫 (如 CTRE)。
3. **數值轉換**: 使用 `std::from_chars` / `std::to_chars` 代替 `stoi` / `to_string`。
4. **預分配**: 總是 `reserve` 目標字符串的大小。
5. **SSO 意識**: 盡量保持字符串短小 (小於 15/22 字節) 以利用 SSO。
