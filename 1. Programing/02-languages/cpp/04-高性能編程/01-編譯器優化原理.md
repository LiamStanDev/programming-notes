## 核心概念

### 1. 編譯流程簡述

理解編譯流程有助於定位性能問題：
1.  **預處理 (Preprocessing)**: 展開宏, 處理 `#include`。
2.  **編譯 (Compilation)**: 將代碼轉換為匯編 (Assembly), 這是大部分優化發生的階段。
3.  **匯編 (Assembly)**: 將匯編轉換為機器碼 (Object file)。
4.  **鏈接 (Linking)**: 合併多個 Object file, 進行 LTO。

### 2. 優化等級 (Optimization Levels)

| 等級 | 描述 | HFT 推薦 | 備註 |
|------|------|----------|------|
| `-O0` | 無優化 | ❌ | 僅用於調試, 生成代碼最慢 |
| `-O1` | 基本優化 | ❌ | 減少代碼體積, 簡單優化 |
| `-O2` | 標準優化 | ✅ (開發) | 啟用大部分不增加體積的優化 (內聯, 循環優化) |
| `-O3` | 激進優化 | ✅ (生產) | 啟用向量化, 更激進的內聯, 可能增加體積 |
| `-Ofast`| 極速優化 | ⚠️ | `-O3` + `-ffast-math`, 可能破壞 IEEE 754 精度 |
| `-Os` | 體積優化 | ❌ | 犧牲速度換取體積, 嵌入式常用 |

## 編譯器優化技術

### 1. 內聯 (Inlining)

將函數調用替換為函數體本身, 消除調用開銷並啟用進一步優化 (如常量折疊)。

```cpp
// 建議內聯
inline int add(int a, int b) { return a + b; }

// 強制內聯 (GCC/Clang)
__attribute__((always_inline)) int fast_add(int a, int b) { return a + b; }

// 禁止內聯 (用於冷代碼或調試)
__attribute__((noinline)) int slow_path(int x) { return x * x; }
```

### 2. 常量傳播與折疊 (Constant Propagation & Folding)

編譯期計算已知結果。

```cpp
// 源代碼
const int N = 100;
int result = N * 2 + 5;

// 編譯後優化為
int result = 205; // 直接使用立即數
```

### 3. 循環優化

-   **循環展開 (Loop Unrolling)**: 減少循環控制開銷, 增加指令並行度。
-   **循環不變量外提 (Loop-Invariant Code Motion)**: 將循環內不變的計算移到循環外。
-   **循環融合 (Loop Fusion)**: 合併相鄰的循環以改善 Cache 局部性。

```cpp
// 優化前
for (int i = 0; i < n; ++i) a[i] = b[i] + 1;
for (int i = 0; i < n; ++i) c[i] = a[i] * 2;

// 優化後 (融合)
for (int i = 0; i < n; ++i) {
    a[i] = b[i] + 1;
    c[i] = a[i] * 2; // 數據在 Cache 中熱乎著
}
```

### 4. 死代碼消除 (Dead Code Elimination)

移除不會被執行的代碼或計算結果未被使用的代碼。

## 鏈接時優化 (LTO)

**Link Time Optimization (LTO)** 允許編譯器在鏈接階段跨越翻譯單元 (Translation Unit) 進行優化。

-   **跨模塊內聯**: 將 `a.cpp` 中的函數內聯到 `b.cpp` 中。
-   **全局死代碼消除**: 移除整個程序中未被使用的函數。

**啟用方式**:
```bash
g++ -O3 -flto main.cpp utils.cpp -o app
```

> [!TIP]
> HFT 系統強烈建議開啟 LTO, 通常能帶來 10-20% 的性能提升, 但會顯著增加編譯時間。

## 性能引導優化 (PGO)

**Profile-Guided Optimization (PGO)** 利用運行時數據指導編譯器優化。

1.  **插樁編譯**: `g++ -O3 -fprofile-generate ...`
2.  **運行收集數據**: 運行典型負載, 生成 `.gcda` 文件。
3.  **優化編譯**: `g++ -O3 -fprofile-use ...`

**優化效果**:
-   **分支預測**: 優化 `if-else` 分支順序。
-   **代碼佈局**: 將熱代碼集中, 減少 I-Cache Miss。
-   **虛函數優化**: 將高頻虛函數調用轉換為直接調用 (Devirtualization)。

## 阻礙優化的模式

### 1. 指針別名 (Pointer Aliasing)

編譯器必須假設兩個指針可能指向同一內存, 從而無法激進優化。

```cpp
// ❌ 潛在別名
void update(int* a, int* b) {
    *a = 10;
    *b = 20; // 可能覆蓋 *a
    // 這裡必須重新讀取 *a
}

// ✅ 使用 __restrict (非標準但廣泛支持)
void update(int* __restrict a, int* __restrict b) {
    *a = 10;
    *b = 20;
    // 編譯器知道 a 和 b 不重疊
}
```

### 2. 虛函數與間接調用

運行時多態 (虛函數) 和函數指針會阻礙內聯。
**解決**: 使用模板 (CRTP) 或 `std::variant` 實現靜態多態。

### 3. 異常處理

異常路徑會增加代碼體積並阻礙某些優化。
**解決**: 在確定的函數上標記 `noexcept`。

### 4. Volatile

`volatile` 強制每次訪問都讀寫內存, 禁止優化。
**注意**: `volatile` **不是** 用於多線程同步的! 請使用 `std::atomic`。

## 編譯器內建函數 (Builtins)

直接生成特定機器指令或給編譯器提示。

```cpp
// 1. 分支預測提示 (C++20 [[likely]])
if (ptr != nullptr) [[likely]] {
    // 熱路徑
}

// 2. 預取數據 (Prefetch)
__builtin_prefetch(&data[i + 16]);

// 3. 假設 (Assume) - 幫助編譯器消除分支
void compute(int x) {
    if (x <= 0) __builtin_unreachable(); // 告訴編譯器 x 永遠 > 0
    // ...
}

// 4. 位運算
int count = __builtin_popcount(mask); // POPCNT 指令
```

## HFT 實戰案例

### 案例 1: 訂單簿價格級別查找

**場景**: 在 OrderBook 中查找特定價格的 Level。

**❌ 未優化**: 使用 `std::map` (紅黑樹)。
```cpp
std::map<double, Level> bids;
// 查找 O(log N), 內存跳轉多 (Cache Miss)
```

**✅ 優化**: 使用預分配數組 (直接定址)。
```cpp
// 價格通常是離散的 (Tick Size)
// 將價格映射為數組索引
inline int price_to_idx(double price) {
    return static_cast<int>((price - min_price) / tick_size);
}

std::vector<Level> bids(MAX_LEVELS);
// 查找 O(1), 內存連續, 易於向量化
```

### 案例 2: 市場數據解碼

**❌ 未優化**: 逐字節拷貝。
```cpp
struct Msg { int id; double price; };
Msg parse(char* buf) {
    Msg m;
    memcpy(&m.id, buf, 4);
    memcpy(&m.price, buf + 4, 8);
    return m;
}
```

**✅ 優化**: `reinterpret_cast` (零拷貝)。
```cpp
// 必須確保內存對齊和字節序 (Endianness)
struct alignas(8) Msg { int id; double price; };
const Msg* parse(const char* buf) {
    return reinterpret_cast<const Msg*>(buf);
}
```

## CMake 最佳實踐

在 `CMakeLists.txt` 中啟用高性能選項。

```cmake
# 1. 設置 C++ 標準
set(CMAKE_CXX_STANDARD 20)

# 2. 針對本機 CPU 優化 (開啟 AVX 等指令集)
set(CMAKE_CXX_FLAGS_RELEASE "${CMAKE_CXX_FLAGS_RELEASE} -O3 -march=native")

# 3. 啟用 LTO (CMake 3.9+)
include(CheckIPOSupported)
check_ipo_supported(RESULT result OUTPUT output)
if(result)
    set_property(TARGET my_target PROPERTY INTERPROCEDURAL_OPTIMIZATION TRUE)
endif()

# 4. 禁用異常和 RTTI (如果不需要)
# add_compile_options(-fno-exceptions -fno-rtti)
```
