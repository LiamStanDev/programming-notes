# 信號處理與計時器 (Signal Handling & Timers)

信號是 Unix/Linux 中異步事件通知的核心機制,高精度計時器則是性能測量和定時任務的基礎。在 HFT 系統中,正確處理信號實現優雅關閉,並使用低延遲計時器進行精確測量,是系統穩定性和性能的關鍵。

---

## 1. 信號處理基礎

### 1.1 信號概念

**信號 (Signal)** 是一種軟件中斷,用於通知進程發生了某個事件。

**⭐⭐⭐ 信號的來源**:
- **硬件異常**: 除零錯誤 (SIGFPE)、非法內存訪問 (SIGSEGV)
- **終端操作**: Ctrl+C (SIGINT)、Ctrl+\ (SIGQUIT)
- **系統調用**: `kill()`, `raise()`, `alarm()`
- **軟件條件**: 管道斷開 (SIGPIPE)、子進程終止 (SIGCHLD)

### 1.2 常見信號

| 信號 | 編號 | 默認行為 | 說明 | HFT 應用 |
|------|------|----------|------|---------|
| `SIGINT` | 2 | 終止 | Ctrl+C,用戶中斷 | 手動停止系統 |
| `SIGTERM` | 15 | 終止 | 請求終止 (可捕獲) | **優雅關閉** |
| `SIGKILL` | 9 | 終止 | 強制終止 (不可捕獲) | 強制停止 |
| `SIGSEGV` | 11 | Core Dump | 段錯誤,非法內存訪問 | 程序錯誤 |
| `SIGPIPE` | 13 | 終止 | 寫入已關閉的管道/Socket | Socket 斷開 |
| `SIGCHLD` | 17 | 忽略 | 子進程狀態改變 | 進程管理 |
| `SIGALRM` | 14 | 終止 | 定時器到期 | 超時處理 |
| `SIGUSR1/2` | 10/12 | 終止 | 用戶自定義信號 | 重載配置 |

**⭐⭐⭐ 信號處理方式**:
1. **默認行為**: 終止、忽略、停止、繼續
2. **忽略**: `SIG_IGN`
3. **自定義處理函數**: 捕獲並處理

### 1.3 基本信號處理

```cpp
#include <signal.h>
#include <unistd.h>
#include <iostream>
#include <atomic>

// 使用原子變量作為標誌
std::atomic<bool> g_shutdown{false};

// 信號處理函數 (應盡量簡單)
void signal_handler(int signum) {
    g_shutdown.store(true, std::memory_order_relaxed);
}

void example_basic_signal() {
    // 設置信號處理器 (舊式,不推薦)
    // signal(SIGINT, signal_handler);
    
    // 使用 sigaction (推薦)
    struct sigaction sa;
    sa.sa_handler = signal_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    
    sigaction(SIGINT, &sa, nullptr);   // Ctrl+C
    sigaction(SIGTERM, &sa, nullptr);  // kill
    
    std::cout << "Press Ctrl+C to exit...\n";
    
    while (!g_shutdown.load(std::memory_order_relaxed)) {
        // 主循環
        sleep(1);
    }
    
    std::cout << "Exiting gracefully\n";
}
```

## 2. Async-Signal-Safe 函數

### 2.1 信號安全性

**⭐⭐⭐ 關鍵原則**: 信號處理器可能在**任何時刻**中斷程序執行,因此只能調用**異步信號安全 (async-signal-safe)** 的函數。

**不安全的操作** (禁止在信號處理器中使用):
- `malloc()` / `free()` - 可能死鎖
- `printf()` / `std::cout` - 使用緩衝區鎖
- 大部分 C++ 標準庫函數
- 非原子的全局變量訪問

**安全的操作**:
- 原子操作 (`std::atomic`)
- `write()` 系統調用
- `_exit()` (不是 `exit()`)
- POSIX 規定的信號安全函數列表

```cpp
#include <signal.h>
#include <unistd.h>
#include <atomic>

std::atomic<bool> g_shutdown{false};

// ❌ 錯誤範例: 不安全
void bad_signal_handler(int signum) {
    std::cout << "收到信號 " << signum << "\n";  // 不安全!
    std::string msg = "停止中...";  // 不安全!
}

// ✅ 正確範例: 安全
void safe_signal_handler(int signum) {
    const char msg[] = "Caught signal\n";
    write(STDERR_FILENO, msg, sizeof(msg) - 1);  // 安全
    
    g_shutdown.store(true, std::memory_order_relaxed);  // 安全
}
```

### 2.2 POSIX 規定的信號安全函數

**常用安全函數**:
- 系統調用: `read()`, `write()`, `_exit()`, `kill()`, `raise()`
- 信號操作: `signal()`, `sigaction()`, `sigprocmask()`
- 時間: `clock_gettime()`, `time()`
- 文件操作: `open()`, `close()`, `dup()`, `fcntl()`

**完整列表**: `man 7 signal-safety`

## 3. sigaction - 現代信號處理

### 3.1 sigaction vs signal

**函數簽名**:
```cpp
#include <signal.h>

int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);

// 信號集操作
int sigemptyset(sigset_t *set);
int sigfillset(sigset_t *set);
int sigaddset(sigset_t *set, int signum);
int sigdelset(sigset_t *set, int signum);
int sigismember(const sigset_t *set, int signum);
```

**參數說明 (sigaction)**:
- `signum`: 信號編號 (如 SIGINT, SIGTERM)
- `act`: 新的信號處理動作 (NULL 表示僅查詢)
- `oldact`: 保存舊的信號處理動作 (NULL 表示不保存)

**struct sigaction 結構**:
```cpp
struct sigaction {
    void (*sa_handler)(int);              // 簡單處理函數
    void (*sa_sigaction)(int, siginfo_t*, void*);  // 詳細處理函數
    sigset_t sa_mask;                     // 處理期間要阻塞的信號
    int sa_flags;                         // 標誌:
                                          //   SA_SIGINFO: 使用 sa_sigaction
                                          //   SA_RESTART: 自動重啟被中斷的系統調用
                                          //   SA_NODEFER: 不自動阻塞該信號
};
```

**siginfo_t 結構** (簡化版):
```cpp
typedef struct {
    int si_signo;     // 信號編號
    int si_code;      // 信號原因
    pid_t si_pid;     // 發送進程的 PID
    uid_t si_uid;     // 發送進程的 UID
    void *si_addr;    // 故障地址 (SIGSEGV, SIGBUS)
} siginfo_t;
```

**返回值**:
- 成功: 返回 0
- 失敗: 返回 -1,並設置 `errno`

**⭐⭐⭐ sigaction** 提供更強大和可預測的信號處理:

```cpp
#include <signal.h>
#include <cstring>
#include <iostream>
#include <atomic>

std::atomic<bool> g_shutdown{false};

class SignalHandler {
public:
    using HandlerFunc = void(*)(int, siginfo_t*, void*);
    
    // 註冊信號處理器
    static bool register_handler(int signum, HandlerFunc handler) {
        struct sigaction sa;
        std::memset(&sa, 0, sizeof(sa));
        
        sa.sa_sigaction = handler;
        sa.sa_flags = SA_SIGINFO;  // 使用 sa_sigaction
        sigemptyset(&sa.sa_mask);
        
        return sigaction(signum, &sa, nullptr) == 0;
    }
    
    // 阻塞信號
    static bool block_signal(int signum) {
        sigset_t set;
        sigemptyset(&set);
        sigaddset(&set, signum);
        return sigprocmask(SIG_BLOCK, &set, nullptr) == 0;
    }
    
    // 解除阻塞
    static bool unblock_signal(int signum) {
        sigset_t set;
        sigemptyset(&set);
        sigaddset(&set, signum);
        return sigprocmask(SIG_UNBLOCK, &set, nullptr) == 0;
    }
};

// 詳細的信號處理器
void detailed_handler(int signum, siginfo_t* info, void* context) {
    const char* sig_name = "UNKNOWN";
    if (signum == SIGINT) sig_name = "SIGINT";
    else if (signum == SIGTERM) sig_name = "SIGTERM";
    
    char buffer[128];
    int len = snprintf(buffer, sizeof(buffer), 
                       "Received %s from PID %d\n", 
                       sig_name, info->si_pid);
    write(STDERR_FILENO, buffer, len);
    
    g_shutdown.store(true);
}

void example_sigaction() {
    SignalHandler::register_handler(SIGINT, detailed_handler);
    SignalHandler::register_handler(SIGTERM, detailed_handler);
    
    std::cout << "Waiting for signals...\n";
    
    while (!g_shutdown.load()) {
        sleep(1);
    }
    
    std::cout << "Shutting down\n";
}
```

## 4. signalfd - 同步信號處理

### 4.1 signalfd 概念

**函數簽名**:
```cpp
#include <sys/signalfd.h>

int signalfd(int fd, const sigset_t *mask, int flags);
```

**參數說明**:
- `fd`: 現有的 signalfd 描述符 (初次調用傳 -1)
- `mask`: 要監聽的信號集合
- `flags`: 標誌:
  - `SFD_NONBLOCK`: 非阻塞模式
  - `SFD_CLOEXEC`: exec 時關閉

**返回值**:
- 成功: 返回文件描述符
- 失敗: 返回 -1,並設置 `errno`

**struct signalfd_siginfo 結構**:
```cpp
struct signalfd_siginfo {
    uint32_t ssi_signo;    // 信號編號
    int32_t  ssi_errno;    // 錯誤編號
    int32_t  ssi_code;     // 信號代碼
    uint32_t ssi_pid;      // 發送進程 PID
    uint32_t ssi_uid;      // 發送進程 UID
    // ... 其他欄位
};
```

**使用方式**:
1. 使用 sigprocmask 阻塞要監聽的信號
2. 創建 signalfd
3. 通過 read() 讀取信號信息 (返回 struct signalfd_siginfo)
4. 可與 epoll 整合

**⭐⭐⭐ signalfd()** 將信號轉換為可讀取的文件描述符,使信號處理可以整合到 `epoll` 事件循環中。

**為什麼需要 signalfd?**

傳統信號處理有諸多問題:
1. **異步性**: 信號可能在任何時刻中斷程序執行
2. **重入問題**: 信號處理函數中只能調用異步信號安全的函數
3. **競態條件**: 信號與主程序之間的數據共享需要特殊處理

**signalfd 優勢**:
- 信號通過 `read()` 同步讀取
- 可以與 `epoll` 一起監控
- 在主事件循環中統一處理
- 無需考慮信號安全性

### 4.2 signalfd 實現

**epoll 相關函數**:
```cpp
#include <sys/epoll.h>

// 創建 epoll 實例
int epoll_create1(int flags);  // flags: 0 或 EPOLL_CLOEXEC

// 控制 epoll 實例
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
// op: EPOLL_CTL_ADD (添加), EPOLL_CTL_MOD (修改), EPOLL_CTL_DEL (刪除)

// 等待事件
int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);

// struct epoll_event 結構
struct epoll_event {
    uint32_t events;    // 事件類型: EPOLLIN, EPOLLOUT, EPOLLERR, EPOLLHUP 等
    epoll_data_t data;  // 用戶數據
};

typedef union epoll_data {
    void *ptr;
    int fd;
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;
```

**返回值**:
- epoll_create1: 成功返回 epoll fd,失敗返回 -1
- epoll_ctl: 成功返回 0,失敗返回 -1
- epoll_wait: 成功返回就緒的 fd 數量,0 表示超時,-1 表示錯誤

```cpp
#include <sys/signalfd.h>
#include <sys/epoll.h>
#include <signal.h>
#include <unistd.h>
#include <iostream>

class SignalFD {
    int sfd_;
    
public:
    SignalFD() : sfd_(-1) {}
    
    bool init(const std::vector<int>& signals) {
        // 阻塞這些信號 (避免默認處理)
        sigset_t mask;
        sigemptyset(&mask);
        for (int sig : signals) {
            sigaddset(&mask, sig);
        }
        sigprocmask(SIG_BLOCK, &mask, nullptr);
        
        // 創建 signalfd
        sfd_ = signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);
        return sfd_ >= 0;
    }
    
    // 讀取信號 (非阻塞)
    bool read_signal(int& signum) {
        struct signalfd_siginfo si;
        ssize_t n = read(sfd_, &si, sizeof(si));
        
        if (n == sizeof(si)) {
            signum = si.ssi_signo;
            return true;
        }
        return false;
    }
    
    int fd() const { return sfd_; }
    
    ~SignalFD() {
        if (sfd_ >= 0) close(sfd_);
    }
};

// 使用範例: 與 epoll 整合
void example_signalfd_epoll() {
    SignalFD sigfd;
    sigfd.init({SIGINT, SIGTERM});
    
    int epfd = epoll_create1(0);
    
    struct epoll_event ev;
    ev.events = EPOLLIN;
    ev.data.fd = sigfd.fd();
    epoll_ctl(epfd, EPOLL_CTL_ADD, sigfd.fd(), &ev);
    
    std::cout << "等待信號 (可與其他 I/O 一起處理)...\n";
    
    while (true) {
        struct epoll_event events[10];
        int nfds = epoll_wait(epfd, events, 10, -1);
        
        for (int i = 0; i < nfds; ++i) {
            if (events[i].data.fd == sigfd.fd()) {
                int signum;
                if (sigfd.read_signal(signum)) {
                    std::cout << "收到信號: " << signum << "\n";
                    if (signum == SIGINT || signum == SIGTERM) {
                        goto cleanup;
                    }
                }
            }
        }
    }
    
cleanup:
    close(epfd);
    std::cout << "優雅關閉\n";
}
```

## 5. 高精度計時

### 5.1 clock_gettime()

**函數簽名**:
```cpp
#include <time.h>

int clock_gettime(clockid_t clk_id, struct timespec *tp);
int clock_getres(clockid_t clk_id, struct timespec *res);
int clock_settime(clockid_t clk_id, const struct timespec *tp);
```

**參數說明**:
- `clk_id`: 時鐘類型 (見下方說明)
- `tp`: 指向 `struct timespec` 的指標
- `res`: 時鐘解析度 (最小時間單位)

**返回值**:
- 成功: 返回 0
- 失敗: 返回 -1,並設置 `errno`

**struct timespec 結構**:
```cpp
struct timespec {
    time_t tv_sec;   // 秒 (從 Epoch 或某個起點開始)
    long   tv_nsec;  // 納秒 (0-999,999,999)
};
```

**注意**: 使用 vDSO 優化時,clock_gettime 可能不產生系統調用,延遲僅 20-30 ns

**⭐⭐⭐ clock_gettime()** 提供納秒級精度的時間獲取,是 HFT 系統中延遲測量的標準方式。

**時鐘類型 (clk_id)**:

| 時鐘 | 說明 | 起始點 | 是否受 NTP 影響 | HFT 用途 |
|------|------|--------|----------------|----------|
| `CLOCK_REALTIME` | 系統實時時間 (Wall Clock) | 1970-01-01 00:00:00 UTC | 是 (會跳變) | 時間戳記錄、日誌 |
| **`CLOCK_MONOTONIC`** | 單調遞增時間,不受系統時間調整影響 | 系統啟動 | 否 (但會調速) | **延遲測量 (推薦)** |
| `CLOCK_MONOTONIC_RAW` | 完全不受調整的單調時間 | 系統啟動 | 否 (完全不調整) | 精確性能分析 |
| `CLOCK_BOOTTIME` | 包含休眠時間的單調時間 | 系統啟動 | 否 | 跨休眠的時間測量 |
| `CLOCK_PROCESS_CPUTIME_ID` | 當前進程的 CPU 時間 | 進程啟動 | 不適用 | 進程 CPU 使用分析 |
| `CLOCK_THREAD_CPUTIME_ID` | 當前線程的 CPU 時間 | 線程啟動 | 不適用 | 線程性能分析 |

**時鐘選擇建議**:
- **延遲測量**: 使用 `CLOCK_MONOTONIC` (保證單調遞增,不會倒退)
- **絕對時間戳**: 使用 `CLOCK_REALTIME` (可以轉換為人類可讀時間)
- **精確基準測試**: 使用 `CLOCK_MONOTONIC_RAW` (不受 NTP 微調影響)
- **CPU 性能分析**: 使用 `CLOCK_PROCESS_CPUTIME_ID` 或 `CLOCK_THREAD_CPUTIME_ID`

**⭐⭐⭐ CLOCK_REALTIME vs CLOCK_MONOTONIC**:

- **CLOCK_REALTIME**: 
  - 表示真實世界的時間 (1970-01-01 以來的秒數)
  - 可能因 NTP 同步或手動調整而跳變
  - 用於記錄事件發生的絕對時間

- **CLOCK_MONOTONIC**:
  - 從某個未指定的起點開始單調遞增
  - 不會跳變,只會單調增加
  - **測量時間間隔必須使用此時鐘**

### 5.2 使用 clock_gettime()

```cpp
#include <time.h>
#include <iostream>
#include <cstdint>

// 獲取納秒級時間戳
uint64_t get_timestamp_ns() {
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000000000ULL + ts.tv_nsec;
}

// 獲取實時時間
uint64_t get_realtime_ns() {
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    return ts.tv_sec * 1000000000ULL + ts.tv_nsec;
}

// 測量操作延遲
void measure_latency() {
    struct timespec start, end;
    
    clock_gettime(CLOCK_MONOTONIC, &start);
    
    // 執行一些操作
    volatile int x = 0;
    for (int i = 0; i < 1000000; ++i) {
        x += i;
    }
    
    clock_gettime(CLOCK_MONOTONIC, &end);
    
    // 計算時間差
    long elapsed_ns = (end.tv_sec - start.tv_sec) * 1000000000L 
                    + (end.tv_nsec - start.tv_nsec);
    
    std::cout << "Elapsed: " << elapsed_ns << " ns\n";
    std::cout << "Elapsed: " << elapsed_ns / 1000.0 << " us\n";
}

// 查看時鐘解析度
void print_clock_resolution() {
    struct timespec res;
    
    clock_getres(CLOCK_REALTIME, &res);
    std::cout << "CLOCK_REALTIME resolution: " 
              << res.tv_nsec << " ns\n";
    
    clock_getres(CLOCK_MONOTONIC, &res);
    std::cout << "CLOCK_MONOTONIC resolution: " 
              << res.tv_nsec << " ns\n";
}
```

### 5.3 HFT 延遲測量類

**⭐⭐⭐ 生產級實現**:

```cpp
#include <time.h>
#include <cstdint>
#include <iostream>

class LatencyTimer {
public:
    LatencyTimer() {
        reset();
    }
    
    void reset() {
        clock_gettime(CLOCK_MONOTONIC, &start_);
    }
    
    // 獲取經過的納秒數
    uint64_t elapsed_ns() const {
        struct timespec now;
        clock_gettime(CLOCK_MONOTONIC, &now);
        
        return (now.tv_sec - start_.tv_sec) * 1000000000ULL
             + (now.tv_nsec - start_.tv_nsec);
    }
    
    // 獲取經過的微秒數
    double elapsed_us() const {
        return elapsed_ns() / 1000.0;
    }
    
    // 打印經過時間
    void print_elapsed(const char* label) const {
        std::cout << label << ": " << elapsed_us() << " us\n";
    }
    
private:
    struct timespec start_;
};

// 使用範例
void example_latency_timer() {
    LatencyTimer timer;
    
    // 執行操作
    volatile int sum = 0;
    for (int i = 0; i < 1000000; ++i) {
        sum += i;
    }
    
    timer.print_elapsed("計算延遲");
}
```

## 6. timerfd - 定時器文件描述符

### 6.1 timerfd 概念

**⭐⭐⭐ timerfd** 將定時器封裝為文件描述符,可以與 `epoll` 整合,實現高效的定時任務。

**傳統定時器的問題**:
- `sleep()/usleep()`: 阻塞整個線程
- `alarm()`: 只能設置一個定時器,精度為秒
- `setitimer()`: 通過信號通知,有異步處理的所有問題

**⭐⭐⭐ timerfd 的優勢**:
1. 可以創建多個獨立的定時器
2. 納秒級精度
3. 與 epoll 整合,實現統一的事件處理
4. 同步讀取,無競態條件

### 6.2 timerfd 使用

**函數簽名**:
```cpp
#include <sys/timerfd.h>

int timerfd_create(int clockid, int flags);
int timerfd_settime(int fd, int flags, 
                    const struct itimerspec *new_value,
                    struct itimerspec *old_value);
int timerfd_gettime(int fd, struct itimerspec *curr_value);
```

**參數說明 (timerfd_create)**:
- `clockid`: 時鐘類型:
  - `CLOCK_REALTIME`: 實時時鐘
  - `CLOCK_MONOTONIC`: 單調時鐘 (推薦)
- `flags`: 標誌:
  - `TFD_NONBLOCK`: 非阻塞模式
  - `TFD_CLOEXEC`: exec 時關閉

**參數說明 (timerfd_settime)**:
- `fd`: timerfd 文件描述符
- `flags`: 
  - `0`: new_value 是相對時間
  - `TFD_TIMER_ABSTIME`: new_value 是絕對時間
- `new_value`: 新的定時器設置
- `old_value`: 保存舊的設置 (NULL 表示不保存)

**struct itimerspec 結構**:
```cpp
struct itimerspec {
    struct timespec it_interval;  // 周期間隔 (0 表示一次性定時器)
    struct timespec it_value;     // 首次觸發時間 (0 表示停止定時器)
};
```

**返回值**:
- timerfd_create: 成功返回文件描述符,失敗返回 -1
- timerfd_settime/gettime: 成功返回 0,失敗返回 -1

**讀取行為**:
- 定時器到期時,fd 變為可讀
- read() 返回 8 字節的 uint64_t,表示到期次數

**工作機制**:
1. 定時器到期時,FD 變為可讀
2. `read()` 返回到期次數 (8 字節 uint64_t)
3. 如果多次到期未讀取,次數會累加

```cpp
#include <sys/timerfd.h>
#include <sys/epoll.h>
#include <unistd.h>
#include <iostream>
#include <cstdint>

void example_timerfd() {
    // 創建定時器
    int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK);
    if (tfd < 0) {
        perror("timerfd_create");
        return;
    }
    
    // 設置定時器: 首次 1 秒後觸發,之後每 500ms 觸發
    struct itimerspec its;
    its.it_value.tv_sec = 1;      // 首次延遲
    its.it_value.tv_nsec = 0;
    its.it_interval.tv_sec = 0;   // 周期
    its.it_interval.tv_nsec = 500000000;  // 500ms
    
    timerfd_settime(tfd, 0, &its, nullptr);
    
    // 與 epoll 整合
    int epfd = epoll_create1(0);
    struct epoll_event ev;
    ev.events = EPOLLIN;
    ev.data.fd = tfd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, tfd, &ev);
    
    std::cout << "Timer started...\n";
    
    struct epoll_event events[10];
    int count = 0;
    
    while (count < 5) {
        int n = epoll_wait(epfd, events, 10, -1);
        
        for (int i = 0; i < n; ++i) {
            if (events[i].data.fd == tfd) {
                uint64_t expirations;
                read(tfd, &expirations, sizeof(expirations));
                
                std::cout << "Timer expired! Count: " << ++count 
                          << ", Expirations: " << expirations << "\n";
            }
        }
    }
    
    close(tfd);
    close(epfd);
}
```

### 6.3 HFT 周期任務

**⭐⭐⭐ 生產級實現**:

```cpp
#include <sys/timerfd.h>
#include <unistd.h>
#include <iostream>

class PeriodicTask {
    int tfd_;
    
public:
    PeriodicTask(int interval_ms) {
        tfd_ = timerfd_create(CLOCK_MONOTONIC, 0);
        
        struct itimerspec its;
        its.it_value.tv_sec = interval_ms / 1000;
        its.it_value.tv_nsec = (interval_ms % 1000) * 1000000;
        its.it_interval = its.it_value;
        
        timerfd_settime(tfd_, 0, &its, nullptr);
    }
    
    ~PeriodicTask() {
        if (tfd_ >= 0) close(tfd_);
    }
    
    void wait() {
        uint64_t expirations;
        read(tfd_, &expirations, sizeof(expirations));
    }
    
    int fd() const { return tfd_; }
};

// 使用範例: 定期統計
void example_periodic_stats() {
    PeriodicTask stats_timer(1000);  // 每秒
    
    for (int i = 0; i < 10; ++i) {
        stats_timer.wait();
        std::cout << "統計更新 " << i << "\n";
    }
}
```

## 7. RDTSC - CPU 時間戳計數器

### 7.1 RDTSC 原理

**⭐⭐⭐ RDTSC (Read Time-Stamp Counter)** 直接讀取 CPU 的硬件計數器,是最低延遲的計時方式。

**什麼是 TSC?**

**TSC (Time-Stamp Counter)** 是 x86/x64 CPU 中的一個 64 位寄存器,在每個 CPU 時鐘周期遞增。例如,3 GHz 的 CPU 每秒遞增 3×10^9 次。

**優勢**:
- **極低開銷**: 只需幾個 CPU 周期 (~20 cycles),相比 `clock_gettime()` 的 ~100 cycles
- **高精度**: 周期級精度,約 0.3ns@3GHz
- **無系統調用**: 完全在用戶態執行

**注意事項**:
1. **頻率校準**: TSC 計數的是周期數,需要知道 CPU 頻率才能轉換為時間
2. **多核同步**: 現代 CPU (Invariant TSC) 保證所有核心的 TSC 同步
3. **頻率變化**: 需要 Constant TSC 或 Invariant TSC 支持,否則會因省電模式而變化
4. **指令重排**: 使用 `rdtscp` 或配合內存屏障確保測量準確

**RDTSC vs RDTSCP**:

| 指令 | 特性 | 用途 |
|------|------|------|
| `rdtsc` | 可能被亂序執行 | 一般計時 |
| **`rdtscp`** | 序列化,等待之前的指令完成 | **精確延遲測量 (推薦)** |

### 7.2 使用 RDTSC

**檢查 TSC 特性**:
```bash
# 檢查 CPU 是否支持 constant_tsc 和 nonstop_tsc
grep -E 'constant_tsc|nonstop_tsc' /proc/cpuinfo

# constant_tsc: TSC 頻率不變 (不受 CPU 頻率變化影響)
# nonstop_tsc: TSC 在 C-state (省電模式) 下繼續運行
# rdtscp: 支持 RDTSCP 指令 (序列化的 TSC 讀取)
```

**內建函數**:
```cpp
#include <x86intrin.h>

// RDTSC - 讀取時間戳計數器
uint64_t __rdtsc(void);

// RDTSCP - 序列化的 RDTSC (等待之前的指令完成)
uint64_t __rdtscp(unsigned int *aux);

// CPUID - CPU 識別 (可用作序列化指令)
void __cpuid(int info[4], int function_id);
```

**函數說明**:
- `__rdtsc()`: 
  - 讀取 64 位 TSC 值
  - 可能被亂序執行 (不精確)
  - 延遲: ~20 CPU cycles
  
- `__rdtscp(unsigned int *aux)`:
  - 序列化的 TSC 讀取
  - 等待所有之前的指令完成後才讀取
  - `aux` 返回 CPU 編號和 NUMA 節點信息
  - 延遲: ~25 CPU cycles
  - **推薦用於精確測量**

**TSC 值轉換**:
```
時間 (秒) = TSC 差值 / CPU 頻率 (Hz)
時間 (納秒) = (TSC 差值 * 1,000,000,000) / CPU 頻率 (Hz)
```

```cpp
#include <x86intrin.h>
#include <time.h>
#include <iostream>
#include <cstdint>

// 讀取 TSC
inline uint64_t rdtsc() {
    return __rdtsc();
}

// 帶序列化的 RDTSC (更精確)
inline uint64_t rdtscp() {
    unsigned int aux;
    return __rdtscp(&aux);
}

// 獲取 TSC 頻率 (需要校準)
double calibrate_tsc_frequency() {
    struct timespec start, end;
    
    clock_gettime(CLOCK_MONOTONIC, &start);
    uint64_t tsc_start = rdtsc();
    
    // 等待一段時間
    struct timespec delay = {0, 100000000};  // 100ms
    nanosleep(&delay, nullptr);
    
    clock_gettime(CLOCK_MONOTONIC, &end);
    uint64_t tsc_end = rdtsc();
    
    // 計算頻率
    long elapsed_ns = (end.tv_sec - start.tv_sec) * 1000000000L 
                    + (end.tv_nsec - start.tv_nsec);
    uint64_t tsc_diff = tsc_end - tsc_start;
    
    return (double)tsc_diff / elapsed_ns;  // cycles per ns
}

void example_rdtsc() {
    double cycles_per_ns = calibrate_tsc_frequency();
    std::cout << "TSC frequency: " << cycles_per_ns << " cycles/ns\n";
    std::cout << "TSC frequency: " << cycles_per_ns * 1000 << " MHz\n";
    
    // 測量操作延遲
    uint64_t start = rdtscp();
    
    // 執行操作
    volatile int x = 0;
    for (int i = 0; i < 1000; ++i) {
        x += i;
    }
    
    uint64_t end = rdtscp();
    uint64_t cycles = end - start;
    double ns = cycles / cycles_per_ns;
    
    std::cout << "Elapsed: " << cycles << " cycles\n";
    std::cout << "Elapsed: " << ns << " ns\n";
}
```

### 7.3 HFT 延遲測量類

**⭐⭐⭐ 生產級 RDTSC 計時器**:

```cpp
#include <x86intrin.h>
#include <time.h>
#include <iostream>

class TSCTimer {
public:
    TSCTimer() : cycles_per_ns_(calibrate_tsc_frequency()), start_(0) {}
    
    void start() {
        start_ = __rdtscp(&aux_);
    }
    
    uint64_t stop_cycles() {
        return __rdtscp(&aux_) - start_;
    }
    
    double stop_ns() {
        return stop_cycles() / cycles_per_ns_;
    }
    
    double stop_us() {
        return stop_ns() / 1000.0;
    }
    
private:
    double cycles_per_ns_;
    uint64_t start_;
    unsigned int aux_;
    
    static double calibrate_tsc_frequency() {
        struct timespec start, end;
        
        clock_gettime(CLOCK_MONOTONIC, &start);
        uint64_t tsc_start = __rdtsc();
        
        struct timespec delay = {0, 100000000};  // 100ms
        nanosleep(&delay, nullptr);
        
        clock_gettime(CLOCK_MONOTONIC, &end);
        uint64_t tsc_end = __rdtsc();
        
        long elapsed_ns = (end.tv_sec - start.tv_sec) * 1000000000L 
                        + (end.tv_nsec - start.tv_nsec);
        
        return (double)(tsc_end - tsc_start) / elapsed_ns;
    }
};

// 使用範例
void example_tsc_timer() {
    TSCTimer timer;
    
    timer.start();
    
    // 執行關鍵路徑
    volatile int sum = 0;
    for (int i = 0; i < 100; ++i) {
        sum += i;
    }
    
    std::cout << "延遲: " << timer.stop_ns() << " ns\n";
}
```

## 8. HFT 實戰: 完整信號與計時系統

### 8.1 優雅關閉系統

**⭐⭐⭐ 生產級實現**:

```cpp
#include <signal.h>
#include <thread>
#include <vector>
#include <atomic>
#include <iostream>

class GracefulShutdown {
    std::atomic<bool> shutdown_{false};
    std::vector<std::thread> threads_;
    
public:
    void initialize() {
        // 阻塞所有線程的信號
        sigset_t mask;
        sigfillset(&mask);
        pthread_sigmask(SIG_BLOCK, &mask, nullptr);
        
        // 啟動工作線程
        for (int i = 0; i < 4; ++i) {
            threads_.emplace_back([this, i]() {
                this->worker_thread(i);
            });
        }
        
        // 主線程處理信號
        signal_handler_thread();
    }
    
private:
    void worker_thread(int id) {
        std::cout << "Worker " << id << " 啟動\n";
        
        while (!shutdown_.load(std::memory_order_acquire)) {
            // 處理任務...
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
        }
        
        std::cout << "Worker " << id << " 關閉\n";
    }
    
    void signal_handler_thread() {
        // 只在主線程處理信號
        sigset_t mask;
        sigemptyset(&mask);
        sigaddset(&mask, SIGINT);
        sigaddset(&mask, SIGTERM);
        
        int sig;
        sigwait(&mask, &sig);  // 阻塞等待信號
        
        std::cout << "\n收到停止信號,關閉中...\n";
        shutdown_.store(true, std::memory_order_release);
        
        // 等待所有工作線程結束
        for (auto& t : threads_) {
            if (t.joinable()) t.join();
        }
        
        std::cout << "所有線程已關閉\n";
    }
};
```
