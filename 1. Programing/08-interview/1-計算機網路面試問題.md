### 網路基礎與核心協定

###### Q1: 描述 IP 數據包的基本結構，以及 IP 報頭中的 **TTL** 字段的作用。

一個 IP 數據包（Packet）主要由兩部分組成：
1. **IP Header：** 包含所有關於路由和傳輸的控制信息，長度通常是 20 個字節（bytes），除非包含選項 (Options)。
	e.g. Source Address, Destination Address, TTL, Protocol (6: TCP, 17: UDP), Header CheckSum, Total Length
2. **Payload：** 承載高層協議（如 TCP、UDP 或 ICMP）的數據，以及應用層的實際信息（例如，HFT 中的訂單/行情數據）。

**TTL (Time To Live)** 是一個 8 位的字段，有兩個主要作用:
1. 防止數據包在網路中無限循環 (Loop Prevention)：
	- 當數據包從源主機發出時，TTL 會被設置一個初始值（如 64、128 或 255）。
	- 每當數據包經過一個**路由器 (Router)** 時，路由器會將 **TTL 值減 1**。
	- 如果 **TTL 減至 0**，路由器會丟棄該數據包，並通常向發送方返回一個 ICMP **"Time Exceeded"** 錯誤消息。
2. 計算網路跳數 (Hop Count):
	traceroute 就是透過設定 TTL 來繪製完整路徑，發送方發送一個數據包，將 TTL 設置為 1，第一個路由器收到包後，TTL 減為 0，路由器丟棄並發回 **"Time Exceeded"** 消息（從而知道第一跳的地址）。接著，發送方發送另一個數據包，將 **TTL 設置為 2**。重複此過程。

###### Q2: 詳細解釋 **TCP** 和 **UDP** 的報文結構的主要區別。
> 在 HFT 中 UDP 用於行情廣播，TCP 用於訂單確認

1. UDP 報文結構 (User Datagram Protocol Header): UDP 追求**簡單、快速和無連接**。它的報文結構極度精簡，僅包含 8 個字節的報頭。

| 字段名稱                    | 佔用比特位   | 描述                            |
| ----------------------- | ------- | ----------------------------- |
| 源端口 (Source Port)       | 16 bits | 發送方應用程序的端口號。                  |
| 目的端口 (Destination Port) | 16 bits | 接收方應用程序的端口號。                  |
| 長度 (Length)             | 16 bits | 整個 UDP 數據包（報頭 + 數據）的總長度。      |
| 校驗和 (Checksum)          | 16 bits | 用於檢測數據包在傳輸過程中是否有損壞。**它是可選的。** |


2. TCP 報文結構 (Transmission Control Protocol Header): TCP 追求**可靠性、有序性和流量控制**。它的報文結構比 UDP 複雜得多，標準報頭長度至少為 20 個字節。

| 字段名稱                               | 佔用比特位   | 描述                                                   |
| ---------------------------------- | ------- | ---------------------------------------------------- |
| 源端口 (Source Port)                  | 16 bits | 發送方應用程序的端口號。                                         |
| 目的端口 (Destination Port)            | 16 bits | 接收方應用程序的端口號。                                         |
| 序號 (Sequence Number)               | 32 bits | **核心字段。** 用於標識本報文段第一個數據字節的序號，確保數據的**有序性**。           |
| 確認號 (Acknowledgement Number)       | 32 bits | **核心字段。** 期望收到對方下一個數據報文段的第一個字節的序號，用於實現**可靠性**。       |
| 報頭長度 (Header Length / Data Offset) | 4 bits  | 報頭的長度，以 4 字節為單位（類似 IP 報頭的 IHL）。                      |
| 保留位 (Reserved)                     | 6 bits  | 暫時保留。                                                |
| 標誌位 (Flags / Control Bits)         | 6 bits  | **核心字段。** 如 SYN, ACK, FIN, RST 等，用於建立、維護和終止連接。       |
| 窗口大小 (Window Size)                 | 16 bits | **核心字段。** 用於**流量控制**，告知對方自己還能接收多少字節的數據。              |
| 校驗和 (Checksum)                     | 16 bits | 用於檢測數據包的錯誤。**它是必需的。**                                |
| 緊急指針 (Urgent Pointer)              | 16 bits | 當 URG 標誌位設置時，指向緊急數據的結束位置。                            |
| 選項 (Options)                       | 變長      | 如 MSS (Maximum Segment Size)、SACK (Selective ACK) 等。 |

| 標誌位 | 全稱 (Full Name)  | 作用                                                    |
| --- | --------------- | ----------------------------------------------------- |
| URG | Urgent          | 緊急數據標誌。                                               |
| ACK | Acknowledgement | **確認標誌。** 表示報頭中的 $\text{ACK Number}$ 字段是有效的。這是最常用的標誌。 |
| PSH | Push            | 推送標誌。要求接收方立即將數據傳遞給應用層，不等待緩衝區滿。                        |
| RST | Reset           | **重置連接。** 用於異常關閉連接或拒絕一個連接請求。                          |
| SYN | Synchronize     | **同步序列號。** 用於**建立連接**（三次握手）。                          |
| FIN | Finish          | **終止發送。** 用於**關閉連接**（四次揮手）。                           |

Q6: 什麼是 **Nagle 算法**？它在高頻交易中有何缺點？如何在 C++ Socket 編程中禁用它？

當你調用 `send()` 時，數據會被複製到**TCP 的發送緩衝區 (Send Buffer)** 裡。
- **如果緩衝區數據很少：** TCP 不會立刻發送。為了效率，它通常會等待一小段時間，看是否有更多數據進來，這是為了避免發送許多只包含幾個位元組的小報文（這會產生大量的協議開銷）。這個機制就是著名的 **Nagle 演算法**。
- **Nagle 演算法的規則：**
    - TCP 只有在以下兩種情況下會發送數據：
        1. 發送緩衝區內的數據量達到**最大報文段大小 (MSS)**。
        2. 所有先前發送的數據都已被確認 (ACKed)。
    - 這優化了網路的利用率，但可能會輕微增加延遲。

> MSS 是指 **單個 TCP 報文段 (Segment) 中，** 可以承載的**應用層數據**的最大位元組數。
>- **決定因素：** MSS 主要是由底層網路的 **MTU (Maximum Transmission Unit)** 決定的。
>    - MSS=MTU−(IP Header Size)−(TCP Header Size)
>    - 在最常見的乙太網中，MTU 是 1500 位元組。標準的 IP 和 TCP 頭部各佔 20 位元組。所以 MSS 通常是 1500−20−20=1460 位元組。
