## wrk

### 命令說明

wrk 是現代化的 HTTP 基準測試工具,使用多線程和事件驅動架構,能產生大量負載。支援 Lua 腳本擴展。

**基本語法:**
```bash
wrk [options] <url>
```

### 常用選項

| 選項 | 說明 |
|------|------|
| `-t, --threads` | 線程數 |
| `-c, --connections` | 連接數 |
| `-d, --duration` | 測試時間 |
| `-s, --script` | Lua 腳本檔案 |
| `-H, --header` | 添加標頭 |
| `--timeout` | 請求超時時間 |
| `--latency` | 顯示延遲統計 |

### 使用場景

1. **API 效能測試**: 測試後端服務吞吐量
2. **基準測試**: 比較不同配置的效能
3. **容量規劃**: 評估系統最大負載
4. **回歸測試**: 確認優化效果

---

### 操作範例

#### 基本壓測

```bash
$ wrk -t12 -c400 -d30s http://localhost:8080/api/health

Running 30s test @ http://localhost:8080/api/health
  12 threads and 400 connections
  Thread Stats   Avg      Stdev     Max   +/- Stdev
    Latency    12.34ms   5.67ms  89.12ms   78.90%
    Req/Sec     2.70k   234.56     3.12k    75.00%
  972345 requests in 30.00s, 156.78MB read
Requests/sec:  32411.50
Transfer/sec:      5.23MB
```

**輸出說明:**
- `Latency`: 回應延遲統計 (平均、標準差、最大值)
- `Req/Sec`: 每秒每線程請求數
- `Requests/sec`: 總 QPS (每秒請求數)
- `Transfer/sec`: 每秒傳輸量

#### 顯示延遲分佈

```bash
$ wrk -t12 -c400 -d30s --latency http://localhost:8080/api/users

  Latency Distribution
     50%   10.23ms
     75%   15.67ms
     90%   23.45ms
     99%   45.67ms
```

**輸出說明:**
- `50%`: 中位數延遲
- `90%`: P90 延遲 (90% 請求低於此值)
- `99%`: P99 延遲 (重要效能指標)

#### 帶標頭的請求

```bash
$ wrk -t4 -c100 -d10s \
      -H "Authorization: Bearer TOKEN123" \
      -H "Content-Type: application/json" \
      http://localhost:8080/api/users
```

### Lua 腳本

#### POST 請求腳本

建立 `post.lua`:
```lua
wrk.method = "POST"
wrk.body   = '{"name": "test", "email": "test@example.com"}'
wrk.headers["Content-Type"] = "application/json"
```

執行:
```bash
$ wrk -t4 -c100 -d30s -s post.lua http://localhost:8080/api/users
```

#### 動態請求腳本

建立 `dynamic.lua`:
```lua
counter = 0

request = function()
    counter = counter + 1
    local path = "/api/users/" .. (counter % 1000)
    return wrk.format("GET", path)
end
```

#### 處理回應腳本

建立 `check_response.lua`:
```lua
response = function(status, headers, body)
    if status ~= 200 then
        print("Error: " .. status)
    end
end

done = function(summary, latency, requests)
    print("Total requests: " .. summary.requests)
    print("Errors: " .. summary.errors.status)
end
```

#### 認證腳本

建立 `auth.lua`:
```lua
token = "Bearer eyJhbGciOiJIUzI1NiIs..."

request = function()
    wrk.headers["Authorization"] = token
    return wrk.format("GET", "/api/protected")
end
```

### 實戰技巧

#### 漸進式負載測試

```bash
#!/bin/bash
for conn in 10 50 100 200 400; do
    echo "=== Testing with $conn connections ==="
    wrk -t4 -c$conn -d10s http://localhost:8080/api/health
    echo
    sleep 5
done
```

#### 比較不同端點

```bash
#!/bin/bash
endpoints=("/api/users" "/api/products" "/api/orders")

for ep in "${endpoints[@]}"; do
    echo "=== Testing $ep ==="
    wrk -t4 -c100 -d10s --latency "http://localhost:8080$ep"
    echo
done
```

## ab (Apache Bench)

### 命令說明

ab 是 Apache 內建的簡易 HTTP 壓測工具,輕量且易用,適合快速基準測試。

**基本語法:**
```bash
ab [options] <url>
```

### 常用選項

| 選項 | 說明 |
|------|------|
| `-n` | 總請求數 |
| `-c` | 併發數 |
| `-t` | 測試時間 (秒) |
| `-p` | POST 資料檔案 |
| `-T` | Content-Type |
| `-H` | 添加標頭 |
| `-A` | HTTP 基本認證 |
| `-k` | 啟用 Keep-Alive |
| `-g` | 輸出 gnuplot 格式 |
| `-e` | 輸出 CSV 格式 |

### 使用場景

1. **快速測試**: 簡單的效能檢查
2. **基準比較**: 前後效能對比
3. **入門測試**: 學習壓測概念

---

$ ab -n 1000 -c 50 -e results.csv http://localhost:8080/

## k6

### 命令說明

k6 是現代化的負載測試工具,使用 JavaScript 編寫測試腳本,提供豐富的指標和視覺化支援。

**基本語法:**
```bash
k6 run [options] <script.js>
```

### 常用選項

| 選項 | 說明 |
|------|------|
| `--vus` | 虛擬用戶數 |
| `--duration` | 測試時間 |
| `--iterations` | 總迭代數 |
| `--out` | 輸出格式 |

### 使用場景

1. **複雜場景測試**: 多步驟用戶流程
2. **API 測試**: 帶邏輯的 API 測試
3. **負載模式**: 漸進式、階梯式負載
4. **CI/CD 整合**: 自動化效能測試

---

### 操作範例

#### 基本腳本

建立 `test.js`:
```javascript
import http from 'k6/http';
import { sleep, check } from 'k6';

export default function () {
    const res = http.get('http://localhost:8080/api/health');
    
    check(res, {
        'status is 200': (r) => r.status === 200,
        'response time < 200ms': (r) => r.timings.duration < 200,
    });
    
    sleep(1);
}
```

#### POST 請求腳本

```javascript
import http from 'k6/http';
import { check } from 'k6';

export default function () {
    const url = 'http://localhost:8080/api/users';
    const payload = JSON.stringify({
        name: 'test',
        email: 'test@example.com'
    });
    
    const params = {
        headers: {
            'Content-Type': 'application/json',
            'Authorization': 'Bearer TOKEN123'
        }
    };
    
    const res = http.post(url, payload, params);
    
    check(res, {
        'status is 201': (r) => r.status === 201,
    });
}
```

#### 階梯式負載

```javascript
import http from 'k6/http';

export const options = {
    stages: [
        { duration: '30s', target: 10 },   // 爬升到 10 VUs
        { duration: '1m', target: 50 },    // 爬升到 50 VUs
        { duration: '30s', target: 100 },  // 爬升到 100 VUs
        { duration: '1m', target: 100 },   // 維持 100 VUs
        { duration: '30s', target: 0 },    // 降到 0
    ],
};

export default function () {
    http.get('http://localhost:8080/api/health');
}
```

#### 閾值設定

```javascript
export const options = {
    thresholds: {
        http_req_duration: ['p(95)<200'],  // 95% 請求 < 200ms
        http_req_failed: ['rate<0.01'],    // 錯誤率 < 1%
    },
};
```

## iperf3

### 命令說明

iperf3 是網路帶寬測試工具,用於測量 TCP/UDP 吞吐量,評估網路效能。

**基本語法:**
```bash
# 伺服器端
iperf3 -s [options]

# 客戶端
iperf3 -c <server> [options]
```

### 常用選項

| 選項 | 說明 |
|------|------|
| `-s` | 伺服器模式 |
| `-c` | 客戶端模式 |
| `-p` | 埠號 |
| `-t` | 測試時間 |
| `-P` | 並行連接數 |
| `-u` | UDP 模式 |
| `-b` | 目標帶寬 |
| `-R` | 反向測試 |
| `-J` | JSON 輸出 |
| `--bidir` | 雙向測試 |

### 使用場景

1. **網路帶寬測試**: 測量最大吞吐量
2. **網路品質評估**: 檢查延遲和丟包
3. **故障排查**: 診斷網路效能問題
4. **基準測試**: 網路設備效能比較

---

### 操作範例

#### 基本帶寬測試

伺服器端:
```bash
$ iperf3 -s

-----------------------------------------------------------
Server listening on 5201
-----------------------------------------------------------
```

客戶端:
```bash
$ iperf3 -c 192.168.1.100

Connecting to host 192.168.1.100, port 5201
[  5] local 192.168.1.50 port 54321 connected to 192.168.1.100 port 5201
[ ID] Interval           Transfer     Bitrate         Retr
[  5]   0.00-1.00   sec   112 MBytes   940 Mbits/sec    0
[  5]   1.00-2.00   sec   112 MBytes   941 Mbits/sec    0
...
[  5]   0.00-10.00  sec  1.09 GBytes   940 Mbits/sec    0       sender
[  5]   0.00-10.04  sec  1.09 GBytes   936 Mbits/sec            receiver

iperf Done.
```

**輸出說明:**
- `Transfer`: 傳輸資料量
- `Bitrate`: 帶寬 (Mbits/sec)
- `Retr`: TCP 重傳次數

#### 指定測試時間

```bash
$ iperf3 -c 192.168.1.100 -t 30
```

#### 多連接測試

```bash
$ iperf3 -c 192.168.1.100 -P 4
```

#### 反向測試 (伺服器發送)

```bash
$ iperf3 -c 192.168.1.100 -R
```

#### 雙向測試

```bash
$ iperf3 -c 192.168.1.100 --bidir
```

#### UDP 測試

```bash
$ iperf3 -c 192.168.1.100 -u -b 100M

[ ID] Interval           Transfer     Bitrate         Jitter    Lost/Total
[  5]   0.00-10.00  sec   119 MBytes   100 Mbits/sec  0.023 ms  0/86572 (0%)
```

**輸出說明:**
- `Jitter`: 抖動 (延遲變化)
- `Lost/Total`: 丟包數/總數

#### JSON 輸出

```bash
$ iperf3 -c 192.168.1.100 -J > result.json
```

## stress-ng

### 命令說明

stress-ng 是系統壓力測試工具,可對 CPU、記憶體、I/O 等資源產生負載,用於穩定性和極限測試。

**基本語法:**
```bash
stress-ng [options]
```

### 常用選項

| 選項 | 說明 |
|------|------|
| `--cpu` | CPU 壓力測試 |
| `--vm` | 記憶體壓力測試 |
| `--vm-bytes` | 記憶體大小 |
| `--io` | I/O 壓力測試 |
| `--hdd` | 磁碟壓力測試 |
| `--timeout` | 測試時間 |
| `--metrics` | 顯示指標 |

### 使用場景

1. **穩定性測試**: 系統長時間負載測試
2. **散熱測試**: 檢查散熱效能
3. **極限測試**: 找出系統瓶頸
4. **燒機測試**: 新硬體驗證

---

### 操作範例

#### CPU 壓力測試

```bash
$ stress-ng --cpu 4 --timeout 60s --metrics

stress-ng: info:  [12345] dispatching hogs: 4 cpu
stress-ng: info:  [12345] successful run completed in 60.00s
stress-ng: info:  [12345] stressor       bogo ops real time  usr time  sys time   bogo ops/s
stress-ng: info:  [12345] cpu              234567    60.00s    239.89s     0.12s     3909.45
```

**輸出說明:**
- `bogo ops`: 完成的操作數
- `bogo ops/s`: 每秒操作數

#### 記憶體壓力測試

```bash
$ stress-ng --vm 2 --vm-bytes 1G --timeout 60s
```

#### I/O 壓力測試

```bash
$ stress-ng --io 4 --timeout 60s
```

#### 磁碟壓力測試

```bash
$ stress-ng --hdd 2 --timeout 60s
```

#### 綜合壓力測試

```bash
$ stress-ng --cpu 4 --vm 2 --vm-bytes 1G --io 2 --timeout 300s --metrics
```

#### 指定 CPU 方法

```bash
$ stress-ng --cpu 4 --cpu-method matrixprod --timeout 60s
```

## 實戰技巧

### 壓測前檢查清單

```bash
#!/bin/bash
echo "=== Pre-test Checklist ==="

# 檢查目標服務
echo "1. Target service status:"
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/health

# 檢查系統資源
echo "2. System resources:"
free -h
df -h /

# 檢查連接數限制
echo "3. Connection limits:"
ulimit -n
sysctl net.core.somaxconn
```

### 壓測監控腳本

```bash
#!/bin/bash
# 在壓測時同時監控系統資源
while true; do
    echo "$(date): CPU: $(top -bn1 | grep 'Cpu(s)' | awk '{print $2}')"
    echo "$(date): MEM: $(free | grep Mem | awk '{print $3/$2 * 100.0}')"
    sleep 5
done
```

### 結果比較

```bash
#!/bin/bash
# 比較優化前後效能
echo "=== Before Optimization ===" > results.txt
wrk -t4 -c100 -d30s http://localhost:8080/api/users >> results.txt

# ... 進行優化 ...

echo "=== After Optimization ===" >> results.txt
wrk -t4 -c100 -d30s http://localhost:8080/api/users >> results.txt
```
