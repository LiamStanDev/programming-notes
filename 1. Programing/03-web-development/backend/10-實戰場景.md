## 場景一: API 開發與測試

### 問題描述
開發 RESTful API,需要測試各種請求、檢查回應、分析效能。

### 工具選擇
- **curl**: HTTP 請求測試
- **jq**: JSON 處理
- **nc**: 連接測試

### 完整流程

#### 1. 基本功能測試

```bash
# 健康檢查
$ curl -s http://localhost:8080/health | jq .
{
  "status": "healthy",
  "version": "1.0.0"
}

# GET 請求
$ curl -s http://localhost:8080/api/users | jq '.[] | {id, name}'

# POST 請求
$ curl -X POST http://localhost:8080/api/users \
    -H "Content-Type: application/json" \
    -d '{"name": "Alice", "email": "alice@example.com"}' | jq .

# PUT 請求
$ curl -X PUT http://localhost:8080/api/users/1 \
    -H "Content-Type: application/json" \
    -d '{"name": "Alice Updated"}' | jq .

# DELETE 請求
$ curl -X DELETE http://localhost:8080/api/users/1
```

#### 2. 認證測試

```bash
# 登入取得 token
$ TOKEN=$(curl -s -X POST http://localhost:8080/api/login \
    -H "Content-Type: application/json" \
    -d '{"username": "admin", "password": "secret"}' | jq -r '.token')

# 使用 token
$ curl -s http://localhost:8080/api/protected \
    -H "Authorization: Bearer $TOKEN" | jq .
```

#### 3. 效能測量

```bash
# 測量回應時間
$ curl -w "DNS:%{time_namelookup}s Connect:%{time_connect}s TTFB:%{time_starttransfer}s Total:%{time_total}s\n" \
    -o /dev/null -s http://localhost:8080/api/users

DNS:0.001s Connect:0.002s TTFB:0.045s Total:0.046s
```

#### 4. 批次測試腳本

```bash
#!/bin/bash
# test_api.sh

BASE_URL="http://localhost:8080"

echo "=== API Test Suite ==="

# Test 1: Health check
echo -n "Health check: "
STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$BASE_URL/health")
[ "$STATUS" -eq 200 ] && echo "PASS" || echo "FAIL ($STATUS)"

# Test 2: List users
echo -n "List users: "
STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$BASE_URL/api/users")
[ "$STATUS" -eq 200 ] && echo "PASS" || echo "FAIL ($STATUS)"

# Test 3: Create user
echo -n "Create user: "
RESULT=$(curl -s -X POST "$BASE_URL/api/users" \
    -H "Content-Type: application/json" \
    -d '{"name": "Test", "email": "test@example.com"}')
USER_ID=$(echo "$RESULT" | jq -r '.id')
[ -n "$USER_ID" ] && echo "PASS (ID: $USER_ID)" || echo "FAIL"

# Test 4: Get user
echo -n "Get user: "
STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$BASE_URL/api/users/$USER_ID")
[ "$STATUS" -eq 200 ] && echo "PASS" || echo "FAIL ($STATUS)"

# Test 5: Delete user
echo -n "Delete user: "
STATUS=$(curl -s -o /dev/null -w "%{http_code}" -X DELETE "$BASE_URL/api/users/$USER_ID")
[ "$STATUS" -eq 204 ] && echo "PASS" || echo "FAIL ($STATUS)"

echo "=== Test Complete ==="
```

## 場景二: 服務連接問題排查

### 問題描述
應用程式無法連接到資料庫或其他服務。

### 工具選擇
- **nc**: 埠測試
- **ss**: 連接狀態
- **dig**: DNS 查詢
- **tcpdump**: 封包分析

### 完整流程

#### 1. 基本連通性測試

```bash
# 測試埠是否開放
$ nc -zv db.example.com 3306
Connection to db.example.com 3306 port [tcp/mysql] succeeded!

# 如果失敗
$ nc -zv db.example.com 3306
nc: connect to db.example.com port 3306 (tcp) failed: Connection refused
```

#### 2. DNS 解析檢查

```bash
# 檢查 DNS 解析
$ dig +short db.example.com
192.168.1.100

# 如果解析失敗,檢查 DNS 設定
$ cat /etc/resolv.conf
$ dig @8.8.8.8 db.example.com
```

#### 3. 網路路徑分析

```bash
# 追蹤路由
$ mtr -r -c 10 db.example.com

# 檢查是否有丟包或高延遲
```

#### 4. 本地連接狀態

```bash
# 檢查本地是否有連接
$ ss -tn | grep 3306

# 檢查連接狀態
$ ss -tn state established '( dport = :3306 )'
```

#### 5. 封包分析

```bash
# 擷取連接嘗試
$ sudo tcpdump -i eth0 host db.example.com and port 3306

# 檢查 SYN 是否有回應
# SYN -> 無回應: 網路問題或防火牆
# SYN -> RST: 服務未啟動
# SYN -> SYN-ACK: 連接成功
```

#### 6. 完整診斷腳本

```bash
#!/bin/bash
# diagnose_connection.sh

HOST=${1:-db.example.com}
PORT=${2:-3306}

echo "=== Connection Diagnosis ==="
echo "Target: $HOST:$PORT"
echo

# 1. DNS
echo "1. DNS Resolution:"
IP=$(dig +short "$HOST" | head -1)
if [ -n "$IP" ]; then
    echo "   OK: $HOST -> $IP"
else
    echo "   FAIL: Cannot resolve $HOST"
    exit 1
fi

# 2. ICMP
echo "2. ICMP Connectivity:"
if ping -c 1 -W 2 "$HOST" >/dev/null 2>&1; then
    echo "   OK: Host is reachable"
else
    echo "   WARN: ICMP blocked or host unreachable"
fi

# 3. TCP
echo "3. TCP Port Test:"
if nc -z -w 5 "$HOST" "$PORT" 2>/dev/null; then
    echo "   OK: Port $PORT is open"
else
    echo "   FAIL: Port $PORT is closed or filtered"
    exit 1
fi

# 4. Route
echo "4. Network Path:"
traceroute -m 10 "$HOST" 2>/dev/null | tail -5

echo
echo "=== Diagnosis Complete ==="
```

## 場景三: 效能瓶頸定位

### 問題描述
服務回應緩慢,需要找出瓶頸在 CPU、記憶體、I/O 還是網路。

### 工具選擇
- **htop**: 即時監控
- **vmstat**: 系統統計
- **iostat**: I/O 統計
- **perf**: CPU 分析
- **ss**: 網路狀態

### 完整流程

#### 1. 整體概況

```bash
# 查看系統負載
$ uptime
 10:30:00 up 5 days,  3:45,  2 users,  load average: 8.15, 7.10, 6.05

# 負載 > CPU 核心數表示可能有瓶頸
$ nproc
4
```

#### 2. CPU 分析

```bash
# 查看 CPU 使用率
$ vmstat 1 5
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 8  0      0 1234567 102400 4194304  0    0     5    10  100  200 85  5  5  5  0

# 高 us (user) + 低 id (idle) = CPU 瓶頸
# 高 wa (iowait) = I/O 瓶頸

# 找出 CPU 大戶
$ ps aux --sort=-%cpu | head -10

# 使用 perf 分析
$ sudo perf top
```

#### 3. 記憶體分析

```bash
# 查看記憶體
$ free -h
              total        used        free      shared  buff/cache   available
Mem:           15Gi       12Gi       500Mi       100Mi        3Gi        2Gi

# available < 10% = 記憶體不足

# 檢查 swap 使用
$ vmstat 1
# si/so > 0 表示頻繁 swap

# 找出記憶體大戶
$ ps aux --sort=-%mem | head -10
```

#### 4. I/O 分析

```bash
# 查看磁碟 I/O
$ iostat -x 1 5

Device  %util  await
sda     98.5   150.2

# %util > 80% = 磁碟繁忙
# await > 20ms = 延遲高

# 找出 I/O 大戶
$ sudo iotop -o
```

#### 5. 網路分析

```bash
# 查看連接數
$ ss -s
TCP:   5000 (estab 4500, closed 200, orphaned 50, timewait 200)

# 查看網路流量
$ sar -n DEV 1 5

# 檢查網路錯誤
$ netstat -s | grep -i error
```

#### 6. 綜合診斷腳本

```bash
#!/bin/bash
# diagnose_performance.sh

echo "=== Performance Diagnosis ==="
echo "Time: $(date)"
echo

# Load
LOAD=$(uptime | awk -F'load average:' '{print $2}')
CPUS=$(nproc)
echo "Load Average:$LOAD (CPUs: $CPUS)"

# CPU
CPU_IDLE=$(vmstat 1 2 | tail -1 | awk '{print $15}')
echo "CPU Idle: ${CPU_IDLE}%"
if [ "$CPU_IDLE" -lt 20 ]; then
    echo "  -> WARNING: High CPU usage"
    echo "  Top CPU consumers:"
    ps aux --sort=-%cpu | head -5 | awk '{print "    " $11 " (" $3 "%)"}'
fi

# Memory
MEM_AVAIL=$(free -m | grep Mem | awk '{print $7}')
MEM_TOTAL=$(free -m | grep Mem | awk '{print $2}')
MEM_PERCENT=$((MEM_AVAIL * 100 / MEM_TOTAL))
echo "Memory Available: ${MEM_AVAIL}MB (${MEM_PERCENT}%)"
if [ "$MEM_PERCENT" -lt 10 ]; then
    echo "  -> WARNING: Low memory"
fi

# I/O
echo "Disk I/O:"
iostat -x 1 1 | grep -E "^sd|^nvme" | while read line; do
    UTIL=$(echo "$line" | awk '{print $NF}')
    DEV=$(echo "$line" | awk '{print $1}')
    echo "  $DEV: ${UTIL}% util"
done

echo
echo "=== Diagnosis Complete ==="
```

## 場景四: 程式崩潰除錯

### 問題描述
C++ 程式發生 Segmentation Fault 或其他崩潰。

### 工具選擇
- **gdb**: 除錯器
- **coredumpctl**: Core dump 管理
- **addr2line**: 位址轉行號
- **dmesg**: 核心訊息

### 完整流程

#### 1. 啟用 Core Dump

```bash
# 檢查當前設定
$ ulimit -c
0

# 啟用
$ ulimit -c unlimited

# 設定 core 檔案路徑
$ echo "/tmp/core.%e.%p" | sudo tee /proc/sys/kernel/core_pattern
```

#### 2. 執行程式

```bash
$ ./myapp
Segmentation fault (core dumped)
```

#### 3. 分析 Core Dump

```bash
# 使用 gdb
$ gdb ./myapp /tmp/core.myapp.12345

(gdb) bt
#0  0x00005555555551a0 in process_data (ptr=0x0) at main.cpp:25
#1  0x0000555555555140 in main () at main.cpp:10

(gdb) frame 0
#0  0x00005555555551a0 in process_data (ptr=0x0) at main.cpp:25
25          *ptr = 100;

(gdb) print ptr
$1 = (int *) 0x0

(gdb) info locals
ptr = 0x0
value = 42
```

#### 4. 檢查核心訊息

```bash
$ dmesg | tail -20

[12345.678] myapp[12345]: segfault at 0 ip 00005555555551a0 sp 00007fffffffe000 error 6 in myapp[555555554000+2000]
```

#### 5. 定位原始碼

```bash
$ addr2line -e ./myapp -f -C 0x00005555555551a0

process_data
/home/user/project/main.cpp:25
```

#### 6. 修復和驗證

```bash
# 使用 valgrind 驗證
$ valgrind ./myapp

# 使用 AddressSanitizer
$ g++ -fsanitize=address -g -o myapp main.cpp
$ ./myapp
```

## 場景五: 記憶體問題排查

### 問題描述
程式記憶體持續增長,可能有洩漏。

### 工具選擇
- **valgrind**: 記憶體檢測
- **pmap**: 記憶體映射
- **gdb**: 除錯

### 完整流程

#### 1. 觀察記憶體增長

```bash
# 監控進程記憶體
$ watch -n 1 'ps aux | grep myapp'

# 或使用 pmap
$ pmap -x $(pgrep myapp) | tail -5
```

#### 2. Valgrind 檢測

```bash
$ valgrind --leak-check=full --show-leak-kinds=all ./myapp

==12345== LEAK SUMMARY:
==12345==    definitely lost: 10,240 bytes in 10 blocks
==12345==    indirectly lost: 0 bytes in 0 blocks
==12345==      possibly lost: 0 bytes in 0 blocks
==12345==    still reachable: 0 bytes in 0 blocks
```

#### 3. 分析洩漏位置

```bash
==12345== 1,024 bytes in 1 blocks are definitely lost in loss record 1 of 1
==12345==    at 0x4C2BBAF: malloc (vg_replace_malloc.c:299)
==12345==    by 0x109234: allocate_buffer() (main.cpp:15)
==12345==    by 0x109180: process_request() (main.cpp:30)
==12345==    by 0x109100: main (main.cpp:50)
```

#### 4. AddressSanitizer 檢測

```bash
$ g++ -fsanitize=address -g -o myapp main.cpp
$ ./myapp
```

## 場景七: 負載測試與調優

### 問題描述
評估服務效能並進行調優。

### 工具選擇
- **wrk**: 壓測
- **htop/vmstat/iostat**: 監控
- **ss**: 連接狀態

### 完整流程

#### 1. 基準測試

```bash
# 初始壓測
$ wrk -t4 -c100 -d30s --latency http://localhost:8080/api/health

Running 30s test @ http://localhost:8080/api/health
  Latency Distribution
     50%   12.34ms
     90%   25.67ms
     99%   45.89ms
  Requests/sec:  8234.56
```

#### 2. 監控系統資源

開啟另一終端:
```bash
$ dstat -cdnm 1
```

#### 3. 找出瓶頸

根據監控結果判斷:
- CPU 高 -> 優化代碼或增加實例
- Memory 高 -> 優化記憶體使用
- I/O 高 -> 優化資料庫查詢或快取
- 連接數高 -> 調整連接池

#### 4. 調優

```bash
# 調整系統參數
$ sudo sysctl -w net.core.somaxconn=65535
$ sudo sysctl -w net.ipv4.tcp_max_syn_backlog=65535

# 調整應用參數 (連接池、線程數等)
```

#### 5. 再次測試

```bash
$ wrk -t4 -c100 -d30s --latency http://localhost:8080/api/health

# 比較結果
```

## 場景八: 日誌分析與監控

### 問題描述
分析日誌找出錯誤和效能問題。

### 工具選擇
- **tail**: 追蹤
- **rg**: 搜尋
- **awk**: 統計
- **jq**: JSON 處理

### 完整流程

#### 1. 即時監控錯誤

```bash
$ tail -f /var/log/app.log | rg --line-buffered "ERROR|WARN"
```

#### 2. 統計分析

```bash
# 錯誤統計
$ rg -c "ERROR" /var/log/app.log
42

# 按類型統計
$ rg -o "ERROR \w+" /var/log/app.log | sort | uniq -c | sort -rn

# Top 錯誤訊息
$ rg "ERROR" /var/log/app.log | awk '{$1=$2=$3=""; print}' | sort | uniq -c | sort -rn | head -10
```

#### 3. 時間範圍分析

```bash
# 特定時間範圍
$ awk '/2024-01-15 10:3[0-5]/' /var/log/app.log | rg "ERROR"
```

#### 4. JSON 日誌分析

```bash
# 提取錯誤
$ cat /var/log/app.json | jq 'select(.level == "ERROR") | {time: .timestamp, msg: .message}'

# 統計
$ cat /var/log/app.json | jq -r '.level' | sort | uniq -c
```

## 總結

### 問題類型與工具對應

| 問題類型 | 首選工具 | 輔助工具 |
|----------|----------|----------|
| API 測試 | curl, jq | nc, httpie |
| 連接問題 | nc, ss | dig, tcpdump, mtr |
| CPU 瓶頸 | htop, perf | vmstat, mpstat |
| 記憶體問題 | valgrind, pmap | free, gdb |
| I/O 瓶頸 | iostat, iotop | dstat |
| 網路效能 | iperf3, ss | tcpdump, iftop |
| 程式崩潰 | gdb, coredumpctl | addr2line, dmesg |
| 鏈接庫問題 | ldd, nm | ldconfig, readelf |
| 日誌分析 | rg, awk, jq | tail, journalctl |
| 壓力測試 | wrk, ab | k6, siege |

### 除錯心法

1. **先觀察再行動**: 用監控工具了解現狀
2. **由外而內**: 網路 -> 系統 -> 應用
3. **二分法**: 縮小問題範圍
4. **保留現場**: 記錄 log、保存 core dump
5. **對比基準**: 與正常狀態對比
