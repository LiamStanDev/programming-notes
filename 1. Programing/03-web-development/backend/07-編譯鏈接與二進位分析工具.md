## 鏈接庫診斷工具

### ldd

#### 命令說明

ldd 顯示可執行檔案或共享庫的動態鏈接依賴。

**基本語法:**
```bash
ldd [options] <file>
```

#### 常用選項

| 選項   | 說明           |
| ---- | ------------ |
| `-v` | 詳細輸出         |
| `-u` | 顯示未使用的直接依賴   |
| `-r` | 執行重定位並報告缺失符號 |

#### 使用場景

1. **依賴檢查**: 查看程式需要的庫
2. **問題診斷**: 找出缺失的庫
3. **部署準備**: 確認依賴完整性

---

#### 操作範例

##### 查看依賴

```bash
$ ldd ./myapp

        linux-vdso.so.1 (0x00007ffff7fc9000)
        libpthread.so.0 => /lib/x86_64-linux-gnu/libpthread.so.0 (0x00007ffff7d80000)
        libssl.so.1.1 => /lib/x86_64-linux-gnu/libssl.so.1.1 (0x00007ffff7cf0000)
        libcrypto.so.1.1 => /lib/x86_64-linux-gnu/libcrypto.so.1.1 (0x00007ffff7a00000)
        libstdc++.so.6 => /lib/x86_64-linux-gnu/libstdc++.so.6 (0x00007ffff7800000)
        libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007ffff7600000)
        /lib64/ld-linux-x86-64.so.2 (0x00007ffff7fcb000)
```

**輸出說明:**
- `=>` 左邊: 程式需要的庫名
- `=>` 右邊: 實際路徑
- 括號內: 載入地址

##### 發現缺失的庫

```bash
$ ldd ./myapp

        libfoo.so.1 => not found
        libbar.so.2 => not found
```

**解決方法:**
```bash
# 1. 搜尋庫位置
$ find /usr -name "libfoo*"
/usr/local/lib/libfoo.so.1

# 2. 添加到庫路徑
$ export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH

# 或永久設定
$ echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf
$ sudo ldconfig
```

##### 詳細輸出

```bash
$ ldd -v ./myapp

        Version information:
        ./myapp:
                libssl.so.1.1 (OPENSSL_1_1_0) => /lib/x86_64-linux-gnu/libssl.so.1.1
                libc.so.6 (GLIBC_2.17) => /lib/x86_64-linux-gnu/libc.so.6
```

### ldconfig

#### 命令說明

ldconfig 管理動態鏈接庫快取,設定運行時庫搜尋路徑。

**基本語法:**
```bash
ldconfig [options]
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `-p` | 列出快取中的庫 |
| `-v` | 詳細輸出 |
| `-n` | 只處理指定目錄 |

#### 使用場景

1. **安裝新庫後**: 更新庫快取
2. **搜尋庫**: 查找系統中的庫
3. **診斷問題**: 檢查庫路徑設定

---

#### 操作範例

##### 列出快取中的庫

```bash
$ ldconfig -p | head -20

1234 libs found in cache `/etc/ld.so.cache'
        libz.so.1 (libc6,x86-64) => /lib/x86_64-linux-gnu/libz.so.1
        libssl.so.1.1 (libc6,x86-64) => /lib/x86_64-linux-gnu/libssl.so.1.1
        libstdc++.so.6 (libc6,x86-64) => /lib/x86_64-linux-gnu/libstdc++.so.6
```

##### 搜尋特定庫

```bash
$ ldconfig -p | grep libssl

        libssl.so.1.1 (libc6,x86-64) => /lib/x86_64-linux-gnu/libssl.so.1.1
        libssl.so (libc6,x86-64) => /lib/x86_64-linux-gnu/libssl.so
```

##### 更新快取

```bash
$ sudo ldconfig -v

/usr/local/lib:
        libfoo.so.1 -> libfoo.so.1.0.0
/lib/x86_64-linux-gnu:
        libssl.so.1.1 -> libssl.so.1.1
```

##### 添加新的庫路徑

```bash
# 建立設定檔
$ echo "/opt/myapp/lib" | sudo tee /etc/ld.so.conf.d/myapp.conf

# 更新快取
$ sudo ldconfig
```

### pkg-config

#### 命令說明

pkg-config 查詢已安裝庫的編譯和鏈接參數。

**基本語法:**
```bash
pkg-config [options] <library>
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `--cflags` | 編譯參數 |
| `--libs` | 鏈接參數 |
| `--modversion` | 版本 |
| `--list-all` | 列出所有包 |

#### 使用場景

1. **編譯時**: 獲取正確的編譯參數
2. **版本檢查**: 確認庫版本
3. **自動化建構**: 在 Makefile 中使用

---

#### 操作範例

##### 獲取編譯參數

```bash
$ pkg-config --cflags openssl
-I/usr/include/openssl

$ pkg-config --libs openssl
-lssl -lcrypto
```

##### 編譯時使用

```bash
$ g++ -o myapp main.cpp $(pkg-config --cflags --libs openssl)
```

##### 檢查版本

```bash
$ pkg-config --modversion openssl
1.1.1f
```

##### 列出所有可用包

```bash
$ pkg-config --list-all | grep boost
```

## 符號與二進位分析

### nm

#### 命令說明

nm 列出目標檔案中的符號表。

**基本語法:**
```bash
nm [options] <file>
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `-C` | Demangle C++ 符號 |
| `-D` | 只顯示動態符號 |
| `-u` | 只顯示未定義符號 |
| `-g` | 只顯示外部符號 |
| `-S` | 顯示符號大小 |

#### 符號類型

| 類型 | 說明 |
|------|------|
| `T` | 程式碼段 (text) |
| `D` | 已初始化資料段 |
| `B` | 未初始化資料段 (BSS) |
| `U` | 未定義 (需外部提供) |
| `W` | 弱符號 |

#### 使用場景

1. **符號問題**: 診斷 undefined symbol
2. **除錯**: 檢查函數是否存在
3. **分析**: 了解二進位結構

---

#### 操作範例

##### 列出所有符號

```bash
$ nm ./myapp

0000000000001234 T main
0000000000002345 T _Z10processIntPKci
                 U printf
                 U malloc
```

##### Demangle C++ 符號

```bash
$ nm -C ./myapp

0000000000001234 T main
0000000000002345 T processInt(char const*, int)
                 U printf
                 U malloc
```

##### 只看未定義符號

```bash
$ nm -u ./myapp

                 U printf
                 U malloc
                 U _ZNSt8ios_base4InitC1Ev
```

##### 查看動態符號

```bash
$ nm -D /lib/x86_64-linux-gnu/libssl.so.1.1 | grep SSL_read

0000000000012345 T SSL_read
```

##### 檢查庫是否提供特定符號

```bash
$ nm -D /usr/lib/libfoo.so | grep -C "MyClass::process"
```

### objdump

#### 命令說明

objdump 顯示目標檔案的各種資訊,包括反組譯、段資訊等。

**基本語法:**
```bash
objdump [options] <file>
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `-d` | 反組譯 |
| `-D` | 反組譯所有段 |
| `-S` | 混合原始碼和組譯 |
| `-t` | 符號表 |
| `-T` | 動態符號表 |
| `-h` | 段標頭 |
| `-x` | 所有標頭 |

#### 使用場景

1. **反組譯**: 查看機器碼
2. **段分析**: 檢查二進位結構
3. **除錯**: 低層次除錯

---

#### 操作範例

##### 反組譯

```bash
$ objdump -d ./myapp

./myapp:     file format elf64-x86-64

Disassembly of section .text:

0000000000001234 <main>:
    1234:       55                      push   %rbp
    1235:       48 89 e5                mov    %rsp,%rbp
    1238:       48 83 ec 10             sub    $0x10,%rsp
```

##### 混合原始碼

```bash
$ objdump -S ./myapp

int main() {
    1234:       55                      push   %rbp
    int x = 10;
    1235:       c7 45 fc 0a 00 00 00    movl   $0xa,-0x4(%rbp)
```

##### 查看段資訊

```bash
$ objdump -h ./myapp

./myapp:     file format elf64-x86-64

Sections:
Idx Name          Size      VMA               LMA               File off  Algn
  0 .text         00001234  0000000000001000  0000000000001000  00001000  2**4
  1 .rodata       00000567  0000000000003000  0000000000003000  00003000  2**4
  2 .data         00000123  0000000000004000  0000000000004000  00004000  2**4
```

##### 查看動態符號

```bash
$ objdump -T ./myapp | grep GLIBC

0000000000000000      DF *UND*  0000000000000000  GLIBC_2.2.5 printf
0000000000000000      DF *UND*  0000000000000000  GLIBC_2.17  clock_gettime
```

### readelf

#### 命令說明

readelf 顯示 ELF 格式檔案的資訊。

**基本語法:**
```bash
readelf [options] <file>
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `-h` | ELF 標頭 |
| `-l` | 程式標頭 |
| `-S` | 段標頭 |
| `-s` | 符號表 |
| `-d` | 動態段 |
| `-V` | 版本資訊 |
| `-a` | 所有資訊 |

#### 使用場景

1. **ELF 分析**: 詳細檢查 ELF 結構
2. **版本檢查**: 查看 GLIBC 版本需求
3. **依賴分析**: 查看 RPATH 設定

---

#### 操作範例

##### 查看 ELF 標頭

```bash
$ readelf -h ./myapp

ELF Header:
  Magic:   7f 45 4c 46 02 01 01 00 00 00 00 00 00 00 00 00
  Class:                             ELF64
  Data:                              2's complement, little endian
  Type:                              EXEC (Executable file)
  Machine:                           Advanced Micro Devices X86-64
  Entry point address:               0x1234
```

##### 查看動態段 (RPATH/RUNPATH)

```bash
$ readelf -d ./myapp | grep -E 'NEEDED|RPATH|RUNPATH'

 0x0000000000000001 (NEEDED)             Shared library: [libssl.so.1.1]
 0x0000000000000001 (NEEDED)             Shared library: [libc.so.6]
 0x000000000000001d (RUNPATH)            Library runpath: [/opt/myapp/lib]
```

##### 查看版本需求

```bash
$ readelf -V ./myapp

Version needs section '.gnu.version_r' contains 2 entries:
 Addr: 0x0000000000000400  Offset: 0x000400  Link: 4 (.dynstr)
  000000: Version: 1  File: libc.so.6  Cnt: 2
  0x0010:   Name: GLIBC_2.17  Flags: none  Version: 3
  0x0020:   Name: GLIBC_2.2.5  Flags: none  Version: 2
```

### c++filt

#### 命令說明

c++filt 將 C++ 編譯器產生的 mangled 符號名稱還原為可讀形式。

**基本語法:**
```bash
c++filt [options] <symbol>
```

#### 使用場景

1. **符號解讀**: 理解 C++ 符號
2. **錯誤診斷**: 解讀錯誤訊息
3. **除錯**: 對應符號到原始碼

---

#### 操作範例

##### 還原單一符號

```bash
$ c++filt _ZNSt6vectorIiSaIiEE9push_backERKi

std::vector<int, std::allocator<int> >::push_back(int const&)
```

##### 配合 nm 使用

```bash
$ nm ./myapp | c++filt

0000000000001234 T MyClass::process(std::string const&)
0000000000002345 T MyClass::MyClass()
```

##### 管道處理

```bash
$ nm -u ./myapp | c++filt | grep MyClass
```

## 程式除錯工具

### gdb

#### 命令說明

gdb (GNU Debugger) 是最強大的程式除錯工具,支援斷點、單步執行、記憶體檢查等。

**基本語法:**
```bash
gdb [options] <program> [core]
gdb [options] -p <pid>
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `-q` | 安靜模式 |
| `-p` | 附加進程 |
| `-c` | 載入 core dump |
| `-x` | 執行命令檔 |

#### 基本命令

| 命令 | 說明 |
|------|------|
| `run (r)` | 執行程式 |
| `continue (c)` | 繼續執行 |
| `step (s)` | 單步進入 |
| `next (n)` | 單步跳過 |
| `finish` | 執行到函數返回 |
| `break (b)` | 設定斷點 |
| `delete (d)` | 刪除斷點 |
| `print (p)` | 顯示變數 |
| `backtrace (bt)` | 堆疊追蹤 |
| `frame (f)` | 切換堆疊幀 |
| `info` | 顯示資訊 |
| `quit (q)` | 退出 |

#### 使用場景

1. **崩潰分析**: 分析 Segfault
2. **邏輯除錯**: 單步追蹤程式
3. **死鎖分析**: 檢查線程狀態
4. **Core dump 分析**: 事後分析

### valgrind

#### 命令說明

valgrind 是記憶體除錯和分析工具,用於檢測記憶體洩漏、非法存取等。

**基本語法:**
```bash
valgrind [options] <program> [args]
```

#### 常用選項

| 選項 | 說明 |
|------|------|
| `--leak-check=full` | 完整洩漏檢查 |
| `--show-leak-kinds=all` | 顯示所有洩漏類型 |
| `--track-origins=yes` | 追蹤未初始化值來源 |
| `--log-file=<file>` | 輸出到檔案 |

#### 使用場景

1. **記憶體洩漏**: 檢測未釋放的記憶體
2. **非法存取**: 檢測越界存取
3. **未初始化**: 檢測使用未初始化值

---

### Sanitizers

#### 命令說明

Sanitizers 是編譯時的檢測工具,比 valgrind 快但需要重新編譯。

#### 類型

| Sanitizer | 編譯選項 | 用途 |
|-----------|----------|------|
| AddressSanitizer | `-fsanitize=address` | 記憶體錯誤 |
| ThreadSanitizer | `-fsanitize=thread` | 資料競爭 |
| UndefinedBehaviorSanitizer | `-fsanitize=undefined` | 未定義行為 |
| LeakSanitizer | `-fsanitize=leak` | 記憶體洩漏 |

---

#### 操作範例

##### AddressSanitizer

```bash
$ g++ -fsanitize=address -g -o myapp main.cpp
$ ./myapp

=================================================================
==12345==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x602000000050
WRITE of size 4 at 0x602000000050 thread T0
    #0 0x109234 in process_array() main.cpp:20
    #1 0x109180 in main main.cpp:10

0x602000000050 is located 0 bytes to the right of 40-byte region
```

##### ThreadSanitizer

```bash
$ g++ -fsanitize=thread -g -o myapp main.cpp
$ ./myapp

==================
WARNING: ThreadSanitizer: data race (pid=12345)
  Write of size 4 at 0x7fff12345678 by thread T1:
    #0 increment() main.cpp:15

  Previous read of size 4 at 0x7fff12345678 by thread T2:
    #0 read_value() main.cpp:20
==================
```

### coredumpctl

#### 命令說明

coredumpctl 管理 systemd 收集的 core dump。

**基本語法:**
```bash
coredumpctl [command] [options]
```

#### 常用命令

| 命令 | 說明 |
|------|------|
| `list` | 列出 core dump |
| `info` | 顯示詳情 |
| `dump` | 導出 core |
| `gdb` | 用 gdb 打開 |

---

#### 操作範例

```bash
# 列出 core dump
$ coredumpctl list

TIME                            PID   UID   GID SIG COREFILE  EXE
Mon 2024-01-15 10:30:00 CST    12345  1000  1000  11 present   /home/user/myapp

# 用 gdb 打開最新的 core
$ coredumpctl gdb

# 導出 core 檔案
$ coredumpctl dump -o myapp.core
```

## 常見問題排查流程

### 1. 鏈接庫找不到

**錯誤訊息:**
```
./myapp: error while loading shared libraries: libfoo.so.1: cannot open shared object file: No such file or directory
```

**排查步驟:**

```bash
# 1. 檢查依賴
$ ldd ./myapp | grep "not found"
        libfoo.so.1 => not found

# 2. 搜尋庫
$ find /usr -name "libfoo*" 2>/dev/null
/usr/local/lib/libfoo.so.1.0.0

# 3. 檢查快取
$ ldconfig -p | grep libfoo
# (無輸出表示不在快取中)

# 4. 解決方法 A: 臨時設定
$ export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
$ ./myapp

# 5. 解決方法 B: 永久設定
$ echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf
$ sudo ldconfig

# 6. 驗證
$ ldd ./myapp | grep libfoo
        libfoo.so.1 => /usr/local/lib/libfoo.so.1 (0x00007f...)
```

### 2. Undefined Symbol

**錯誤訊息:**
```
./myapp: symbol lookup error: ./myapp: undefined symbol: _ZN7MyClass7processEv
```

**排查步驟:**

```bash
# 1. 還原符號名稱
$ c++filt _ZN7MyClass7processEv
MyClass::process()

# 2. 檢查程式需要此符號
$ nm -u ./myapp | c++filt | grep "MyClass::process"
                 U MyClass::process()

# 3. 找出哪個庫應提供此符號
# (檢查連結的庫)
$ nm -D /usr/lib/libfoo.so | c++filt | grep "MyClass::process"
# (若無輸出,表示庫版本不對或未導出)

# 4. 檢查庫版本
$ pkg-config --modversion foo

# 5. 解決方法
# - 安裝正確版本的庫
# - 檢查編譯時的鏈接順序 (依賴庫要放後面)
```

### 3. Segmentation Fault

**排查步驟:**

```bash
# 1. 啟用 core dump
$ ulimit -c unlimited
$ echo "/tmp/core.%e.%p" | sudo tee /proc/sys/kernel/core_pattern

# 2. 執行程式
$ ./myapp
Segmentation fault (core dumped)

# 3. 分析 core dump
$ gdb ./myapp /tmp/core.myapp.12345

(gdb) bt
#0  0x00005555555551a0 in process (ptr=0x0) at main.cpp:15
#1  0x0000555555555140 in main () at main.cpp:8

(gdb) frame 0
#0  0x00005555555551a0 in process (ptr=0x0) at main.cpp:15
15          *ptr = 100;

(gdb) print ptr
$1 = (int *) 0x0

# 4. 定位行號
$ addr2line -e ./myapp -f -C 0x00005555555551a0
process
main.cpp:15
```

**診斷**: 第 15 行存取空指標

### 4. 死鎖

**排查步驟:**

```bash
# 1. 找出進程 PID
$ pgrep myapp
12345

# 2. 附加 gdb
$ sudo gdb -p 12345

(gdb) info threads
  Id   Target Id                    Frame
* 1    Thread 0x7f... (LWP 12345)   __lll_lock_wait ()
  2    Thread 0x7f... (LWP 12346)   __lll_lock_wait ()

(gdb) thread apply all bt

# 3. 或使用 strace
$ sudo strace -p 12345
futex(0x5555557890, FUTEX_WAIT_PRIVATE, 2, NULL) = ...
```

**診斷**: 多個線程在 `__lll_lock_wait` 表示等待鎖,可能死鎖

### 5. 記憶體洩漏

```bash
# 使用 Valgrind
$ valgrind --leak-check=full --show-leak-kinds=all ./myapp

# 或使用 AddressSanitizer
$ g++ -fsanitize=address -g -o myapp main.cpp
$ ./myapp
```
